# 世界美食大百科 · 寰宇小馆

> **分类**：`#vibeknow` 人文知识　·　分类索引见根目录 [`TRACKS.md`](../../TRACKS.md)

一份可以翻的世界菜单。**菜单与菜品介绍是主体**，世界各地的代表性美食按大洲分册列出；
点开任一道菜可以看到它的来历、做法与风味，并在地球定位组件上看到它产自哪里。

地球复用 [`earth-3d`](../earth-3d/) 的 3D 框架，但在这里**不是主体**，而是一个显示地理位置的组件：
移动端嵌在菜品页顶部，桌面端作右侧常驻栏，随当前菜品把相机对准产地。

## 打开方式

双击 `index.html`。资源在 `assets/`，需与 `index.html` 保持同级目录。

## 交互

**菜单页（主界面）**

- 顶部大洲横幅自 y=0 通栏铺满，标题与副标题压在图上，菜系页签咬在横幅下沿 —— 横幅与菜单连成一体
- 菜系页签：全部 / 亚洲 / 欧洲 / 非洲 / 北美 / 南美 / 大洋洲，列表按大洲分节
- 切页签换**大洲主题**：一整套配色（深色底 / 铜 / 纸 / 强调色）、横幅配图与横幅文案同时切换，
  七套主题覆盖菜单、菜品、品鉴、总结、地球槽与底栏
- **选中页签铺该洲的深木色实底**（`--wood-5 → --wood-7`，与详情页顶部地球槽同一套洲色），
  纸色字 + 顶部一道本洲朱线 —— 一眼看得出"我现在在哪个洲"
- 每行：菜品小图 · 菜名 · 引导点线 · 产地（右端对齐成列）
- 点行 → 进菜品页；点行尾的 ＋ → 加入点单
- 底部点单栏：**已点 N 道菜**（弱操作「清空」用文字链接）+ **「开始上菜」**（朱红实底按钮）
- 首页**没有地球**（它只在菜品页出现），故启动提示只讲本页能做的事：点菜名看详情、＋ 加入点单

**菜品页**

- 顶部地球定位组件：对准该菜产地，标出竹签牌与经纬度，同菜系的其余菜以暗色点作上下文；
  首次进入本页提示一次手势（拖动可转动 · 滚轮 / 双指缩放）；
  这条提示**只落在地球画布内**（画布顶部 12px 处），不滑到下面的菜品介绍上 ——
  文案说的是地球，就该压着地球显示
- 顶部仅一道居中的面包屑（大洲 · 菜名），所有操作收在底栏，单手可及
- 菜品图、菜名、产地、介绍、「配料 / 口味」（右端对齐）
- 底部操作栏**只有右侧一组**：**返回菜单 / 加入点单 / 下一道 ›**（三级：返回与加入点单是描边次按钮，
  下一道是朱红主按钮）—— 左侧不再挂「已点 N 道」：390 宽下三枚按钮已占满一行，再加一列状态文字就挤了，
  是否已点改由「加入点单」按钮自身的 ✓ 态表达，信息不丢
- 未点单时「下一道」按当前菜系顺次浏览，跨到别的菜系所在的菜时整页配色随之换装
- 「加入点单」的已点态与菜单行尾的 ＋ 同款：朱红实心 + ✓（原先详情单独用铜色，口径已统一）

**品鉴页（上菜专用）**

- 点「开始上菜」后逐道进入品鉴页，不复用菜品详情页：暗场聚光 + 菜品大图（宣纸裱框）
  + 菜名产地 + 一句简介
- 顶部同样只有居中面包屑；底栏与首页同规格：**第 X / N 道**（左）+ **返回菜单 / 下一道 ›**（右，
  同三级按钮）—— 只有舞台是暗场，操作条不再是另一套深色
- 最后一道时「下一道」变为「风味总结」，中途随时按「返回菜单」退出品鉴

**风味总结页**

- 走到末道后给出本席的口味结论：**六维口味雷达图**（甜 / 辣 / 酸 / 咸 / 鲜 / 香，全席均值，
  峰值那个维度标红）+ 由数据生成的一句定评 + 覆盖的大洲与国家数
  —— 雷达图给出的是味型轮廓（"鲜香为主 / 六味均衡"这种形状感），条图只能比长短
- 菜品回顾：每道菜一行（色点 · 菜名 · 产地 · 该菜最突出的两味）
- 热量合计：本席总热量、占成人日均 2000 千卡的比例、每道均值、最重与最轻的一道，
  以及折合快走的分钟数（按 60 公斤成人、6 公里 / 小时折算）
  —— 右端那一列是整行的结论（"北京烤鸭 · 560 千卡"），**不允许省略**：该列不设 `max-width`
  与省略号，空间不够时压缩进度条（`min-width:24px` 保底）而非截断文字
- 顶部居中面包屑 + 底部操作栏（与前三页同壳体）：**本席 N 道 · X 大洲**（左）+ **返回菜单**（右）
  —— 原来「返回菜单」是文末的一枚居中按钮，现已收进底栏，走到哪一层都能退

**操作栏与按钮（四页一套，以首页为基准）**

| 层级 | 用途 | 样式 |
|------|------|------|
| 壳体 | `.orderbar` / `.dish-actions` / `.serve-bar` / `.sum-bar` | 纸色渐变 + 上缘桌沿木线 + `padding:12px 16px` + 底部安全区，左状态信息 / 右按钮组（**菜品页不设信息区**，整组靠右） |
| 一级 | 主操作（开始上菜 / 下一道 / 风味总结 / 加入点单·已点） | `.obtn` 朱红实底白字，`padding:10px 22px`，`14px` |
| 二级 | 次操作（**返回菜单** / 未点的加入点单） | `.obtn.ghost` 透明 + 描边，`13px` |
| 三级 | 弱操作（清空） | `.olink` 虚下划线文字链接 |

三个子页的顶部都不放返回键：返回 / 退出一律在底栏（拇指端），顶部只留一道居中面包屑。
**同一个动作必须同一个样子**：菜品页 / 品鉴页 / 总结页的返回按钮文字统一为「返回菜单」，
位置统一在按钮组首位、样式统一为二级描边按钮 —— 不再出现「‹ 菜单」「退出品鉴」两种叫法、
也不再一处是描边次按钮、另一处却是朱红主按钮。

**地球组件与设置**

- 拖动地球可转动、滚轮 / 双指缩放；缓慢转动时以菜品朝向为基准轻微摆头，地理位置始终留在视野中央
- 地球在移动端只出现在菜品页：嵌在子页上栏之下，其余子页让位给内容

## 数据

- 内置 **36 道美食**，覆盖 **6 大洲**、**31 个国家**
- 数据文件：`assets/foods.js`，每条记录字段：
  `name / country / city / lat / lon / continent / intro / ingredients / tags / taste / kcal / color / img`
- `taste` 为六维味觉分值 `[甜, 辣, 酸, 咸, 鲜, 香]`，各 0–5 整数，口径是该菜在当地的代表性吃法，
  供风味总结页的口味图谱使用。**六维顺序不可变**（`app.js` 的 `TASTE_DIMS` 与之一一对应），
  改分值时只需改 `foods.js`
- `kcal` 为一份成品的热量估算值（千卡），供风味总结页的热量合计使用；
  换算常量（成人日均 2000 千卡、快走 5.2 千卡 / 分钟）集中在 `app.js`
- 离线零依赖：`img` 缺失或加载失败时，用该条记录的 `color` 色卡代替菜品图，故图片可分批补

## 大洲主题

七套配色全部写在 `index.html` 的 `body[data-ctn="…"]` 变量组里，由 `app.js` 写属性换装；
变量沿用同一套名字（深色底 / 铜 / 纸 / 强调色 / 墨 / 线 / 横幅图），故所有页面一并跟随。
横幅上的标题与副标题文案在 `app.js` 的 `THEME` 表里。

主题的归属：**菜单页跟页签**（`st.continent`，返回菜单即还原）、**菜品页与品鉴页跟当前这道菜所属大洲**
（在「全部」下顺次浏览跨洲时整页换装）、**总结页回到 `all`**（本席结论可能跨洲，不继承上一道菜的洲色）。

## 兼容性（Chrome 61 回退层）

最低基线是 **Android 8.1 出场 Chrome / WebView 61**（小工具统一口径）。做法是
「基线层 + 能力检测后的增强层」，不为旧内核另起一套页面：

| 能力 | 基线（Chrome 61 可用） | 增强（检测后启用） |
|------|----------------------|------------------|
| Flex `gap` | 子项 `margin-left`（`.mrow > * + *`、`.acts > * + *` …） | `.supports-flex-gap` 下换 `gap` 并清 margin |
| `clamp()` | `--hero-h` 固定值 + 按视口高的媒体查询分档 | 不引入 |
| `min()` | 同一个 `vw` 值 + `max-width/max-height` 收口（`.sv-img` 正方形） | 不引入 |
| `env(safe-area-inset-*)` | `--sat / --sattop / --sab` 取 `0 / 8px / 0` | `@supports` 块里换成 `env()` |
| `:focus` | `:focus` 描边基线 | 不用 `:focus-visible` |
| WebGL 3D | 地球槽内挂 `.globe-down`，菜单 / 菜品 / 点单 / 品鉴 / 总结照常 | 完整地球 |

两个坑，已写进代码注释：

- **Flex gap 不能用 `CSS.supports('gap')` 判断** —— 那只能证明浏览器认识这个属性名，
  证明不了它在 Flexbox 里生效（只支持 Grid gap 的内核照样返回 true）。页面顶部的内联脚本
  真的建一个 flex 容器量 `scrollHeight`，量出来才算。
- **`env()` 不能直接写进 `:root`** —— 自定义属性会把 `env(...)` 当 token 原样收下，
  等到 `calc()` 里展开时才失效，连带把整条 `padding` / `height` 声明作废（不是退回 0，是整条没了）。
  所以基线写死 0，env 版本关在 `@supports` 里。

**3D 不可用不再是全屏报错**：旧写法直接盖一张「无法启动 3D 场景」遮住整页并 `return`，
等于把「球转不起来」判成「整页不可用」。现在地球只是标产地的组件，它挂了就只在槽内降级，
底下的菜单、介绍、点单上菜、风味总结一条不少。

验证两层（`_dev/build_zip.py` 之后跑）：

- `_dev/check_chrome61.py`：按禁忌清单静态扫**最终 zip**（浏览器对不认识的 CSS 静默丢弃，
  现代内核上实机跑通并不等于 Chrome 61 可用，只能逐条核对）—— 83 项。
- `_dev/check_fallback.py`：在真浏览器里模拟能力缺失（拿掉 WebGL、屏蔽 gap 增强层、
  删掉 Chrome 61 之后的 API），把「切洲 → 看菜 → 点单 → 上菜 → 品鉴 → 总结」走一遍，
  验证降级逻辑本身没写反 —— 33 项。

⚠ 本机无 Chrome 61 / WebView 61 内核，**Chrome 61 内核行为未实测**；
以上覆盖的是「降级路径写对了」，不等于「Chrome 61 上真能跑」。

## 与 earth-3d 的关系

复用 earth-3d 的：WebGL 渲染器、星空天球、地球贴图与云层、`ll2v` 经纬→球面坐标、相机手势。

改造为定位组件：画布由全屏改为面板内尺寸，相机改写为"对准产地"而非自由浏览，
标记点由 36 个常显改为"当前菜品实心 + 同菜系压暗"，城市标签只保留当前一道。

移除：四季成因、地月系统、地球内部剖切、经纬网格、月相指示器；
以及本项目早期版本的全屏地球主体、底部大洲筛选器、浮层详情卡与弹出式菜单面板。

新增：菜单页与菜品页的路由、按大洲分册的行式菜单、点单与上菜流程、
菜品图加载与色卡回退、地球组件的自适应布局（移动端内嵌 / 桌面端侧栏）。

## 分类判定

没有任务、没有输赢，用户点开是为了"看看世界各地的人都在吃什么、怎么吃"，看完脑子里多一份对他人饮食文化的认知 → `#vibeknow`。地球是标注产地的组件，3D 是手段而非目的，故不归 `#vibeart`。
