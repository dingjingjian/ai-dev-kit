# 背景音乐需求（`assets/audio/bgm.js`）

> **音频以 base64 藏在 `assets/audio/bgm.js` 里**（容器上传白名单不收音频扩展名），
> 由 `app.js` 交给 Web Audio 解码播放；源曲目 `assets/audio/bgm.mp3` 只作构建输入、**不进 zip**。
> 数据不在 / 解码失败也不报错：音乐开关整块隐藏，五页流程与从前完全一样。

| 项 | 实测值 |

## 1. 为什么不能直接放一个 mp3

容器两条规则夹死了「包内媒体文件 + `<audio src>`」这条路：

1. **上传白名单不含任何音频扩展名** —— 只允许
   `jpg / css / gif / svg / png / js / jpeg / json / html / woff2 / webp / woff`，
   `.mp3` 会在上传页被直接打回；
2. **CSP 明确** `<audio>` / `<video>` 只允许**包内媒体文件**，禁外部域名与 `data:` / `blob:` 媒体源 ——
   在线音乐链接、base64 内联成 data URI、`writeTempFile` 现写音频，三条都走不通。

于是只剩一条路：**音频字节 → base64 字符串 → 藏进 `.js`（白名单类型）→ 运行时解码播放**。
再叠上性能门禁（`performance-budget.md` §1）：

> 单条 Base64 **解码后不超过 1 MiB**；超过 100 KiB 提示风险，超过 1 MiB 视为大 Base64，
> 必须改成独立包内文件。

「改成独立包内文件」在容器里做不到（见 ①），所以**音频本身必须压到 1 MiB 以内**。
源文件是 320kbps：按 MPEG 帧级裁剪只能留 **26.2s**，对一首慢速主题曲太短 —— 所以走重编码：

```
原始 mp3（320kbps / 206.3s / 7.87MB）
  → tools/make-bgm.mjs：解码 → 取乐句 68s→194s → 降为单声道 → 低通 11kHz 后 2 倍抽取到 22.05kHz
  → lamejs 编 64kbps CBR（985 KB）→ base64 → assets/audio/bgm.js
```

## 2. 循环点是怎么定的（`tools/analyze-bgm.mjs`）

**先排除「找重复段」这条路**：这首曲子没有真正重复的段落 —— 波形互相关（3s 窗、±100ms 时移）
最高只有 **0.058**。任何循环点都是「两段不同音乐交叠」，只能挑**听感冲突最小**的那个。

判据由 `tools/analyze-bgm.mjs` 实现，按重要性排序：

| 判据 | 取法 |
|------|------|
| 织体相似 | 8 频带对数能量包络（FFT 1024 / 跳 512）在 2.5s 窗上的相关系数 |
| 接缝安静 | 接缝两侧 3s 的 RMS —— **这首最关键的一条**：轻奏处的交叠最不容易被听出来 |
| 长度 | 越长越耐听，但要塞进 1 MiB 预算 |
| 整小节 | 节拍可靠时两端落在小节线上（重拍对齐比织体相似更有效）；**这首节拍不可靠**，改按 0.5s 自由网格 |
| 波形相关 | 曲子真有重复段时这一项会很高（>0.5），那种接缝几乎听不出来；没有时它就只是个参考 |

```bash
node tools/analyze-bgm.mjs "原始文件.mp3" --top 10      # 分析对象是原始曲目，不是 bgm.mp3
```

结论 —— **64.00s → 197.00s（133.0s）**：

```
织体相似 0.922 · 接缝电平 0.0357（全曲 45% 分位 0.0689 —— 该点约为它的一半，落在轻奏处）
波形相关 0.058（无重复段）
对照：把整段首尾相接（曲头 0s 接曲尾）织体 0.738 · 波形 0.024
```

> 「强拍」的来源就是把整段首尾相接：两段不相干的乐句叠在一起，重拍互相撞。
> 换成轻奏处的内部乐句后，交叠发生在音乐最弱的地方，接缝几乎听不出来。
> 节拍在这首上不可靠（管弦乐连奏、起音弱，自相关峰值只比邻域高 2%），所以没有按小节线切。

## 3. 换曲目 / 换循环点

```bash
npm --prefix tools i mpg123-decoder @breezystack/lamejs   # 只需一次

# ① 找循环乐句（分析**原始文件**，不是 assets/audio/bgm.mp3）
node tools/analyze-bgm.mjs "新的原始文件.mp3" --top 10
#    → 打印候选表、推荐乐句与交叠长度，并给出可直接粘贴的两行命令

# ② 按推荐重切 + 重编码 + 生成 base64（自动核对 1 MiB 门禁）
node tools/make-bgm.mjs "新的原始文件.mp3" --a 64 --b 197 --kbps 56
#    → 覆盖 assets/audio/bgm.mp3（构建输入）与 assets/audio/bgm.js（运行时数据）

# ③ 把交叠秒数抄进 app.js 的 BGM_XFADE，重新打包
node pack.mjs
```

**`app.js` 不用改**：它只认 `assets/audio/bgm.js`。唯一要跟着改的是 `BGM_XFADE`（交叠秒数）。
若新曲目**有真正的重复段**（工具会报波形相关 > 0.5），接缝几乎听不出来，交叠取 1~2s 就够。

## 4. 运行时行为

| 项 | 行为 |
|------|------|
| 起播 | autoplay 策略要求用户手势：**第一次点按 / 点击 / 按键之后**才出声（`app.js` 捕获阶段听 pointerdown / click / keydown） |
| 循环 | 整段即乐句；每遍在最后 5s 线性淡出、下一遍从 0s 线性淡入，两者完全重叠、增益和恒为 1（内容高度相似时线性叠加不会凸起，换成等功率曲线反而会 +3dB） |
| 第一遍 | 不走 5s 淡入（那只是给接缝用的），改成 1.2s 起势，免得刚点开要等 5 秒才到正常音量 |
| 音量 | `GainNode` 包络 0 → 0.42，不做 `setInterval` 调 volume |
| 开关 | **地球槽（地图）右上角、顶栏之下**的黄铜小牌（`top:calc(var(--dishbar) + var(--sattop) + var(--bgmgap))`，`--bgmgap` 默认 12px）：出声中＝亮起铜牌 + 音符；静音＝转暗 + 斜杠音符。点击即静音 / 恢复。顶栏不为它留白，标题居中不受影响 |
| 偏好 | `localStorage` 键 `jp3d.bgm`：没存过＝偏好开启，只有用户手动关掉才记成静音（下次进园仍是静音） |
| 切后台 | `visibilitychange` 停声 + `suspend()` 音频上下文，回前台自动续上 |
| 缺数据 | 解码成功才给 `<html>` 挂 `has-bgm` 把开关显出来；没数据 / 解不出＝开关隐藏 |
| 演示模式 | `?demo` 不显示开关（`html.is-demo`）；且演示全程无用户手势，BGM 不会自动起播 |

## 5. 验收自检

**✅ = 已在无头 Chromium（真实资产）实测；⬜ = 只能在有声音的真机环境确认。**

- ✅ `decodeAudioData` 成功：`duration=133.068s`、单声道；`html` 挂上 `has-bgm`
- ✅ 首屏（还没发生手势）开关可见但不亮、**不出声**（`aria-pressed=false`、无存档）
- ✅ 第一次用户手势后自动起播、铜牌点亮（`class="bgm-btn on"`、`aria-pressed=true`）
- ✅ 点开关静音（熄灭、`localStorage` 存 `0`）；再点恢复（点亮、存 `1`）
- ✅ 循环排期正确（插桩 `AudioContext`）：`start when=13.61 offset=0 buf=133.07`、`stop when=146.73`
  —— 每遍 133.12s（含 0.05s 收尾余量），交叠 4s、步长 129.07s，满足 L = D − X
- ✅ `pack.mjs`：`assets/audio/bgm.js` 进包；`bgm.mp3` 不出现在 zip 里
- ⬜ 连续循环 3 圈以上，听接缝有没有"咔"声 / 音量大跳 —— **需戴耳机试听**（这首没重复段，接缝是两段不同音乐的 4s 交叠）
- ⬜ 切后台音乐停、回前台续上（代码路径已就位，出声行为未实测）
- ⬜ 大门页（那 7.1s 开门过程）里音乐不中断
- ⬜ iOS 真机能出声（iOS 硬件静音开关处于静音位时系统会静音 WebView 音频，属系统行为）
- ⬜ Android 8.1 / WebView 61 真机解码 64kbps 单声道 22.05kHz —— 未实测（Chromium 已通过）
