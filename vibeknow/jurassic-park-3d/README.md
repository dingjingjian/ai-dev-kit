# 侏罗纪公园 · 游览导航

> **分类**：`#vibeknow` 人文知识　·　分类索引见根目录 [`TRACKS.md`](../../TRACKS.md)

一个侏罗纪公园游览导航 app。**选择游览路线 → 公园大门开启 → 游览车按路线行进 → 游览总结**，
致敬 1993 年经典电影《侏罗纪公园》。30 种恐龙按 4 条主题路线组织，
游览车行进时地球组件实时标注化石发现地。

> 本项目参照 [`world-food-3d`](../world-food-3d/) 的技术框架构建，底层逻辑从「菜单点菜」改为「园区游览 app」。

## 打开方式

双击 `index.html`。资源在 `assets/`，需与 `index.html` 保持同级目录。

## 交互

### 路线选择页（主界面）

- 顶部公园大门视觉区：三角 logo、公园标题、两侧火炬火焰动画、底部 CSS 画的简化大门
- 4 条路线卡片，每张卡片有路线名、标签、描述、展品数/年代数/国家数/刺激度
- 卡片背景为路线主题色渐变 + 路线横幅图（缺图回退渐变）
- 点路线卡片 → 进入大门过渡页

### 大门过渡页（致敬电影）

- 两扇 CSS 木门向两侧打开（`rotateY` 动画，2.2s）
- 门中央浮现三角 logo + "JURASSIC PARK" 文字
- 依次淡入：欢迎语 → "When Dinosaurs Ruled the Earth" → 路线名
- 约 3.8s 后自动进入游览页
- 大门背景图（缺图用 CSS 渐变 + 木门兜底）

### 游览页（游览车视角）

- 顶栏：游览车编号（`#01`）、路线名 · 年代面包屑、进度（第 X / N 处）
- 地球定位组件嵌在顶栏下方：标出当前路线全部展品的化石发现地，
  当前展品高亮脉动，其余路线成员压暗作上下文
- 展品大图（骨白裱框）、名称、化石发现地、介绍、特征标签、展品标签
- 底栏游览车控制栏：上一展品 / 进度信息 / 下一展品 / 退出
- 最后一处时「下一展品」变为「游览总结」

### 游览总结页

- 路线名 + 展品数/年代数/国家数
- 感谢语 + 由数据生成的一句定评（最突出/最克制的维度）
- **六维特征雷达图**（体型/威胁/速度/智力/防御/稀有，本次均值，峰值维度标红）
- 展品回顾：每处一行（色点 · 名称 · 发现地 · 该展品最突出的两维）
- 体型合计：本次总体长、占展厅均长基准 15 米的比例、每处均值、最长与最短
- 底栏：返回选择路线

### 地球组件

- 拖动地球可转动、滚轮/双指缩放
- 游览时以展品朝向为基准轻微摆头，化石发现地始终留在视野中央
- 仅在游览页显示（CSS `body.mode-tour .globe-slot{display:block}`）

## 数据

- 内置 **30 种恐龙**，覆盖 **5 个地质年代**、**11 个国家**
- 数据文件：`assets/dinos.js`，每条记录字段：
  `name / country / city / lat / lon / era / intro / traits / tags / stats / length / color / img`
- `stats` 为六维特征分值 `[体型, 威胁, 速度, 智力, 防御, 稀有]`，各 0–5 整数，口径是该物种的代表性个体，
  供游览总结页的特征图谱使用。**六维顺序不可变**（`app.js` 的 `STATS_DIMS` 与之一一对应）
- `length` 为成年个体代表体长的估算值（米），供游览总结页的体型合计使用；
  换算常量（展厅均长基准 15 米）集中在 `app.js`
- 离线零依赖：`img` 缺失或加载失败时，用该条记录的 `color` 色卡代替展品图，故图片可分批补

## 兼容性（Chrome 61 回退层）

最低基线是 **Android 8.1 出场 Chrome / WebView 61**。做法是「基线层 + 能力检测后的增强层」，
不为旧内核另起一套页面：

| 能力 | 基线（Chrome 61 可用） | 增强（检测后启用） |
|------|----------------------|------------------|
| Flex `gap` | 子项 `margin-left` | `.supports-flex-gap` 下换 `gap` 并清 margin |
| `clamp()` | `--hero-h` 固定值 + 按视口高的媒体查询分档 | 不引入 |
| `env(safe-area-inset-*)` | `--sat / --sattop / --sab` 取 `0 / 8px / 0` | `@supports` 块里换成 `env()` |
| `:focus` | `:focus` 描边基线 | 不用 `:focus-visible` |
| WebGL 3D | 地球槽内挂 `.globe-down`，路线/大门/游览/总结照常 | 完整地球 |

**3D 不可用不再是全屏报错**：地球只是标化石发现地的组件，它挂了就只在槽内降级，
底下的路线选择、大门动画、游览车、游览总结一条不少。

## 与 earth-3d 的关系

复用 earth-3d 的：WebGL 渲染器、星空天球、地球贴图与云层、`ll2v` 经纬→球面坐标、相机手势。

改造为化石发现地定位组件：画布由全屏改为面板内尺寸，相机改写为"对准化石发现地"而非自由浏览，
标记点由 30 个常显改为"路线成员全显 + 当前置品高亮脉动 + 其余压暗"，发现地标签只保留当前一处。

## 与 world-food-3d 的关系

参照 `world-food-3d` 的技术框架（四页结构、地球定位组件、Chrome 61 兼容层、零依赖离线单文件），
底层逻辑从「菜单点菜」改为「园区游览 app」：

- 菜单页 → 路线选择页（4 条主题路线，原按大洲的菜品列表）
- 菜品页 → 大门过渡页（致敬电影的大门开启动画，原无此页）
- 品鉴页 → 游览页（游览车视角按路线行进，原逐道上菜）
- 风味总结 → 游览总结（六维特征图谱 + 体型合计，原口味图谱 + 热量合计）
- 点单 + 上菜 → 选路线 + 开始游览（原逐个加入点单再统一上菜）

数据字段对应：`foods`→`dinos`、`continent`→`era`、`taste`→`stats`、`kcal`→`length`、`ingredients`→`traits`。

## 分类判定

没有任务、没有输赢，用户点开是为了"选一条路线，坐游览车穿行史前世界，看看各种恐龙的化石在哪儿出土"，
看完脑子里多一份对古生物与地球史的认知 → `#vibeknow`。地球是标注化石发现地的组件，3D 是手段而非目的，故不归 `#vibeart`。
