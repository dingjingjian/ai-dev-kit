# 背景音乐需求

本文是给「找 BGM」这一步用的：说明这首歌要满足什么条件、怎么选、怎么裁、怎么进包。

> 图片素材另见 [`兵种图片素材需求.md`](兵种图片素材需求.md) 与 [`场景配图需求.md`](场景配图需求.md)。
> 生成顺序与整体流程见 [`素材生成说明.md`](素材生成说明.md)。

## 一、先说清一件事：音频不能作为音频文件进包

本项目的交付形态是「零依赖离线 H5」，最终要打成 zip 上传。而容器有两个硬限制：

1. **上传白名单不含任何音频扩展名**（只收 jpg/css/gif/svg/png/js/jpeg/json/html/woff2/webp/woff）；
2. **CSP 禁 `data:` / `blob:` 媒体源**，所以"把音频塞进 `<audio src="data:...">`"这条路也不通。

于是只有一条路：把音频 **base64 编码后藏进 `assets/audio/bgm.js`**，
运行时由 `app.js` 用 `atob` 解成 `ArrayBuffer`，交给 Web Audio 的 `decodeAudioData` 播放——
全程不产生任何 URL，也就绕开了上面两条限制。

**直接推论**：一首歌进包后就是一段 base64 字符串，而性能门禁要求
**单条 Base64 解码后 ≤ 1 MiB**。所以——

> **成片音频（不是源文件）必须压进 1 MiB 以内。**
> 在 64kbps 单声道 22.05kHz 下，1 MiB ≈ **126 秒**。这就是选段的长度预算。

## 二、选曲要求

### 2.1 风格

- **古罗马 / 古典史诗向**：缓慢、庄重、有行进感。鼓与低音持续音铺底，
  铜管或弦乐做主题，避免现代合成器音色与流行歌的段落结构。
- **不要人声**。有人声的曲子在循环接缝处会露馅（换气、咬字），也容易盖过界面音效。
- **动态要平**。整段音量起伏小、没有突然的强奏——页面里它是背景，
  一首有巨大动态对比的曲子会在最响处显得吵、在最轻处显得没声。
- 参考方向（仅作风格锚点，不指代具体曲目）：纪录片式的古代战争配乐、
  博物馆展陈背景乐、凯尔特/地中海古乐器的现代编曲。

### 2.2 结构（决定能不能循环）

最重要的一条：**曲子里要有一段"听起来像自己"的乐句**。
BGM 是反复播放的，如果随便裁一段，接缝上叠的就是两段不相干的音乐，
重拍互撞，一听就是个突兀的强拍。

选曲时优先挑满足以下条件的：

| 条件 | 说明 |
|------|------|
| 有重复的织体 | 同一段配器/节奏在曲中出现两次以上，循环时两端能接上 |
| 首尾电平低 | 乐句两端都在轻奏处，交叠淡化最不容易被听出来 |
| 落在小节线 | 两端都在小节线上，重拍对齐 |
| 长度 60–126s | 长于 126s 塞不进 1 MiB（见第一节）；短于 60s 会很快听腻 |

### 2.3 版权

- 用**自有版权、CC0 / CC-BY、或已购授权**的曲目；商用发布前留档授权凭证。
- 留档位置见 [`素材生成说明.md`](素材生成说明.md) 第五节。

## 三、拿到的源文件要求

- 格式：**mp3 / m4a / aac / wav 任一**，但 `analyze-bgm.mjs` 的解码器只吃 mp3——
  别的格式先转一道。
- 码率越高越好（320kbps 最佳）——反正要重编码，源文件差会一路带到成品。
- **源文件本身不进包**（`tools/pack.mjs` 已排除 `bgm-src.mp3` / `bgm.mp3`），
  放本地即可，只是构建输入。

### 3.1 源是视频时：先抽音轨

游戏原声通常只有视频。用 `tools/extract-audio.py`：

```bash
python tools/extract-audio.py "视频.mp4" -o assets/audio/bgm-src.mp3
# 可选 --kbps 320（默认）--mono（直接混单声道）
```

ffmpeg 不在 PATH——脚本用 `imageio_ffmpeg` 自带的二进制（`pip install imageio-ffmpeg`）。
它会打印音视频流信息与时长，并给出下一步的命令。

> 注意：`imageio_ffmpeg` 只带 **ffmpeg**，不带 ffprobe，
> 所以脚本是靠解析 ffmpeg 的元信息输出拿流信息的，别改用 `ffprobe -show_streams`。

## 四、选段与编码（两条命令）

### 4.1 装依赖（只需一次）

```bash
cd tools && npm i mpg123-decoder @breezystack/lamejs
```

### 4.2 先分析，找循环点

```bash
node tools/analyze-bgm.mjs "原始文件.mp3"
# 可选参数：--min 40 --max 130 --top 16 --json > loop.json
```

工具按五项判据排序候选（织体相似 / 接缝安静 / 长度 / 整小节 / 波形相关），
最后直接给出两行可复制的命令。看输出末尾这两段：

- `①` —— 整段音频都进包、由 app 在运行时选乐句；
- `②` —— 用 `make-bgm` 先截段，buffer 就是乐句。**本项目走 ②。**

判读提示：

- 波形相关 **> 0.5**：这两处是真正的同一段音乐，接缝几乎听不出来。
- 只有 **0.1~0.3**：曲子没有真正的重复段（慢速主题曲常常如此），
  接缝是两段不同音乐的交叠。**务必戴耳机试听一遍**再定。

### 4.3 分析要多久

4 分钟左右的曲子通常几十秒内跑完。如果跑了三四分钟还没出结果，
很可能是踩到了 `analyze-bgm.mjs` 的旧 bug（已在本项目修掉）：
它会给**全部**候选补算波形互相关，而候选数动辄几万——
修法只精算前 160 个。别的项目里若还有这行，照此改。

### 4.4 再截段 + 重编码

```bash
node tools/make-bgm.mjs "原始文件.mp3" --a 68 --b 194 --kbps 64
```

（`--a` `--b` 换成上一步给的秒数。）它会做四件事：
取乐句 → 降为单声道 → 降采样到 22.05kHz（31 抽头 sinc 低通后 2 倍抽取）→ 重编码，
最后写出 `assets/audio/bgm.js`（`window.RTW3D_BGM="..."`）并打印门禁核对。

输出末尾会核对两条硬门禁：

```
单条 Base64 解码后 ≤ 1 MiB : ✅ 0.xxx MiB（余量 xx KB）
单个 .js ≤ 2 MiB           : ✅
```

**只要有一条 ❌，就降 `--kbps`（64 → 56 → 48）或缩短 `--a/--b` 重跑**，别硬塞。

## 五、运行时机制（不用改，供排查参考）

- `assets/app.js` 里的变量是 `window.RTW3D_BGM`；开关状态存 `localStorage['rtw3d.bgm']`。
- 浏览器要求**用户手势后才能起播**，所以第一次要等一次点击（点阵营卡即可）。
- 循环用 **4 秒交叠淡化**：末尾 4s 淡出、开头 4s 淡入，两路交叉，不做硬接缝。
  交叠秒数在 `app.js` 的 `BGM_XFADE`，若要改，与分析工具给的 `xfade` 建议值对齐。
- **`assets/audio/bgm.js` 缺失是允许的**：页面照常跑，只是没有声音。
  所以 BGM 可以最后一步再补。
