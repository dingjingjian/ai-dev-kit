## 二、P0-1 装备图 ×52 与 logo 不是透明底（最高优先）

### 证据

1. **容器层**：`assets/gear/*.webp`（52）与 `assets/tex/logo.webp` 的 WebP fourcc 全部是 `VP8 `（有损、**无 `ALPH` 块**），即文件里根本没有 alpha 通道。两套兵种图与其余 13 张场景图同理，但那两类不要求透明。
2. **像素层**（canvas 解码取真值）：逐文件 `minA = 255`、透明像素占比 `0.0%`；外圈 6 环「接近白色(≥235)」占比 **63%–100%**，外圈平均亮度 234–248（`logo` 外圈亮度 253、近白 100%）。
3. **实机观感**：装备图标位是 28×28，底色为深色（`.gear-ic` 的 `rgba(201,161,59,.08)` 压在暗色页面上）→ 52 个图标在深色主题下是**一片浅灰方块**；`logo` 以 `height:82px; contain` 压在 hero 阵营横幅上 → 出现一块 123×82 的**白色矩形**。

### 根因

出图模型按「transparent background」提示词画出的是**浅灰白底色**（还带一点中央亮、四周暗的渐变），并非真透明；`tools/prep_units.py` 里 `--kind gear` 虽然设了 `alpha=True`、`alpha_quality=90`，但源图本身没有 alpha，libwebp 对「全不透明」的 RGBA 会**直接丢弃 alpha 通道**——脚本没错，救不回上游。

### 整改（二选一，推荐 B）

- **A（出图端）**：提示词改为「纯色键控底（如 `#00FF00` 纯绿）」，或使用支持真透明 PNG 输出的模型/接口，再抠图。
- **B（落位前加一步抠图）**：

```bash
# 逐张抠图（任选其一）
rembg i in.png out.png                      # rembg
backgroundremover -i in.png -o out.png      # backgroundremover
# 再走既有流程落位
python tools/prep_units.py --kind gear --src <抠好的目录> --force
```

同一批处理里**把 `assets/tex/logo.webp` 也一起抠**（它同样是硬约束的透明底）。

### 防回归（建议随本次整改一起落）

- `tools/check_assets.js`：在装备图集与场景图分支里加一条断言——读容器头，`VP8 `（无 `ALPH`）即 `FAIL`；`logo.webp` 与 `assets/gear/*.webp` 必须命中 `VP8X + ALPH`。
- `tools/prep_units.py`：在 `save_webp()` 之后对 `t['alpha'] is True` 的目标断言产物含 `ALPH`，否则**点名报错**（现在它只保证压进预算，不保证透明）。

> 这一项此前**没有任何脚本覆盖**——`check_assets.js` 只查「在不在 / 方不方 / 多大」，所以 52 张白底图一路绿灯通过。

## 四、P1 兵牌整批 48 张画风不对（规格已修正，需整批重出）

先说结论：这批兵牌不是「某几张背景不对」，而是**整批 48 张画风选错了**。

原 §3.5 写的是「游戏单位卡式画法、单人 3/4 侧身、均匀柔光、**色块概括、边缘干净、对比略高于写实那套**」，照这条出出来的就是现在这种**描边感 + 平涂色块 + 高对比平光**的样子——它其实更接近玩家 MOD（Bullgod「牛神」）兵牌，而**不是《罗马 2》原版**。原版兵牌是**写实古典半身像 + 低对比暗调 + 厚重油画质感**（造型语言来自古希腊红绘陶瓶与罗马石刻浮雕）。
