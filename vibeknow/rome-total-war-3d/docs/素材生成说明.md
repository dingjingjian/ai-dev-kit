# 素材生成说明

本文是「出图 / 找 BGM / 落位 / 核对」的总流程。逐项规格不在这里，按图位查另两份文档：

| 素材 | 规格文档 |
|------|----------|
| 兵种图 ×48（写实）+ ×48（兵牌） | [`兵种图片素材需求.md`](兵种图片素材需求.md) |
| 装备图 ×52（检阅页右列「装备拆解」） | [`装备图集需求.md`](装备图集需求.md) |
| logo / 大理石 / 阵营横幅 ×9 / **过渡画面 ×9**（共 20 个图位） | [`场景配图需求.md`](场景配图需求.md) |
| 背景音乐 | [`背景音乐需求.md`](背景音乐需求.md) |
| **可直接复制的提示词** | [`提示词包.md`](提示词包.md)（由 `tools/gen_prompts.py` 生成，不要手改） |

## 一、分工

| 环节 | 谁做 |
|------|------|
| 找 BGM、出图 | 你 |
| 框架、UI、生图文档、提示词包、落位与核对脚本 | 已就绪（本仓库） |

**出图前**先拿提示词：

```bash
python tools/gen_prompts.py               # 从三份规格文档拼出 168 条完整提示词 → docs/提示词包.md
                                          # （写实 48 + 兵牌 48 + 装备 52 + 场景 20；每条兵种给 4 段）
python tools/gen_prompts.py --txt out     # 另写 .txt/图（写实 <id>.txt / 兵牌 card-<id>.txt）
```

> 提示词**怎么交给生图 agent**（一条一图、EN/CN 二选一、位置数字要翻译成画面口吻、
> 模型不听话时的加码顺序）见 [`提示词包.md`](提示词包.md) 零、——出图前读一遍，能省下大半返工。

**出图后**一键落位（裁方 → 缩尺寸 → 转 sRGB → 压 WebP → 写进正确文件名）：

```bash
python tools/prep_units.py --src <原图目录> --dry                 # 写实：先空跑，看文件名匹配对不对
python tools/prep_units.py --src <原图目录>                       # 写实：确认无误再真跑
python tools/prep_units.py --kind card --src <兵牌原图目录> --dry  # 兵牌：另开一个目录跑同一套流程
python tools/prep_units.py --kind card --src <兵牌原图目录>        #  → assets/units/card/
python tools/prep_units.py --kind gear --src <装备原图目录>        # 装备：128×128 透明底 → assets/gear/
python tools/prep_units.py --kind tex --src <过渡画面原图目录>      # ⑨ 过渡画面 → assets/tex/gate-<key>.webp
                                                                  #   原图命名 gate-rome.png / gate-macedon.png …
                                                                  #   （带前缀的图位一律这样命名，与 faction-<key> 同规矩；
                                                                  #    实在对不上用 --map 写一份对应表）
```

素材落位后跑一遍核对，就知道有没有超标：

```bash
node tools/check_data.js      # 代码契约：数据 / CSS / JS 三方对不对得上
node tools/check_assets.js    # 素材本身：在不在、够不够方、多大、总量超没超
python tools/smoke_test.py    # 无头冒烟：五页流程 + 缺图回退 + 自选军团分支
```

## 二、生成顺序（建议四批）

按「先定调子、再补数量」排，**任何一批做完都能单独落位看效果**——
缺的图一律回退色卡、横幅或纯色，页面照常能跑，不会白屏。

| 批次 | 内容 | 为什么先做 |
|------|------|-----------|
| **1** | 过渡画面 ×9（⑨ `gate-<key>.webp`） | 「即将检阅」页整整 7 秒就是它，而且是这一页唯一按阵营变的东西；做完这一页就成型。规格见 [`场景配图需求.md`](场景配图需求.md) 三、 |
| **2** | 阵营横幅 ×9 | 首页 hero 轮播 + 阵营卡片主体，**一图两用**；做完首页就基本成型。顺带：在 ⑨ 出图之前，它也在扮演 ⑨（每阵营一张不同的过渡画面） |
| **3** | 兵种图 ×48（写实） | 数量最大，可以分批补；建议按阵营推进，一个阵营 6 张一次出，风格更一致。**除罗马外的 42 支在用这套** |
| **4** | logo / 大理石 | 锦上添花（logo 与大理石已落位）。**兵牌那套不用出**：2026-09-22 整组退役，48 支一律走写实 |
| **5** | 装备图 ×52 | 8KB 的小图、一件被多个兵种复用；缺了页面就退成槽位名文字，可以最后补 |

> ⑨ 九张之间要**同一机位、同一光位**（夕阳左后方逆光、入口洞内最深）——换阵营时是硬切，
> 机位或光位一变就会跳。同一批、同一套前缀出完最稳。

BGM 与上面四批并行，什么时候做完什么时候落位。

> 出图模型的"风格一致性"靠**同一批、同一套前缀**保证。
> 48 张兵种图如果分十次出、每次换措辞，最后会有几张明显不对——
> 按阵营分批出（每批 6 张、共用同一条前缀）比一次性出 48 张更稳。

## 三、后处理要点

出完图到落位之间还有四步，跳过任何一步都可能"看着对、实际不能用"：

### 3.1 裁成精确尺寸

| 图位 | 输出尺寸 |
|------|----------|
| 兵种图（写实 / 兵牌两套同规格） | **512×512**（必须精确方图） |
| 装备图 | **128×128**（保留透明底） |
| 阵营横幅 | 1600×600 |
| 过渡画面 ⑨ | 1600×900 |
| logo | 512×340，**军牌式（不透明，深石底 + 暗金描边）** |
| 大理石 | 512×512，**可平铺** |

### 3.2 转 WebP 并压到预算内

交给脚本做，不要一张张手工另存：

```bash
python tools/prep_units.py --src <原图目录>
```

它按 §3.1 的尺寸表裁方缩放，从 q82 往下找第一档能压进预算的质量（最低 q60），
压不进去会**点名报错**而不是硬写出一张超重的图。原图目录只读，绝不删改。

想手工处理时的等价命令（cwebp 示例，Google WebP 工具包）：

```bash
cwebp -resize 512 512 -q 80 in.png -o out.webp
# logo 是军牌式（不透明）：按普通有损压即可，不用 -alpha_q
cwebp -resize 512 340 -q 82 in.png -o logo.webp
# 装备图才要透明底：
cwebp -resize 128 128 -q 85 -alpha_q 100 in.png -o gear.webp
```

质量从 `q 80` 起；单图超上限就往下调（`80 → 75 → 70`），
**不要为了压体积把尺寸降到 512 以下**——画框最大 190px，512 已经是最低够用线。

预算总表：

| 素材 | 单张上限 | 全套上限 |
|------|----------|----------|
| 兵种图 ×48（写实） | 70 KB | 2.6 MB |
| 兵种图 ×48（兵牌） | 55 KB | 2.0 MB |
| 场景图 ×20 | logo 40 / 大理石 60 / 横幅 120 / **过渡画面 110** KB | 2.7 MB |
| 其中 ⑨ 过渡画面 ×9 | 110 KB | 0.9 MB |
| 装备图 ×52 | 8 KB | 0.6 MB |
| BGM | 解码后 1 MiB | `bgm.js` ≤ 2 MB |

> 过渡页**已取消视频**（原预算是 1.2 MB / 1 段 7 秒 720p）：⑨ 九张图全出也只占 ≤0.9 MB，
> 比视频更省，而且换阵营时画面真的会变。

### 3.3 清掉元数据

导出时去掉 EXIF / ICC / 缩略图。元数据通常只占几 KB，
但带广色域 ICC 的图在不同浏览器上会偏色，统一按 **sRGB** 输出最省心。

### 3.4 这几项必须单独验

- **大理石**：拼 2×2 看接缝。平铺纹理最常翻车的就是这一条，接缝一眼可见就重出。
- **⑨ 过渡画面 ×9**：九张并排看，确认**同一机位、同一光位**（夕阳左后方逆光、入口洞内最深），
  入口都在画面正中、整扇完整可见，画面下三分之一没有主体（字幕压在那儿）。
  换阵营时这一页是硬切，九张之间任何一张漂了就看得出来。
- **阵营横幅**：它既是卡片底图、也是首页 hero 轮播图，两者的裁切方式不同
  （卡片裁上下、hero 裁左右）。焦点压在最右侧的图在 hero 里会被裁掉——焦点要落在画面中部偏右。
- **兵牌那套（已退役，留档备用）**：先对画风——**写实古典半身像（胸肩到腰）+ 低对比暗调 + 厚重油画质感 + 模糊暗色纯色底**，
  出现线稿描边、平涂色块、强明暗对比、亮白底、图内边框或界面元素，一律重出（详见
  [`兵种图片素材需求.md`](兵种图片素材需求.md) §3.5–3.8，2026-09-22 已按《罗马 2》原版兵牌修正）。
  再和写实那套并排看，确认是**同一批兵种、同一套装备**，只是画风、取景与背景不同。
  高卢 / 日耳曼两阵营最容易跟写实那批混出，单独盯一遍。
- **装备图**：必须**透明底**（把图放到深色底与浅色底上各看一遍，出现白方块就是没抠干净）；
  缩到 28px 再看一眼——认不出来的就删细节。马具那四张要确认**没有马镫**。

## 四、落位

```
assets/units/<id>.webp       兵种图 ×48（写实），文件名 = units.js 的 id（含连字符）
                             （兵牌那套 assets/units/card/ 已退役、图已删）
assets/gear/<id>.webp        装备图 ×52，文件名 = assets/gear.js 里 GEAR 的键（128×128 透明底）
assets/tex/logo.webp
assets/tex/gate-<key>.webp   ⑨ 过渡画面 ×9（每阵营一张；缺了退该阵营横幅）
assets/tex/marble.webp
assets/tex/faction-<key>.webp    ×9，key = units.js 的 FACTIONS[].key，自选军团是 custom
                                 （8 个预设阵营的横幅同时是首页 hero 轮播图）
assets/audio/bgm.js          由 tools/make-bgm.mjs 生成，不要手改
assets/audio/bgm-src.mp3     源曲目（构建输入，不进包）
assets/audio/README.md       版权留档（不进包）
```

**文件名必须逐字对应**。写错不会报错——会静默回退到色卡或大理石，看不出哪里错了。
`node tools/check_assets.js` 会列出所有缺失与多余的文件名，落位后先跑它。

> 文件名不用手工逐个改：`python tools/prep_units.py --src <原图目录>` 会自动把
> `velites (1).png`、`Velites_01.PNG` 这类都认成 `velites` 并写成 `<id>.webp`；
> 兵牌那套用 `--kind card --src <兵牌原图目录>` 落进 `assets/units/card/`。
> 实在认不出来的会列出来等你改名，不会瞎猜着覆盖。

## 六、踩坑清单

| 症状 | 原因 | 处理 |
|------|------|------|
| 兵种图显示成一块纯色 | 文件名与 `id` 不一致，或不是 WebP | `check_assets.js` 会列出多余/缺失的文件名 |
| 兵种图显示成一块纯色（色卡） | 该兵种的写实图未落位 / 文件名与 `id` 不一致 | 见上一行；`check_assets.js` 会点名缺哪几张（兵牌那套已退役，不会再回退到它） |
| 装备拆解那列全是文字没有小图 | `assets/gear/<id>.webp` 未落位，或文件名与 `gear.js` 的键不一致 | `python tools/prep_units.py --kind gear --src <装备原图目录>`；`check_assets.js` 会列出缺的张数与多余的文件 |
| `prep_units.py` 报「压不进 XX KB」 | 细节量太大（高频纹理、噪点、误入的文字） | 换图或降低画面复杂度；不要靠缩小尺寸绕开——512 已是最低够用线 |
| 重跑了 `prep_units.py` 但页面没变 | 默认跳过已落位的文件 | 改了原图要加 `--force`，否则拿到的还是上一版 |
| 画面里人物糊成一团 | 细节太多，实际只显示 88–190px | 按 [`兵种图片素材需求.md`](兵种图片素材需求.md) 二、的构图模板重出，删细节 |
| 过渡页面「换阵营但画面没变」 | `gate-<key>.webp` 没落位或 key 写错 | 静默退到该阵营横幅（看着没错，其实是横幅在顶）；`check_assets.js` 会点名 ⑨ 缺哪几张 |
| 换阵营时过渡画面跳了一下 | ⑨ 九张之间机位 / 光位不一致 | 同一批、同一套前缀重出，见 [`场景配图需求.md`](场景配图需求.md) 三、 |
| 过渡页上下留一大条边 | ⑨ 是 16:9，竖屏 `contain` 必然上下留边 | **这是有意为之**：门 / 入口永远完整可见，边上由**同一张图的模糊铺底**填满（`.gate-bg`，吃同一个 `--gate-art`） |
| 过渡页信箱边里露出**另一张图**，或画面里冒出一台现代相机 | 旧的通用凯旋门 ③⑤⑥ 还在画面链里（或又被落位了） | 已整组退役（[`场景配图需求.md`](场景配图需求.md) 八、）：确认 `.gate-bg` / `.gate-shot` 的 `background-image` 只剩 `var(--gate-art)`，并删掉 `assets/tex/` 下那三张 |
| 控制台报 `gate-<key>.webp` 404 | ⑨ 还没出图 / 该阵营缺图 | **正常**：画面链靠「前一层 404 就露下一层」实现，会退到该阵营横幅，不影响功能 |
| 大理石能看到网格状接缝 | 纹理不可无缝平铺 | 换一张，生成后先拼 2×2 验 |
| 骑兵图上出现马镫 | 年代穿帮 | 重出，提示词里明确写「无马镫」 |
| 阵营卡背景不对 | `faction-<key>.webp` 的 key 写错 | 检查 `FACTIONS[].key` |
| 打了包没声音 | `bgm.js` 未生成，或变量名不是 `RTW3D_BGM` | 见 [`背景音乐需求.md`](背景音乐需求.md) 四、 |
| `analyze-bgm.mjs` 跑了几分钟没结果 | 旧版会给全部候选重算波形互相关（已在本项目修） | 见 [`背景音乐需求.md`](背景音乐需求.md) 4.3 |
| 源是 mp4/mkv 等视频 | 先抽音轨 | `python tools/extract-audio.py "视频.mp4"` |

## 七、素材齐了之后

打出 zip：

```bash
node tools/pack.mjs      # 产出 rome-total-war-3d.zip（zip 根即 index.html）
```

录宣传片可以直接用自动演示模式，不用手动点：

```
index.html?demo              自动跑完 罗马 的整套流程
index.html?demo=macedon      指定阵营（key 同 FACTIONS[].key）
index.html?demo&loop         跑完回到阵营页循环重播
index.html?demo&warm=6       先静置 6 秒预热（软件渲染下让地球组件先稳定）
```
