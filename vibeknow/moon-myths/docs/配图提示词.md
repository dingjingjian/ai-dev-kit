# 配图提示词与落位契约

「寰宇月话 · 全球月亮神话」神话卡片配图：**14 张**，一张对应一个文明点位。
本文既是给生图模型的提示词包，也是给落位者的验收标准——**先读第三节「硬约束」和第六节「落位契约」，再动笔出图**。

## 一、图位总览

| 项 | 内容 |
|----|------|
| 数量 | 14 张（每条神话一张，不共用） |
| 落位 | 神话卡片 `.card .pic`（打开标记后弹出，位于神话名与故事之间） |
| 尺寸 | **1080×360**（约 3:1 横幅） |
| 上机裁切 | 图槽高 132px（≤640px 屏为 112px），按 `cover` 居中填充，比例 2.8:1 ~ 3.1:1 |
| 格式 | WebP（有损，质量 78 左右） |
| 体积 | 单张 **≤90KB**，全套 **≤1.2MB** |
| 路径 | `assets/illus/<slug>.webp`，目录不存在时新建 |
| 代码入口 | `assets/myths.js` 每条记录的 `img` 字段（已写好，放图即生效） |

### 缺图不是障碍

`img` 指向的文件不存在或加载失败时，卡片会**自动回退到程序化占位**：夜空渐变 + 星点 + 一轮月白圆盘 + 一行小字「配图待生成」以及该图位的文件名。
也就是说：**14 张可以分批补，一张不做也能上线**。这一点是硬要求，不要为了"必须凑齐 14 张"而降低单张质量。

## 三、硬约束

1. **横向安全边**：出图按 3:1 出，但上机按 2.8:1 ~ 3.1:1 裁切。主体必须居中，**左右各留约 10%、上下各留约 12%** 的空白余量，人物头部、月轮、旗帜等不要贴边。
2. **月色是唯一主光源**。卡片周围是深靛蓝夜空，出现白昼蓝天、强金色逆光或摄影棚打光都会与界面脱节。
3. **色调统一**：全部走深靛蓝 + 月白 + 暖金。允许少量环境色（雪青、赭石），但整体要压暗、低饱和。一张暖橙色的图混进去就会破功。
4. **无文字**：不得出现任何文字、印章、题款、水印、签名板。神话名与故事由界面里的 HTML 文字承担，图上再写字必然和界面字打架。
5. **不混搭文化**：这是最容易翻车的项。埃及条目不要出现希腊柱式，北欧条目不要出现维京长角盔（史实错误），阿兹特克不要配玛雅/印加元素，因纽特不要画成北美印第安羽饰，波利尼西亚不要画成迪士尼式的草裙游客。逐条对照第四节的「红线」验收。
6. **人物要庄重不猎奇**：涉及原住民与非洲题材时，按「古老、庄严、有神性」处理，不做野蛮化、奇观化、漫画化的描绘。
7. **不出现神像面部特写的宗教争议**：印度与埃及条目取「仪式感、侧面、远景」最稳，避免正面巨脸。

## 五、生成与转换

### 出图后落位四步

1. **裁切**：按 1080×360（3:1）裁，主体居中，左右留 10%、上下留 12% 安全边。
2. **压暗调色**（可选但推荐）：整体压暗、降饱和，让画面的平均亮度低于卡片底色 `#060b1a` 的一档以上，避免在深色卡片上"发光刺眼"。
3. **转 WebP**：

```bash
# ffmpeg
ffmpeg -i in.png -vf scale=1080:360 -q:v 78 -y out.webp
# 或 cwebp
cwebp -q 78 -resize 1080 360 in.png -o out.webp
```


- `assets/app.js` 在启动时对 14 条 `img` 各做一次 `new Image()` 预检：加载成功 → 卡片图槽加 `has` 类并设为 `background-image`；失败或 2.6 秒仍未就绪 → 保持占位。

## 七、事实核查记录（2026-09）

出图前对 `myths.js` 的 14 条故事逐一做了文献核查：**12 条有改动，2 条核查通过**（日本·辉夜姬、希腊·塞勒涅）。
下表是**已修正**的条目与依据，此节保留，便于日后复核与出图时对照——**配图必须画修正后的版本，不要照旧稿画**（例如印度条目里头顶月牙的是湿婆、埃及条目里与孔苏对弈的是托特、阿兹特克条目里被斩首的是姐姐）。
