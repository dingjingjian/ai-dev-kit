# 人类科技树 · Tech Tree

> **分类**：`#vibeknow` 人文知识　·　分类索引见根目录 [`TRACKS.md`](../../TRACKS.md)

参照文明系列（Civilization）的科技树形态，把人类的 **72 项技术** 按 **10 个时代** 一层层铺开：纵向是时间，节点是技术，连线是「前置科技」——只有先掌握上游，下游才谈得上出现。每条技术给出中英文名、出现年代、它从哪里来（前置）、又长出了什么（后续）、介绍、关键参数、亮点与 AI 配图提示词。

纯前端零依赖、离线可用，已适配小红书小工具容器。

**与「图鉴」类项目的区别**：本项目的核心不是条目清单，而是**关系**。120 条前置关系构成一张有向无环图，页面把它画成一条条连线，并允许逐级点进去看脉络。

## 打开方式

双击 `index.html`，或打包后上传小红书小工具。

## 三个视图

| 视图 | 路由 | 内容 |
|------|------|------|
| 科技树 | `#/tree` | 10 个时代分层排开，节点 + SVG 前置连线；点击节点看脉络 |
| 图鉴 | `#/list` | 按时代分组的卡片列表，配图位在这里 |
| 详情 | `#/t/<id>` | 大图、介绍、关键参数、前置与后续（可点跳转）、亮点、AI 配图提示词 |

## 功能

- **纸面编年史风格**：暖纸底色、墨色细线、衬线标题、直角线框、无投影无毛玻璃——刻意避开「圆角卡片 + 胶囊徽标 + 玻璃拟态」的通用应用观感，向印刷图录靠拢。
- **首页导语**：卡片里只有一段题引 + 一行统计，题引之后不写说明段（怎么读这棵树，节点上的年代与「起点」标签、图例、底部操作条已经讲清楚了，再写一遍是啰嗦）。题引引自《文明 VI》开篇旁白（中文版）：「从水下第一个生命的萌芽开始……从早期文明的摇篮到浩瀚星宇。」卡片标题是「从第一个生命，到浩瀚星宇」，不与顶栏那条常驻的「人类科技树」重名。
- **科技树分层布局**：时代为层，层内节点按「前置重心」自动排序（重心 + 保序拓扑修正），把前置尽量排到下游的左上方，减少连线交叉。
- **时代立柱不挡线**：每个时代是左侧一根窄立柱（罗马数字 + 名称 + 年代，随滚动吸顶），不横占节点区；跨时代连线在时代之间的空档里横铺，全程可见。吸顶偏移由顶栏实测高度写入 `--nav-h`，不硬编码。
- **两种连线**：同代 / 相邻时代的前置是实线（从源节点底部弯入目标节点顶部）；跨多个时代的前置是**虚线**，表示「更早时代的渊源」。图例里有说明。
- **点击节点看脉络**：选中后整块反色成墨块（像书页上的记号），点亮整条上下游脉络的全部连线，直接前置 / 后续描边加重，无关节点淡出；底部操作条显示「前置 n 项 · 后续 n 项」并给出「查看详情」。
- **搜索**：按中文名 / 英文名 / 年代即时过滤，命中高亮、其余淡出，命中的时代保持展开。
- **起点与前瞻**：没有前置的节点标「起点」，近未来时代的节点标「前瞻」并用虚线描边。
- **背景音乐**：顶栏最右一枚开关，音源是《Sogno di Volare》。**用户第一次点按之后**才出声，之后带 4s 交叠淡化循环；关掉后写进 `localStorage`，下次进来仍是静音。
- **分享到小红书**：详情页一枚按钮，**图文就是该条科技的原图、正文就是它的介绍**（另附时代与年份、前置 / 后续溯源），一键唤起 App 的笔记发布页。只有容器里拿得到 `postNote` 时才出现。
- **返回原位**：从详情返回时回到离开时的视图与滚动位置。
- **移动端优先**：竖屏两列（≥520px 三列），大字号、安全区适配、触摸友好。

| 2 | 早期文明 | 公元前 3500 — 前 1200 年 | 8 | 陶器、农业、畜牧、纺织、轮子、风帆、文字、青铜冶炼 |

| 4 | 中世纪 | 500 — 1450 年 | 8 | 造纸术、印刷术、指南针、远洋帆船、炼金术与蒸馏、火药、机械钟、大学与学术 |
| 5 | 大航海与科学革命 | 1450 — 1700 年 | 7 | 远洋航行、日心说与天文革命、解剖与生理、光学与透镜、解析几何与微积分、真空与大气压、经典力学 |
| 6 | 工业时代 | 1700 — 1870 年 | 8 | 蒸汽机、纺织机械、焦炭炼铁与钢铁、近代化学、铁路与蒸汽机车、电磁学、病菌学说与疫苗、演化论 |

| 8 | 信息时代 | 1950 — 2000 年 | 7 | 计算机与信息论、晶体管与集成电路、航天、分子生物学与基因工程、互联网、医学影像、软件与个人计算 |
| 9 | 数字与智能时代 | 2000 年 — 今 | 7 | 移动互联网与智能手机、云计算与大数据、机器学习与深度学习、基因编辑、光伏与动力电池、生物医药与 mRNA 疫苗、量子计算与量子通信 |
| 10 | 近未来 | 2020 年代 — 未来 | 6 | 通用人工智能、可控核聚变、通用机器人、脑机接口、合成生物学、抗衰老与再生医学 |

**关系规模**：120 条前置关系，其中 22 条跨多个时代（图上画成虚线），3 个起点节点（石器制作、用火、语言）。

> 年代与参数取自公开资料并做了取整与概括（如「约公元前 6000 年」「19 世纪」），用于速查与科普；技术起源多为多地独立发生，条目内一律用「约」与区间表述，正式发布前建议逐条复核一遍。前置关系反映的是**技术上的依赖逻辑**，不是唯一的历史因果，个别条目（如疫苗、抗生素）出现的先后与前置时代并不严格对应。

## 配图协议（图片由图像生成 agent 接手）

**科技树的节点不配图**——节点是紧凑小卡（年代 + 名称 + 英文 + 连线），塞图会挤掉连线空间也看不清。图片只用在两处：**详情页大图**，以及**图鉴视图的卡片与时代封面**。

1. **规格**：条目图 `assets/img/<科技 id>.webp` 640×360；时代封面 `assets/img/cover-<时代 key>.webp` 960×540。尺寸、体积、构图与禁用项的细则统一写在 [`_dev/image-spec.md`](_dev/image-spec.md)（唯一真源，生成时自动嵌入施工图）。
2. **提示词施工图**：逐张提示词见 [`_dev/IMAGE_PROMPTS.md`](_dev/IMAGE_PROMPTS.md)（另有机器可读的 [`_dev/image-prompts.json`](_dev/image-prompts.json)）。该清单由 `python _dev/gen_image_prompts.py` **从 `data.js` 自动派生**，数据只维护一遍。
3. **拼接口径**：完整提示词 = `data.js` 里的 `IMG_STYLE`（统一风格串）+ 空格 + 条目的 `subject`。详情页展示的也正是这条拼好的提示词。
4. **两种画面模式**：`subject` 已指定是「博物馆器物实拍」还是「极简 3D 概念图」（语言、哲学、互联网、人工智能这类没有单一实物的条目走概念图）。风格串里只禁「可读的现代文字」，允许泥板、铅字、针灸铜人上的不可辨识古文字刻痕。
5. **投入即生效**：图片按名放入 `assets/img/` 即可，页面无任何改动；后缀回退链为 `webp → jpg → jpeg → png`，全部找不到才显示占位块。
6. **体积**：条目图 ≤45 KB、时代封面 ≤90 KB、全部配图合计 ≤1.8 MB。`build_zip.py` 会在打包时统计并提示。
7. **状态**：**82 / 82 张已就位**（10 张时代封面 960×540 + 72 张条目图 640×360），合计 845 KB，逐张核过尺寸与体积均在 spec 之内；占位块只在缺图时才露出来。

## 背景音乐

顶栏最右一枚方形开关（与顶栏其他控件同一套纸面样式）：出声＝墨底纸音符，静音＝纸底灰音符 + 斜杠。

| 项 | 说明 |
|------|------|
| 曲目 | 《Sogno di Volare》· 取源曲 **16s → 121s** 这段 105s 乐句 · 64kbps 单声道 22.05kHz（解码后 821 KB / 0.802 MiB） |
| 数据 | `assets/audio/bgm.js`（`window.TT_BGM`，由 `_dev/audio/make-bgm.mjs` 生成）；源曲 `assets/audio/bgm.mp3` 是构建输入，**不进 zip** |
| 为什么 base64 | 容器上传白名单不收任何音频扩展名，CSP 又禁 `data:` / `blob:` 媒体源 ——「包内音频文件 + `<audio src>`」在容器里不存在，音频只能以字符串藏进 `.js`，运行时 `atob → ArrayBuffer → decodeAudioData` 交给 Web Audio，**全程不产生任何 URL** |
| 选点 | 由 `make-bgm.mjs --auto` 选出：判据是「整段平均能量高 + 接缝处安静」（本题 105s 段：能量 0.1343 / 接缝 0.0878），详见 [`docs/背景音乐需求.md`](docs/背景音乐需求.md) §3 |
| 起播 | **用户第一次点按之后**才出声（容器 autoplay 策略要求手势），之后全程循环 |
| 循环 | 每遍最后 4s 线性淡出、下一遍同时淡入，两者完全重叠且增益和恒为 1，接缝听不出来 |
| 开关状态 | 显示的是**此刻有没有在出声**，不是「用户想不想听」——首屏必然没声音，显示成已开启就是在骗人；`bgmWant` 只负责记住偏好并决定首次手势后是否起播 |
| 偏好 | `localStorage` 键 `tt.bgm`：没存过＝偏好开启，用户手动关掉才记成静音；读写失败静默降级 |
| 切后台 | `visibilitychange` 停声 + 挂起音频上下文，回前台续上 |
| 缺数据 | 解码成功才给 `<html>` 挂 `has-bgm` 把开关显出来；没有数据 / 解码失败＝开关隐藏，其余功能一切照常 |

> ⚠️ **版权**：《Sogno di Volare》是《文明 VI》主题曲（Christopher Tin），文件来自素材站下载，
> **不构成商用授权** —— 上架小红书小工具或用于宣传片前必须换曲或取得授权。
> 换曲只需重跑 `node _dev/audio/make-bgm.mjs "新曲目.mp3"`，页面与代码一行都不用改。

## 分享到小红书（详情页）

正文区上方一枚「分享到小红书」按钮：**图文就是该条科技的原图，正文就是它的介绍**（外加时代 · 年份与前置 / 后续溯源）。只有容器里拿得到 `postNote` 时才建出来。

| 项 | 说明 |
|------|------|
| 触发 | 详情页按钮，由用户手势触发（容器要求） |
| 取图 | 页面上**已经加载好的那张原图**经 Canvas 取成 `data:uri`（先试 WebP，编码不被支持再退 JPEG） |
| 为什么不用 XHR 取原字节 | 参考项目 `jurassic-park-3d` 用 XHR + FileReader 把原图字节原封不动交出去；但本仓 skill 的 `device-capabilities.md` §4/§7 把网络请求 API 列为**不可用行为**并进了扫描清单（连标识符都不许出现，打包守卫会 grep），所以这里改走 Canvas —— 代价是重编码一次（640×360 出图约 19 KB），换来一行被禁 API 都不用。容器里页面与图同源，画布不会被污染 |
| 落文件 | 有 `writeTempFile` 就先把 `data:uri` 换成临时 `filePath` 再交给 `postNote`；没有则直接把完整 `data:uri` 传进 `mediaInfo`（`jsbridge-api.md` 允许 base64） |
| 参数 | `pageType:"photo_publish"` · `title` ≤20（`人类科技树 · <科技名>`）· `content` ≤1000 · `mediaInfo.image_resources[0].url`（两处上限都主动裁剪） |
| 能力检测 | 拿不到 `postNote` 就整块隐藏（桌面直接开 `index.html` 不出现、测试里也是这条断言）；**不做 UA / 机型判断** |
| 原图未就位 | 按钮压暗且不可点（lazy 加载晚于渲染，图片 `load` 后自动转可用） |
| 结果语义 | `postNote` 成功只代表**发布页被唤起**、用户点了发布，**不代表过审** —— 所以只提示「已唤起」，不据此改任何状态 |

## 工程约定

| 项 | 说明 |
|----|------|
| 源码 | `index.html`（内联 CSS）+ `data.js`（数据真源）+ `main.js`（渲染逻辑，经典脚本） |
| 数据真源 | `data.js` 的 `ERAS`（时代）、`TECHS`（科技）、`IMG_STYLE`（配图风格串）；`_dev/parse_data.py` 负责解析，供校验与清单派生共用 |
| 条目字段 | `id / era / name / en / year / roots[] / tag / intro / specs[[k,v]] / feats[] / subject`；图片路径由 `id` 与 `era` 推出，不额外存路径 |
| `roots` 字段 | 前置科技的 id 数组，空数组表示该时代起点。**只能指向同代或更早时代**，`_dev/check_data.py` 会校验 |
| 排序约定 | 时代内顺序不写死在数据里，由 `computeEraOrder()` 按前置重心 + 保序拓扑排序算出；数据顺序只作为并列时的基准 |
| 网格列数 | 视口 <520px 两列、否则三列。`main.js` 的 `cols()` 必须与 `index.html` 的 `@media(min-width:520px)` 断点一致 |
| 时代立柱 | `.era` 是 flex：左侧 `.era-rail`（74px，`position:sticky` 吸顶，罗马数字用时代色）+ 右侧 `.era-grid`。立柱不横占节点区，因此连线不被遮住；年代跨度用 `-webkit-line-clamp:3` 截断，完整跨度在图鉴与详情 |
| 连线层级 | 连线 `z-index:1` < 节点与立柱 `z-index:2`，同处 `.board` 一个层叠上下文（**不要**给 `.era` 加 `z-index`，否则每个时代各成一个上下文，后一个时代的节点会压住前一个时代吸顶的立柱） |
| 连线几何 | 同代同行用横曲线（源侧缘 → 目标侧缘），其余用竖曲线（源底部 → 目标顶部）；控制点落在两个时代之间的空档（或列间中点）上，曲线全程可见、只在节点卡片背后穿过。每条线先算成 4 个折点 `[起点, 控制点1, 控制点2, 终点]`，中间两点直接交给三次贝塞尔当控制点 |
| 箭头 | 用 `<polygon>` 画三角形，不用 `<marker>`（`context-stroke` 在 Chrome 61 上不可用）。朝向由最后一段的方向决定（上 / 下 / 左 / 右） |
| 尺寸测量 | 时代内排序用解析坐标（够用），画线用实测 `getBoundingClientRect`（节点高度会随文字换行而变） |
| 防抖重绘 | 视口变化 220ms 后重画，**回调里再确认一次仍在科技树视图**（否则切走后的延迟重绘会覆盖详情页） |
| 图片框 | 固定高度（卡片 150 / 封面 104 / hero 210）而非 `aspect-ratio`（Chrome 61 不支持）；实图 `object-fit:cover` 盖在占位块上 |
| 间距基线 | Chrome <84 无 flex gap（基线 Chrome 61），横向间距一律用子项 `margin`；栅格间距用 `grid-gap`（Chrome 57+ 支持） |
| 懒加载 | `IntersectionObserver`（Chrome 51+）就近加载图片，无该 API 时降级为立即加载；顶栏毛玻璃用 `@supports` 作增强层，基线为不透明底 |
| 底部操作条 | 选中节点后出现，高度写进 `--selbar-h`，让两个悬浮按钮整体上移（否则「回到顶部」会盖住「查看详情」点不到） |
| 主题色 | 图鉴与树内选中用 `--era-accent`（每个时代一色）；详情页按时代把 `--accent / --accent-soft` 写到根元素 |
| 顶部预留带 | 写法与 [`vibegame/ai-os`](../../vibegame/ai-os/) 对齐：`--top-gap:50px` + `--safe-top:calc(var(--top-gap) + var(--inset-top))`，`.topband{min-height:50px; height:var(--safe-top); padding-top:var(--inset-top)}`。原因：`env()` / 容器注入的 `--safe-area-inset-top` 只覆盖状态栏，**不含**宿主那行「返回 / 分享 / 更多」按钮。容器内嵌时 `body.in-app` **重新声明** `--safe-top` 并把 `--top-gap` 加到 70px |
| 顶栏结构 | 两段：① `.topband` = 预留带，左右各让开 72px 给宿主按钮，**标题（21px 衬线）就居中放在这条带子中间**（所以小屏也不会被挤到换行）；② `.topbar` 38px，左侧是当前视图的标签（科技树「72 项 · 10 个时代」/ 图鉴「72 项 · 按时代分组」/ **详情「当前科技名」，如「蒸汽机」**——它一直吸顶可见，滑到简介 / 参数 / 提示词哪一段都还知道在看哪条技术），右侧是视图切换与音乐开关。无宿主时总高 90px —— 比「标题也挤在第二行」省约 16px。`--nav-h` 仍取 `.topwrap` 实测高度，所以时代立柱的吸顶偏移自动跟着走 |
| 背景音乐 | 载荷以 base64 藏在 `assets/audio/bgm.js`（白名单类型），运行时 `atob → ArrayBuffer → decodeAudioData → Web Audio`，不产生任何 URL；源曲 `bgm.mp3` 是构建输入、不进 zip。构建工具 `_dev/audio/make-bgm.mjs`（依赖仅构建期需要） |
| 分享 | 详情页走容器 JSBridge `postNote`（见 `jsbridge-api.md`）：原图经 Canvas → `data:uri` →（有则 `writeTempFile`）→ `postNote`；标题 / 正文按 API 上限 20 / 1000 主动裁剪；`has-share` 标记挂在 `<html>` 上 |

## 小红书小工具适配

- 脚本外置 `data.js` / `main.js`，无内联 `<script>`、无内联事件、无 `eval` / `new Function`，为经典脚本（无 `type="module"` / `import` / `export`）。
- 无任何 http(s) 外部资源引用，全部配图打包在内，离线可用。
- **顶部按容器预留带让位**：`--top-gap` 50px（容器内嵌 70px）+ `var(--safe-area-inset-top, env(...))` 链式相加；宿主那行「返回 / 分享 / 更多」按钮压在带子左右，**带子中间留给标题**，一举两得：既不挡标题，又省掉一整行高度。
- 底部与左右用 `var(--safe-area-inset-*, env(...))` 组合适配刘海屏与 Home Indicator；`viewport-fit=cover`。
- 不使用 UA 判定宿主，不使用 WebSocket / Worker / geolocation / 剪贴板等被禁能力。
- 背景音乐不引用任何音频 URL：base64 藏在 `.js` 里经 Web Audio 解码播放，因此不吃 CSP 的媒体源限制；解码失败只隐藏开关，不影响其余功能。
- 分享只用容器文档列出的 `postNote` / `writeTempFile` 两个端能力，能力检测（不判 UA），且**不发起任何网络请求**取图。
- 复制 AI 提示词：容器已禁用剪贴板类 API，改为点按后选中提示词文本，引导用户长按手动复制。
- JS 以 ES2017 为基线（Chrome 61），未使用可选链、对象展开、`replaceAll`、`Array.at` 等更新语法；`IntersectionObserver` 等非基础 API 均做能力检测与降级。
- CSS 以 Chrome 61 为基线，未使用 `aspect-ratio`、`clamp()`、逻辑属性、`:has()`、Container Queries、现代颜色函数；无 `backdrop-filter`（顶栏与底部操作条都是不透明纸底）。`position:sticky`（Chrome 56+）用于时代立柱吸顶，`sticky` 不可用时立柱退化为普通左侧标题、不影响阅读。
