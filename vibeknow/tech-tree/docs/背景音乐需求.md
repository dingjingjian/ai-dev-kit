# 背景音乐需求与规格

本文件是背景音乐的**唯一真源**：载荷怎么来的、为什么必须是 base64、循环点怎么定的、
门禁怎么核对的。改曲目请照 §5 重跑工具，然后同步本文件里的数字。

## 1. 交付形态

| 项 | 要求 |
| --- | --- |
| 运行时载荷 | `assets/audio/bgm.js`（`window.TT_BGM`，由 `_dev/audio/make-bgm.mjs` 生成） |
| 源曲目 | `assets/audio/bgm.mp3` —— **只作构建输入**，按打包白名单自动不进 zip |
| 编码 | MP3 · 64kbps · 单声道 · 22.05kHz |
| 时长 | 105.0s（源曲 16s → 121s 这一段乐句） |
| 解码后体积 | 821 KB（0.802 MiB）· 门禁 ≤ 1 MiB，余量 203 KB |
| `bgm.js` 体积 | 1095 KB（base64 字符串，单个 `.js` 门禁 ≤ 2 MiB） |
| 加载位置 | `index.html` 里 `data.js` 之后、`main.js` 之前 |

## 2. 为什么必须是 base64 藏在 .js 里

两条容器约束叠加，把「包内音频文件 + `<audio src>`」这条路彻底堵死：

1. **上传白名单不含任何音频扩展名**（只有 jpg / css / gif / svg / png / js / jpeg / json /
   html / woff2 / webp / woff）——`bgm.mp3` 放进 zip 会被上传页直接打回；
2. **CSP 明确禁止 `data:` / `blob:` 媒体源**——`<audio src="data:audio/mp3;base64,…">` 也放不出声。

所以音频只能以字符串形式藏在白名单类型 `.js` 里，运行时由 `main.js`：

```
atob → ArrayBuffer → AudioContext.decodeAudioData() → Web Audio 播放
```

**全程不产生任何 URL**，因此不触碰 CSP 的资源加载规则。同结论见
[`vibeknow/jurassic-park-3d`](../../jurassic-park-3d/docs/背景音乐需求.md)。

性能门禁（`.skill/minitool-zip-builder/references/performance-budget.md` §1）要求
「单条 Base64 解码后不超过 1 MiB；超过 1 MiB 视为大 Base64，必须改成独立包内文件」——
而第 1 条约束决定了这条退路不存在，所以只能把音频本身压进门禁以内。

## 3. 循环点怎么定的

源曲 233.1s · 44.1kHz 立体声 · 1.78 MB。因为门禁只允许约 131s（64kbps 单遍上限），
必须选一段；`_dev/audio/make-bgm.mjs` 的自动选段按两个可量化的判据打分：

- **整段平均能量**（BGM 要有东西在响，不能挑一段太安静的）；
- **接缝电平**（首尾各 0.6s 的最大电平，越低则 4s 交叠淡化时越听不出断点）。

`score = 平均能量 − 3.0 × 接缝电平`，长度在 105s…门禁上限之间逐档试、起点每 1s 滑一次：

| 候选 | 取段 | 长度 | 平均能量 | 接缝电平 | 得分 |
| --- | --- | --- | --- | --- | --- |
| #1（采用） | 16s → 121s | 105s | 0.1343 | 0.0878 | −0.1291 |
| #2 | 11s → 121s | 110s | 0.1302 | 0.0878 | −0.1332 |
| #3 | 6s → 121s | 115s | 0.1271 | 0.0878 | −0.1362 |

取舍：宁可短 20 秒，也要把接缝落在相对安静的位置。这首曲子整体织体很满
（接缝电平 0.088 ≈ 平均能量的 65%），没有真正的静音段落，因此接缝最终仍靠
播放侧的 **4s 交叠淡化**抹平——见下一节。

## 4. 播放侧的约定（`main.js` 的「背景音乐」段）

| 项 | 约定 |
| --- | --- |
| 起播 | **用户第一次点按之后**才出声（容器 autoplay 策略），之后全程循环 |
| 循环 | 每遍长 D 秒，上一遍最后 X 秒线性淡出、下一遍同时线性淡入，两者在 `[D−X, D]` 完全重叠、增益和恒为 1；`X = min(4s, D×15%)` |
| 音量 | `GainNode` 包络（起播 0.9s 升到 0.34），不用 `setInterval` 调 volume |
| 偏好 | `localStorage` 键 `tt.bgm`；**没存过＝偏好开启**，用户手动关掉才记成静音；读写失败静默降级 |
| 开关显示 | 画的是**此刻有没有在出声**，不是「用户想不想听」——autoplay 策略下首屏必然没声音，显示成「已开启」就是在骗人 |
| 切后台 | `visibilitychange` 停声 + `suspend()` 挂起音频上下文，回前台自动续上 |
| 缺数据 | 解码成功才给 `<html>` 挂 `has-bgm` 把开关显出来；没有数据 / 解码失败 = 开关隐藏，其余功能一切照常 |
| 开关位置 | 顶栏最右一枚方形按钮（与顶栏其他控件同一套纸面样式）：出声＝墨底纸音符，静音＝纸底灰音符 + 斜杠 |

## 5. 换曲目

```bash
node _dev/audio/make-bgm.mjs "新曲目.mp3"                 # 自动选段
node _dev/audio/make-bgm.mjs "新曲目.mp3" --a 16 --b 121   # 手动指定取段（秒）
node _dev/audio/make-bgm.mjs "新曲目.mp3" --kbps 56        # 放不下时降码率
node _dev/audio/make-bgm.mjs "新曲目.mp3" --probe          # 只看源文件参数，不产出
```

依赖只在构建时需要（运行时代码零依赖）：

```bash
cd _dev/audio && npm i mpg123-decoder @breezystack/lamejs
```

跑完把 §1 表里的时长与体积、§3 表里的选段数字一并更新到本文件。
