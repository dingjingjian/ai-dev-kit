# 自检

三层自检，各管一段，互不替代。

## 1. 几何层（Blender，无头）

```bash
blender --background --factory-startup --python ../blender/headless_check.py
```

建一次模型，逐项审计，末尾导出 GLB。**19 项**断言，结果落 `../blender/out/_log.txt`。

| 组 | 断言 |
|----|------|
| 记载符合 | 桅数 = 9、帆数 = 12、隔舱数 = 13 |
| 极值归属 | 最高点是桅顶、最低点是大舵（福船大舵低于龙骨），舵不超吃水的 0.65 倍 |
| 整体比例 | 总高/总长 ∈ [0.40, 0.60]、型深/总长 ≥ 0.09 |
| 桅高弧线 | 最高桅落在 t ∈ [0.55, 0.72]、自尾向中递增、自首向中递增 |
| 篷帆形制 | 帆高宽比 ≥ 1.45（须为高窄帆） |
| 舷孔 | 存在该部件、数量 ≥ 40、逐顶点核验不越出舷外 |
| 双色船体 | 船体外壳实际用到 ≥ 2 个材质槽 |
| 穿模 | 隔舱壁不越出船体线型、篷帆不低于所在站位甲板面 |
| 结构与预算 | 全部部件被拆解分组覆盖、三角面 ≤ 15 万 |

后三项比例断言（0.40~0.60 / ≥ 0.09 / ≥ 1.45）是照参考图重建时立的**回归闸门**：
v1 的实际值分别是 0.21 / 0.047 / 1.1，即「桅帆过矮、船体像驳船、帆接近方形」三个观感问题的量化形式。

> 这层抓到过真 bug：铁锚与舵曾垂到龙骨以下（最低点越界），单看渲染图不容易发现；
> 重建时舵又曾因取局部龙骨线而悬在半空，也是这层拦下的。

**注意**：站位 t 一律由顶点世界坐标反推，不要用 `object.location`——
`MB.build()` 把顶点直接写在世界坐标里，`location` 恒为原点，反推会全部落到船中。

## 2. 参数层（Node，零依赖）

```bash
node params_test.js
```

验的是 `assets/ship-params.js` 的自洽（**25 项**）：桅数 / 帆数 / 长宽比是否符合记载、
模型长宽比是否等于记载长宽比、各桅 t 沿船长单调递增、桅高单峰且峰值落位、
帆的自检形状参数、拆解分组覆盖全部部件、型深与吃水干舷的加和关系。

这层不依赖 Blender，改参数后可秒级回归。

## 3. 产物层（Node，零依赖）

```bash
node ../build.mjs && node ../verify-minitool.mjs ../dist && node ../pack.mjs
```

验的是**打包产物合规**（**21 项**）：包结构 / 引用路径 / 端能力 / 脚本形态 /
JS 与 CSS 兼容基线（Chrome 61）/ Base64 与体积门禁。
这是 `minitool-zip-builder` 规范的机器化版本，逐条可在源码里对回原文。
