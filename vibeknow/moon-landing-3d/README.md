# 3D 登月全程 - Moon Landing 3D

> **分类**：`#vibeknow` 人文知识　·　分类索引见根目录 [`TRACKS.md`](../../TRACKS.md)

以「口袋火箭」同款 UI 与自研 WebGL 引擎打造的登月全过程科普应用：按中国载人登月真实的 **长征十号双箭发射 + 环月交会对接** 架构呈现——先发射揽月着陆器驻留环月轨道，数日后再发射梦舟载人飞船，二者环月对接后，航天员转入着陆器动力下降，稳稳落在月面。

## 打开方式

双击 `index.html`。资源在 `assets/`，需与 `index.html` 保持同级目录（贴图以内联 data URI 提供，`file://` 直接打开即可运行，无需联网）。

## 三种模式

展示 / 拆解两种模式下，底部可在**两枚长征十号**之间切换（同一支箭的两种发射构型）：

- **① 第一次发射 · 揽月着陆器**：助推×2 + 芯一级 + 芯二级 + 芯三级 + 整流罩（罩内为揽月着陆器）；无飞船 / 逃逸塔 / 太阳翼。
- **② 第二次发射 · 梦舟载人飞船**：助推×2 + 芯一级 + 芯二级 + 芯三级 + 整流罩（罩内为梦舟飞船：返回舱 + 服务舱）+ 逃逸塔（坐在罩顶）；无着陆器。

两枚箭都是真实长征十号的**三级半**构型（自下而上：芯一级 → 一二级级间段 → 芯二级 → 二三级级间段 → 芯三级 → 整流罩 → 逃逸塔），差别只在罩内载荷与有无逃逸塔。

| 模式 | 说明 |
|------|------|
| **展示** | 当前构型静态陈列（默认第一次发射构型），拖动旋转视角 |
| **拆解** | 当前构型在独立展示空间中逐级铺开，点击标签查看各部件说明——两枚箭共有的芯一级（+两枚助推）/ 一二级级间段 / 芯二级（2 台 YF-100M）/ 二三级级间段 / 芯三级（3 台 YF-75E）之外，构型①有整流罩 / 揽月着陆器，构型②有整流罩 / 梦舟返回舱 / 服务舱 / 逃逸塔（太阳翼按发射构型收拢，入轨后才展开） |
| **登月** | 完整任务流程，含倒计时、实时遥测、阶段字幕与长按加速（按住越久倍率越高：3× → 10× → 25× → 60×，松手立即回到 1×）；构型由任务流程自动切换（第一发 → 第二发），故此处隐藏构型切换器 |

## 登月流程（双箭发射 → 环月对接 → 月面着陆）

**第一次发射 · 揽月着陆器**

| 阶段 | 内容 |
|------|------|
| 发射上升 | 三芯并联点火、程序转弯、最大动压（无逃逸塔，本次不载人） |
| 级间分离 | 两枚 5 m 助推器分离 → 芯一级分离 → 芯二级（液氧煤油）点火 → 整流罩分离（露出着陆器）→ 芯二级耗尽分离 → 芯三级（液氢液氧）点火 |
| 停泊轨道 | 着陆器由芯三级推入近地轨道 |
| 地月转移 | 芯三级二次点火（TLI）奔月，芯三级分离，着陆器沿转移轨道飞向月球 |
| 近月制动 | 着陆器发动机反推减速（LOI），被月球引力捕获 |
| 环月就位 | 着陆器驻留环月轨道，静候飞船 |

**第二次发射 · 梦舟载人飞船**（数日后）

| 阶段 | 内容 |
|------|------|
| 发射上升 | 三芯并联点火、程序转弯、最大动压、逃逸塔分离、整流罩分离（本次载人：逃逸塔 + 整流罩，罩内为梦舟飞船） |
| 级间分离 | 助推器分离 → 芯一级分离 → 芯二级（液氧煤油）点火 → 芯二级耗尽分离 → 芯三级（液氢液氧）点火 |
| 停泊轨道 | 飞船由芯三级推入近地轨道，太阳翼展开 |
| 地月转移 | 芯三级二次点火奔月，芯三级分离，飞船飞向月球 |
| 近月制动 | 飞船发动机反推减速，被月球引力捕获，进入环月轨道 |
| 交会对接 | 飞船靠近驻留着陆器，环月轨道交会对接，航天员转入着陆器 |

**着陆下降**

| 阶段 | 内容 |
|------|------|
| 着陆器与飞船分离 | 揽月着陆器（载 2 名航天员）脱离梦舟飞船，转入落月飞行 |
| 动力下降 | 下降发动机反推制动，展开着陆腿，扬起月尘 |
| 月面软着陆 | 稳稳触地，地球悬于漆黑月空 |

## 关于「双箭发射」架构

本应用按中国载人登月的真实方案呈现：**长征十号双箭发射**——一枚发射揽月着陆器、一枚发射梦舟载人飞船，二者在环月轨道交会对接后，航天员转入着陆器落月；飞船则驻留环月轨道等待返回。为便于同框观赏，地月距离做了压缩（真实约 60 倍地球半径，此处压缩至约 12 倍），遥测数值仍按真实公里 / 米每秒显示；两次发射之间的数天间隔在时间轴上压缩为一次黑场过渡。箭体构型与部段划分为科普示意，不代表工程实态。

> 工程实现见 `assets/mission.js` 的两段式任务时序：第一次发射结束有着陆器「驻留」（`parked`，独立于主体每帧定位）；段间过渡复原共用箭体、按载人构型换上「罩内梦舟 + 罩顶逃逸塔」；第二次发射经交会（`rendezvous`）沿环月轨道从后方追近驻留着陆器（终态角差 = `DOCK_GAP` 换算出的环月角，飞船始终在着陆器后方，接近轨迹不穿越对方），对接帧对齐姿态后着陆器原位重定基、接合到飞船前方（对接机构在飞船头部），再着陆器与飞船分离（梦舟整体作为刚体缓速漂离、驻留环月轨道，不散架也不淡出）、动力下降、着陆末段、月面软着陆。地月转移按真实过程呈现：近地点切向加速（芯三级二次点火，高度基本不变）后关机、沿椭圆滑行，速度在段末与转移段起点严格衔接；环月 / 交会 / 着陆段的镜头始终锁定飞行器本体（取景目标不再经月心插值），月面镜头以月面法线为 up；重新观看时 `reset()` 会连同高度 / 速度一并清零，因此倒计时阶段发射台正常显示。无头自检见 `tests/headless_two_segment.js`（`node tests/headless_two_segment.js`）。
>
> 时序与几何的几个约定（改这块前务必先读）：
> 1. 活动栈质心不写死常量——入轨 / 船箭分离时用 `centroidOf()` 现场求值并做两级重定基（原点平移到新活动体质心 + 部件 `baseY` 同步回退），模型改动后自动跟随。
> 2. 入轨 MET 由上升段实际取得（`state.metInsert`），随后在停泊轨道段平滑推进到 `MET_TLI`；环月段持续推进到本段终点。MET 应全程单调（自检含该项）。
> 3. 停泊轨道环与箭体共用「视觉半径」`R_ORB_VIS`（含高度增益），遥测仍显示真实轨道高度；两者不要各写一套。
> 4. `approach` 是真实相位；`docking` / `landerSep` / `landing` 只是字幕事件（`PHASES` 中保留其文案），`state.phase` 不会取这些值。
> 5. 两枚火箭的构型（部件可见性）只由 `applyConfig(seg)` 一处决定，展示 / 拆解 / 登月三条路径共用；展示 / 拆解通过 `mission.setVariant(1|2)` 切换，`mission.reset()` 始终复位到构型①，由 app 层在复位后再套用目标构型。两次发射的几何基准完全相同（都带整流罩），因此不再需要"飞船整体下移"这类偏移常量。
>
> 6. 整流罩分离字幕按构型区分（`captionFor` 返回 `fairingSepLander` / `fairingSepShip`）。
> 7. 长按加速不写死倍率：`WARP_TIERS` / `WARP_TIER_AT`（mission.js）给出「按住时长 → 倍率」的爬升阶梯——双箭登月 1× 全程约 6.5 分钟（两段上升各约 94 s、各脚本段合计约 203 s），固定 3× 越过巡航段仍嫌慢，故按住越久越快（3× → 60×）、松手立即回 1×；倍率统一落在 `state.warp`，app 层只做展示（按钮显示当前倍率与挡位箭头）。自检中「对接 / 船器分离跳变」按 `djCur / warp` 归一化成「单位 / 场景秒」——环月段每场景秒本就有 0.028 rad × 环月半径 ≈ 14.5 单位的正常位移，不归一化会在高倍率下被误判为瞬移。
> 8. **倍率必须乘在「一切收敛量」上，不只是推进量与姿态**：脚本段推进（`phaseT`）、姿态收敛（`setPose`）、以及脚本段内的**一阶平滑**（`scale` 缩放、`legsDeploy` 着陆腿展开）、镜头收敛（`directCamera` 里的跟随增益 / `distance` / `yaw` / `pitch`，见 `cw`）与 app 层的 `spaceLightK` / `surfCamBlend` 都要乘 `state.warp`（`stepScripted` 里统一为局部 `sw`）。原因是倍率压缩的是**相位的真实时长**：60× 时 30 s 的动力下降只剩 0.5 s，用原始 dt 的一阶平滑根本来不及收敛——实测着陆器被放大到 9.55 倍（应 1.4）、喷管插进月面 5.1 单位、着陆腿只展开 38%、镜头距离停在 7443（应 14，等于整段着陆看不见）。观赏性「漂移」（上升段镜头自转 `dt×0.035` 等）与粒子发射率仍按真实时间。
> 9. **罩内载荷必须整体收在整流罩内壁包络之内**（`tests` 末尾的「整流罩包络」自检会逐件验算）：整流罩母线是「fy ≤ 1.02 为 r=0.62 圆柱段，其上按 ogive 收窄到罩顶 fy=2.05 处为 0」，所以上部可用半径塌缩极快（fy=1.54 只允许 0.498、1.84 只允许 0.283）。改载荷尺寸（`craft.js` 的 `lander*` / `capsule` 等）后若外径越过内壁，就会从罩顶穿模露出一截。当前余量：着陆器最紧处 0.081（乘员舱 fy≈1.64）、梦舟最紧处 0.160（返回舱）。
> 10. **触地原点的半径 `LAND_RM` 是标定量**（mission.js）：触地时活动体原点在着陆器质心上，`LAND_RM = MR + 1.60` 使「着陆腿完全展开（`LEG_ROT_DEPLOY`）+ 着陆缩放收敛到 1.4」时鞋底恰好落在月面（自检断言鞋底离月面 ∈[-0.05, 0.12]）。改动着陆器几何 / 展开角 / 着陆缩放后必须重新标定该值；触地帧还会把 `scale` / `legsDeploy` / 腿角直接钳到终值，保证任何倍率下落点姿态一致。着陆点经度另由 `LAND_PSI_OFF`（1.35 rad）锚定在「近地点 ± 1.35 rad」中离分离点更近的一侧：偏置 0 时地球近乎当顶（仰角 ≈49°），而月面镜头是俯视着陆器（垂直半视场仅 26°），地球必然被挤出画面上缘；偏置后地球仰角 ≈13°，配合 app.js 的月面机位（`elev=0.06` / `az=0.12`）稳定落在画面右上天空。地球云层（`pad.clouds`，云壳仅高出地表 1.2%）按「离地状态」显隐：上升段低空关闭（贴着地表时它只是一层压住大陆的白纱），`altVis` 60→180 淡入、入轨后全程显示——地月转移 / 环月 / 月面回望地球才是有云有大陆的样子。
> 11. **光照：太阳方向是唯一真源**（`craft.js` 的 `M3D.SUN`）。地月天体（地球 / 云 / 大气 / 月球——即带 `useSun` 标记的网格）由它定向照射，于是有真实的晨昏线、昼夜面与随视角变化的相位（地球夜面还透出城市灯光）；箭体 / 发射场仍走「相机随动光」（`light.dir`），任何机位都不背光。两条光在入轨处按 `spaceLightK` 平滑交接——`app.js` 的 `updateLight` 同时产出 `light.sunDir` 与 `light.sunMix`，着色器再按后者收紧晨昏线、压低夜面亮度，因此发射段观感与改动前完全一致。太阳取在地月轨道面（世界 XY 平面）内、方位角 -55°（自 +X 起算），由两条现场约束反算：① 着陆点太阳高度角 ≈42°（月面有可辨投影）；② 同一时刻从着陆点看地球相位 ≈80%。**改这个方向必须回看 `tests` 里「太阳方向」那一节的两条断言。** 注意发射场位于地球「北极」（世界 +Y），该方向会把它压到晨昏线以下——这是刻意取舍，靠上升段沿用随动光规避。
