# 配图生产要求（唯一真源）

本文件是配图交付要求的**唯一真源**：`_dev/gen_image_prompts.py` 会把它整段嵌入
`_dev/IMAGE_PROMPTS.md` 的「1. 交付规格」，README 与 `assets/img/README.md` 只做指引、不重复细则。
改要求请改本文件，然后重跑 `python _dev/gen_image_prompts.py`。

## 交付清单

| 项 | 要求 |
| --- | --- |
| 存放位置 | `assets/img/`（相对项目根目录） |
| 文件命名 | `<base>.webp`，base 见逐张清单（如 `loco-03.webp`、`cover-loco.webp`） |
| 条目图尺寸 | 640 × 360（16:9 横构图） |
| 分类封面尺寸 | 960 × 540（16:9 横构图） |
| 格式 | WebP（页面另有 jpg / png 后缀回退，但 WebP 体积最优） |
| 单张体积 | 条目图 ≤ 45 KB，分类封面 ≤ 90 KB |
| 全部图片合计 | ≤ 2.0 MB（可打包 zip 的上限是 2 MB，图片是主要体积来源） |

## 画面风格：分两层（条目图 = 图鉴插画，封面 = 写实渲染）

配图刻意分两层：风格不同，底色与视角相同。

### 条目图（50 张）：图鉴式插画，不是照片

这是**有意为之的选择**，不要改写成写实渲染：

- **画法**：矢量扁平插画 + 极轻的体积渲染 + 细墨线勾边；色块干净、层次克制，
  读起来像博物馆图册、设备说明书里的插图。
- **不要**：照片质感、逆光轮廓、强烈环境反射、潮湿的金属做旧、镜面高光、
  以及任何带情绪的艺术化处理。
- **背景**：纯净的浅暖白（接近纸色）平面背景，无任何场景、地面、天空、轨道、站台、
  山脉与人影。**画面里不得出现横贯的地平线 / 轨道线**（早期版本只写「不画地面」，
  模型仍会画出一条贯穿整幅的轨枕线，现已明令禁止）；主体下方只允许一圈**极淡的接触阴影**，
  紧贴车轮或建筑基座，不向左右延伸。
- **视角统一**：车辆类一律**正侧视**；车站类一律**正立面**。同一册 54 张图视角不换，
  这是整套内容看起来像一本图鉴的前提。
- **只画一台车**：车辆类画面里只出现一台车（一台机车 / 一节头车）。动车组头车的车头
  只在画面一端，另一端是与车厢相接的平断面；调车机车（东风5型）只有一个司机室，
  车尾是平直的机械间端墙。这些约束写在 `main.js` 的 `subject` 里，改数据时不要删。

### 分类封面（4 张）：写实棚拍静物小品，一景一图，氛围优先

封面是列表页每个分组顶部的大图，要的是**氛围与质感**，因此允许、也鼓励离开插画风：

- **画法**：写实棚拍静物——可信的铸铁、黄铜、做旧木料、帆布、搪瓷、玻璃与煤的材质，
  大面积柔和棚拍光、轻微环境光遮蔽与接触阴影、允许有磕碰划痕与包浆；
  但**不要**镜面高光、不要潮湿做旧、不要戏剧化逆光或情绪化处理。
  **不要**写 diorama（模型会当成「沙盘」，自动补轨道、道砟与地面）。
- **一景一图**：每张封面是**一个完整的画面**——一组物件聚在一起，**一件主、其余靠 / 叠 / 压在前**，
  互相遮挡出前后层次，共用一片极淡的落地阴影，像一张拍出来的静物画；
  **不是**把几件道具等距排成一行「摆件目录」。主体描述（谁是谁的陪衬）在
  `main.js` 的 `COVER_SUBJECTS`，逐张见 `IMAGE_PROMPTS.md` 第 3 节。
- **画的是物件，不是车型**：动轮与连杆 / 车厢门与皮箱 / 敞车侧板与麻袋 / 站台雨棚与站台灯，
  理由见下节。
- **四张必须像一套**（系列一致性，靠这几条钉死）：同一片浅暖白底、同一光位（上方略偏前左）、
  同一正交视角（无透视）、同样的「主件 + 陪衬」结构、同样的占宽（约 75%）与高度上限（45%）、
  同样克制的暖中性色调与包浆程度。改一版就四张一起改，不要单独调某一张的布景。
- **与条目图共用同一条底线**：底色仍是同一片浅暖白无缝背景，视角一律**正交感平视（无透视）**，
  与条目图的正侧视 / 正立面是同一套底子。封面能与条目图换风格，是因为两者不同屏出现。
- **不得出现**文字、编号、路徽、logo、水印、人物与人手（与条目图同一条红线）。
  选物件时**躲开带字的东西**：站牌、车票、表盘、钟面、集装箱编号一概不选。

#### 为什么封面画物件、不画整车

三个理由，第一条是几何上的硬约束：

1. **几何**：封面显示框约 **3.44:1**（窄屏）～ **3.8:1**（宽屏），`object-fit:cover`
   只留下 16:9 源图中间约一半；而一节车正侧视约 **6:1**，四节并排要 **≈24:1** 的横带。
   整车放进封面只有两条路：被**压短成方盒子**（旧版封面即如此，车厢又短又高），或者小到看不清。
   物件没有固定长宽比，聚成一景正好吃满这条横带，比例问题从根上消失。
2. **叙事**：认型号是条目图的活（50 张都是具体型号、都对着实车照片画）；
   封面只要说清「这里是机车 / 客车 / 货车 / 车站」，不必抢条目图的活。
3. **氛围**：煤、麻袋、皮箱、铸铁灯、搪瓷缸这些物件的材质与做旧，比一台干净的整车更有年代感。

一景整体占画面宽度约 **75%**、最高一件不超过画面高度的 **45%**，正好落在可见带里，
既不被裁也不被压。

## 构图（最容易被忽略、也最影响观感）

页面用 `object-fit: cover` 裁切：

- 条目图进列表卡片：显示框约 **2.39:1**，源图**上下各丢 12.7%**
- 分类封面：显示框约 **3.44:1**（窄屏）～ **3.8:1**（宽屏），`object-fit:cover` 只留下源图
  **中间约一半的高度**（窄屏留 52%、宽屏留 47%，上下各丢约 24%～27%）

因此：

- **机车 / 车厢**：主体必须**水平居中**，且**高度不超过画面的 55%**，
  即上下各留 **≥22% 纯背景**；车钩、煤水车、排障器一概不许顶到左右边缘。
- **车站**：站房横向往往很宽，务必**整栋横向居中**，
  宽度不超过画面的 60%、高度不超过画面的 50%；不要把柱子排孤独留白。
- **分类封面**（4 张）：一景整体**垂直居中**、横向占画面宽度的 **70%～80%**，
  最高的一件不超过画面高度的 **45%**（封面上下各丢近一半，只有落在这个区带里才不会被切顶切底）。
  组景要**有主有次、有叠放遮挡**：主件居中偏左、最大，陪衬靠 / 叠 / 压在前，
  不要等距排成一行；整组共用一片极淡的落地阴影，但它**不能拉成一条横贯画面的直线**。
- 画布外沿再留 3% 安全边，避免压缩时被裁。

## 画面内容

- 每条提示词里写的是**具体型号**（本项目页面就是要展示型号），造型必须让你一眼认出这个型号：
  轮式、车体轮廓、车窗排布、涂装色带、受电弓数量这些都是识别点。
- 但画面里**不得出现**任何文字、字母、数字编号、路徽、logo、水印、旗帜与人物。
  型号只靠造型本身被认出来，不靠画面里的字。
- 封面的负面项比条目图更要写死（写实渲染尤其爱补环境）：**轨道、枕木、道砟、碎石、站台、
  地面、地板、地平线、天空、云、接触网、整车整节车厢、多余物件、人手**一项都不要，
  底色是整片浅暖白，除这一组物件与它脚下极淡的落地阴影外画面里没有别的东西。
- 不使用任何外部素材（版权风险）。

## 参考照片怎么用

`_dev/ref/<id>-01.jpg` 等是该型号的真实照片，仅作为**造型参考**：

- 对着照片核对：车体长度比、车轮对数、车顶设备的位置与数量、涂装的分界方式。
- **不要把照片的构图与背景带进画面**：绝大多数照片是斜四分之三视角、带站台与杂物，
  成品必须是干净的底色正侧视 / 正立面。
- 照片里有中式 HI-level 编号、铁路路徽、标语、护栏、接触网、相邻车厢时，一律不要画；
照片脚下的轨道、道砟与地平线同样不要带进画面。
- 每张参考图的来源页地址记录在 `_dev/ref-index.md`，仅作溯源留档（站内链接可能变动，必要时重抓）。
- **封面不指定参考照片**：封面画的是道具静物（动轮、麻袋、站台灯……），现实中本来就没有
  对应的单张照片，按文字要点生图即可；需要找材质与配色参照时，可以翻同分类的条目图
  （`assets/img/` 里的插画）当风格锚点，但**不要**把条目图的构图带过去。

## 生成后处理

若生成工具只输出 PNG / JPG，先落到 `_dev/raw_img/<base>.png`，再执行：

```bash
python _dev/process_images.py
```

该脚本会按清单里的尺寸缩放、按体积预算自动调质量，输出到 `assets/img/<base>.webp`。
