# 大航海时代 · 帆船图鉴

> **分类**：`#vibeknow` 人文知识　·　分类索引见根目录 [`TRACKS.md`](../../TRACKS.md)

一个以大航海时代（Age of Sail，约 1200–1700）为背景的帆船图鉴 app。
**组建舰队 → 起锚出港 → 舰队沿岸航行、逐艘检阅帆船 → 航海日志**，
致敬《大航海时代4》那套"跑遍七大海域、把船一艘艘买回来"的玩法。
30 艘帆船按 5 大海域家族（北海 / 地中海 / 大西洋 / 印度洋 / 东亚）组织，
也可自选舰队自由编成；舰队行进时地球组件实时标注每艘船的**建造地（船坞 / 港口城市）**。

> 本项目参照 [`jurassic-park-3d`](../jurassic-park-3d/) 的技术框架构建，
> 底层逻辑从「园区游览」改为「航海检阅」，数据从恐龙换成帆船。

## 打开方式

双击 `index.html`。资源在 `assets/`，需与 `index.html` 保持同级目录。

## 界面设计语言

全站按 16–17 世纪航海物件的语汇搭（纸 / 铜 / 木 / 绳 / 罗盘），不做深色底换配色式换皮。

- 舰队告示牌 = 钉在海图上的黄铜框木牌：对角铜包角 + 左上登记号 `LOG-01` + 右缘水印印记（预设舰队＝罗盘玫瑰，自选＝火漆印）+ 卡底虚线航迹
- 强度＝海图刻度线；徽章＝压铸小铜牌；色标＝海图航点小菱形
- 六维图谱＝画在罗盘玫瑰上：外圈双环 + 32 道分度刻线 + 盘心星芒 + 轴钉
- 底栏＝橡木仪表台，按钮＝四角铆钉的黄铜铭牌；分段标题＝一截麻绳装订线；加载＝自转罗盘
- 船档卡＝航海日志的一页：左侧黄铜装订边 + 四角铆钉；地球槽＝顶部两枚铜包角 + 题注刻度尺
- 望远镜＝圆形黄铜镜筒 + 分划十字（纯 CSS 叠层，压在放大的船图上）
- 航程进度＝顶栏底边一条计程刻度线（不占布局高度）

以上**全部是纯 CSS / 内联 SVG**，零图片零依赖，出图前后都成立。这与参考项目
「页面不画装饰」的口径不冲突：那条约束针对**主视觉图位**（徽标 / 港口两帧 / 横幅一律用 AI 出图），
这里画的是**界面构件与数据图形**。

首屏还有一层**海图兜底层**（经纬网 + 罗盘玫瑰水印）：港口图缺失时它撑住画面，
`hero-northsea.webp`（回退到 `port-docked-portrait.webp`）一落位（`html.has-hero-img`）整层自动隐藏，不会压在做好的出图上。

## 交互

### 组建舰队页（主界面）

- **版式同参考项目**：通栏 hero 固定在顶不随滚动走，舰队列表区自己滚动
- 顶部 hero：**五大海域地区风格轮播铺满** + 航海徽标图 + 文字标题，只叠一层暗化保可读；
  页面不画任何 CSS/SVG 装饰
- 图位：背景为 `hero-<family>.webp` ×5（北海 / 地中海 / 大西洋 / 印度洋 / 东亚）**地区轮播**，
  8s 一格、纯 CSS 循环交叉淡化，每层回退 ⑧ 竖版港图 → `harbor.webp`；徽标 `logo.webp`（缺图整块隐藏）
- 6 张告示牌卡片：5 支预设舰队 + 1 张「自选舰队」
- 每张有舰队名、描述、帆船数 / 海域数 / 建造国数 / 强度
- 卡片背景为舰队横幅图，缺图依次回退海图纸纹 → 主题色渐变
- 点预设舰队卡 → 进入出港页；点自选舰队卡 → 进入自选舰队页

### 自选舰队页

- **我的舰队**：按编入顺序列出，带序号、色点、海域，可 ↑ ↓ 调序、× 解除编队
- **船舶名录**：30 艘按 5 个海域家族分组，每行缩略图 + 船名 + 建造国/建造地 + 船级 + 排水量 + 火力
- 底栏：随机一队（抽 8 艘按编号排序）、清空、起锚出港
- 舰队存 localStorage（键名 `aos3d.customRoute`），下次出海还在

### 出港页（致敬航海开场）

- **两帧 AI 出图交叉淡化 + 一路推近**：① 泊在港内、帆收起（`port-docked-portrait.webp`）→
  ② 缆已解、帆张满、驶离码头（`port-sail-portrait.webp`），出港过程全在两张图里，页面不做任何 CSS 绘制
  （横版 `port-docked.webp` / `port-sail.webp` **已停用**，只留文件备用）
- 两帧**共用同一条缩放曲线与同一条缓动**（`scale 1 → 1.5`，只有 `opacity` 不同），
  交叉期间逐帧缩放完全一致 —— 读起来是舰队持续驶向远海，不会出现"一进一退"
- **只用竖版**（移动端优先）：
  `port-docked-portrait.webp` / `port-sail-portrait.webp` 置于背景层首位，
  横屏按 cover 铺满、只裁上下；缺图 404 自动落 harbor 兜底
- 约 7.1s 后切进航海页；字幕依次淡入：欢迎登船（1.1s）→ "Age of Sail · 大航海时代"（1.6s）
  → 舰队名（2.1s），**在屏上停留约 5s** 才随整场一起淡出（6.2s 起）
- 图层用 `contain` + **两帧模糊铺底**：舞台铺满视口、不限宽，横屏桌面不会出现"竖槽里塞一张横图"
  （两侧黑边 + 上下两截虚化带）；主图永不裁掉船首尾，信箱边由**同图的两帧各铺一层**填满，
  且与主图共用同一条透明度曲线 —— 第二帧主图换成"扬帆离港"时虚化带同步换帧，不会两张图拼在一起
- **`harbor.webp` 兜底层只在竖版缺失时生效**：`app.js` 预检两张竖版都到位后给 `<html>` 挂
  `has-depart-portrait`，挂上即撤掉 crisp 层的兜底层。原因是竖版主图用 `contain`，
  在「竖屏但宽高比 > 1:2」的视口（平板 / 9:16 手机 / 拖窄的桌面窗口）里按高度撑满后左右留空档，
  而 16:9 的 harbor 是满宽的 —— 不撤掉就会从空档里露出一张横图，看着像两张图拼在一起
- 两帧须同机位同光位；缺图时都回退到 `harbor.webp`

### 航海页（舰队检阅）

- 顶栏只留一行：舰队名 · 海域 · 第 X / N 艘
- 地球定位组件嵌在顶栏下方：标出舰队里全部帆船的**建造地**，
  当前这艘高亮脉动，其余舰队成员压暗作上下文，标签只保留当前一处
- 帆船图做成**海图图鉴画面**：羊皮纸暖色调 + 暖色纸边暗角（不叠网格条纹），
  角上是 `图鉴 NO.0X · 船级`、`AD 年代` 与 `排水量` —— **默认常开，不设开关**
- 左下角「望远镜」：船图放大 2.6 倍（滚轮 1.8–3.6 倍微调）+ 拖动平移，
  罩一圈黄铜镜筒与分划十字看船体细节；Esc / 再点一次收起，换船时镜筒自动归中
- 地球槽右上角两枚圆形图标按钮：左＝**分享这艘船**（把该船原图直发笔记，见 §笔记分享；
  只在容器注入了端能力、且这艘船的原图确实加载成功时出现），右＝背景音乐开关
- 画面是**正方形**（帆船图本身就是 1:1 方图），边长 `24vh`、**宽高同值**、限幅 `88–190px`：
  方图正好填满方框，屏幕矮时整块等比变小，**绝不裁掉桅顶与龙骨**；
  `background-size` 一律用 `contain` 兜底
- **地球高度固定 `--globem:218`，不为任何页面让步**；「一屏不翻页」由
  **画面边长可压缩**（`24vh`，flex 让位）+ 卡片紧凑化保证
- 图片下是一张**船档卡**（最大宽 540px），卡内文字**一律左对齐**、信息分层：
  - 卡头：船名（左）+ 船级徽章（右，`小型船 / 中型船 / 大型船`）
  - 次行：左「海域 · 建造国 · 建造地」、右「排水量 X 吨 ｜ 火力 X/5」
  - 介绍（限 3 行）→ 末行：特征胶囊 `traits` + 类别标签 `tags`（同排）
- 底栏只留三枚按钮：上一艘 / 下一艘 / 结束航程；最后一艘时「下一艘」变为「航海日志」

### 航海日志（总结页）

- 舰队名 + 帆船数 / 海域数 / 建造国数
- **一句自然简报**：本次检阅几艘、满载排水量合计多少吨、最大与最小分别是谁、造在哪儿
- **六维性能图谱**（载重/火力/航速/耐久/机动/稀有，本次均值，峰值维度标红）
- 舰队名册：每艘一行（色点 · 船名 · 建造国/建造地/年代 · 该艘最突出的两维）
- 底栏：再航一次 / 分享（容器注入了端能力才出现，见 §笔记分享）/ 返回组建舰队

### 地球组件

- 拖动地球可转动、滚轮/双指缩放
- 换船时相机沿球面**平滑滑行**到新的建造地：按两点角距离定时长（0.7–2.6s）、取最短角路径、
  easeInOutCubic 整段滑完（**不做左右摆头**；手一按即让位给拖动），标记点始终留在视野中央
- 仅在航海页显示（CSS `body.mode-voyage .globe-slot{display:block}`）

## 数据

- 内置 **30 艘帆船**，覆盖 **5 大海域家族**、**15 个建造国**
- 数据文件：`assets/ships.js`，每条记录字段：
  `name / cls / country / yard / lat / lon / family / year / intro / traits / tags / stats / tons / color / img`
- `stats` 为六维性能分值 `[载重, 火力, 航速, 耐久, 机动, 稀有]`，各 0–5 整数，
  口径为该船型的**典型配置**（非历史个别改装船），供航海日志的性能图谱使用。
  **六维顺序不可变**（`app.js` 的 `STATS_DIMS` 与之一一对应）
- `tons` 为满载排水量估算值（吨），供航海日志的简报使用
- `cls` 取 `small / medium / large`，对应《大航海时代4》的小型船 / 中型船 / 大型船
- 离线零依赖：`img` 缺失或加载失败时，用该条记录的 `color` 色卡代替帆船图

## 背景音乐

右上角一枚黄铜小牌（固定位，不占布局），**默认开启**。

| 项 | 说明 |
|------|------|
| 音频数据 | `assets/audio/bgm.js` —— `window.AOS3D_BGM` = base64 字符串，由 [`tools/make-bgm.mjs`](tools/make-bgm.mjs) 从源曲目 `assets/audio/bgm.mp3` 生成（源文件是构建输入，**不打进 zip**） |
| 当前曲目 | 源 158.1s · MPEG-2 Layer III · 22.05kHz · 80kbps CBR · 无 ID3 标签；实际播前 **101.15s**（音频 988KB = 0.96MiB，压在 base64 门禁内）· **版权来源待自证** |
| 播放方式 | `atob → ArrayBuffer → AudioContext.decodeAudioData()` → `AudioBufferSourceNode` + `GainNode` 包络；**全程不产生任何 URL** |
| 循环 | 循环体是曲子内部**一段 60 小节的完整乐句**（`BGM_A` 19.54s → `BGM_B` 97.56s），与下一遍**交叠 1.300s（整 1 小节）交叉淡化**。这两处波形相关 0.554、最佳时移仅 −1ms —— 本来就是同一段音乐的重复；而把整段首尾相接只有 0.730 / 波形 0.069，那正是"接缝上撞出强拍"的来源 |
| 起播 | **用户第一次点按之后**才出声（容器 autoplay 策略要求手势），之后全程循环 |
| 开关外观 | 右上角**一枚圆形纯图标按钮**（34×34，无文字，只有 `aria-label="背景音乐"`）：未出声＝暗色圆 + 黄铜斜杠音符；正在出声＝亮铜色实心圆 + 深墨音符。两枚图标是内联 SVG，随 `.on` 换显，不依赖图片 |
| 显示口径 | 按钮画的是**此刻有没有在响**，不是"用户想不想听"：首屏必然还没出声（autoplay 策略要手势），所以首屏是未播放态，起播那一刻才亮起来。偏好另存 `localStorage`（键 `aos3d.bgm`），只管"用户第一次点按之后要不要自动出声" |
| 安装位置 | 落在地球槽的**右上角那一带**、顶栏之下：`top:calc(var(--topbar) + var(--sattop) + var(--bgmgap))`，`--bgmgap` 默认 `16px`（正好避开地球槽右上角那枚 15px 黄铜包角）—— 要挪位置就改这一个数。**顶栏不再为它留右侧空白**，标题始终居中 |
| 降级 | 没有数据 / 没有 `AudioContext` / 解码失败 → `<html>` 不挂 `has-bgm`，开关整块隐藏，五页流程照常 |
| 切后台 | `visibilitychange` 停声并挂起音频上下文，回前台的续上 |

**为什么不直接放一个 mp3 在包里**：容器**上传白名单只有** `jpg / css / gif / svg / png / js /
jpeg / json / html / woff2 / webp / woff` —— **没有任何音频扩展名**（`bgm.mp3` 会被上传页直接打回）；
而容器 CSP 又明确「音视频 `<video>` / `<audio>` 只允许包内媒体文件，禁外部域名与 `data:` / `blob:`
媒体源」。两条叠加＝**「包内音频文件」这条路在容器里不存在**，所以音频只能以 base64 藏在白名单类型
（`.js`）里，运行时交给 Web Audio —— 不产生 URL，因此不触碰 CSP 的资源加载规则。
`performance-budget.md` 另要求**单条 Base64 解码后 ≤ 1MiB**，故默认裁到 101.15s；
**帧级裁剪不重编码**，保留段与源文件逐字节一致。

> 演示模式（`?demo`）不显示音乐开关；且演示全程无用户手势，BGM 也不会自动起播 ——
> 宣传片里的配乐请在后期混音时加（见 `xiaohongshu/` 与 `tools/xhs-video/`）。

## 笔记分享

容器里没有名为「分享」的 API，只有 §3.3 的 **POSTNOTE**（唤起 App 的笔记发布页并带上内容与媒体；
`mediaInfo` 必填，且图片 / 视频 / 实况三种资源至少传一种）。两处入口：

| 入口 | 位置 | 媒体 | 笔记正文 |
|------|------|------|----------|
| **分享这艘船** | 航海页右上角（地球槽右上角、音乐开关左侧的圆形图标） | **该船的原图原文件**（`assets/ships/*.webp`，逐字节，不重绘） | 该船的科普介绍 + 一段紧凑资料 |
| **分享舰队** | 航海日志页底栏中间 | Canvas 现画的日志卡片 | 航程简报 + 一行统计 |

### 详情页分享（船的原图）

```
XHR ./assets/ships/<slug>.webp → FileReader.readAsDataURL → data:image/webp;base64,…
  → writeTempFile({ data }) 换成本地 filePath → postNote({ pageType:'photo_publish', … })
```

| 项 | 说明 |
|------|------|
| 为什么不用 canvas | `drawImage` 在 `file://` 来源下会把画布标记成被污染、`toDataURL` 抛 `SecurityError`；而且重绘等于重编码，分享出去的就不是原图了。XHR + FileReader 拿到的是**逐字节原图**，格式仍是 webp |
| 显隐条件 | 只在航海页、**且该船原图确实加载成功**（复用航海页大图那份 `IMG_OK` 预检，不另开探测）、且容器注入了端能力时才出现。没图就不给按钮，与「缺图回退色卡」同一口径，不做占位分享 |
| 标题 | `船名 · 建造国`（限 20 字） |
| 正文 | 该船 `intro`（科普介绍）+「建造国·建造地·年代 / 排水量·船级 / 六维 / 特征」，截到 1000 字内 |
| 换船刷新 | 每次 `showVoyageShip()` 与船图加载回调都会重算显隐，逐艘船各自判断 |

### 舰队分享（日志卡片）

航海日志页底栏中间那枚「分享」把这一趟航海日志画成一张 **1080×1440 的卡片**，
**版式与配色照航海日志页本身复刻**（Canvas 2D，全部是图元与文字，不用任何图片），
分享图和 app 里看到的日志页是同一套语言：

| 区块 | 内容 |
|------|------|
| 底子 | 深海底径向渐变（与 `.page-log` 同一道：`--sea-6 → --sea-8 → --sea-9`） |
| 上下栏 | 两条橡木仪表台（`.log-bar` / `.log-controls` 同款）：顶端居中「航海日志」，底端落款 |
| 标题区 | 「航程完毕」+「本次检阅 **N** 艘帆船 · 覆盖 **M** 个海域 **K** 个建造国」（数字酒红加粗） |
| 简报 | 复用日志页那句自然简报（`.log-brief` 的居中窄栏版式） |
| 性能图谱 | **画在罗盘玫瑰上的六维图谱**：黄铜双环 + 32 道分度 + 五圈多边形网格 + 酒红数据面 + 盘心轴钉；维度名与值分色，峰值维标红 |
| 舰队名册 | 船色菱形色点 + 船名 + 建造国·建造地·年代 + 该艘最突出的两维，逐行虚线分隔（`.sum-ship` 同款） |
| 分隔 | 每个分段标题右侧一截**麻绳**（`.sec::after` 那根斜向绳股） |

> 上一版那两条**年代坐标轴已去掉** —— 日志页本身没有这一段，为「照页面复刻」保持一致。
> 想把时间维加回来（同样的酒红 + 黄铜语言）说一声即可。

再按容器文档 §3.3 的 **POSTNOTE** 唤起 App 的笔记发布页：

```
Canvas → toDataURL('image/jpeg',0.92)   1080×1440 · 实测 ≈320KB（PNG 压不动，要 2.4MB）
       → writeTempFile({ data })   换成本地 filePath        §3.5：大 base64 先落文件再传
       → postNote({ pageType:'photo_publish', mediaInfo:{ image_resources:[{ url: filePath }] } })
```

| 项 | 说明 |
|------|------|
| 显形条件 | **能力检测**：拿不到 `window.xhs.miniTool.postNote` 就整块隐藏（桌面直接打开 `index.html`、`?demo` 录屏都不会出现），不做 UA 判断 |
| 降级 | 客户端没有 `writeTempFile` 时，把完整 `data:uri` 直接交给 `postNote`（§3.3 允许 base64） |
| 入参 | `title` ≤20 字（`大航海时代 · <舰队名>`）；`content` ≤1000 字（自然简报 + 一行统计）；`mediaInfo` **必填且至少一种资源** —— 文档的硬要求，所以必须先出图 |
| 卡片不画图片 | 卡片**只用 Canvas 图元与文字，不 `drawImage` 任何图鉴 webp**：`file://` 来源下画本地图片会把画布标记为被污染，`toDataURL` 会直接抛 `SecurityError` |
| 结果语义 | `postNote` 成功**只代表发布页被唤起并由用户点了发布，不代表过审** —— 只当"已唤起"提示，不据此改任何业务状态 |

> 容器里没有名为「分享」的 API，只有 §3.3 的 POSTNOTE（发布笔记）；用户在发布页仍可继续编辑或取消。
> `postNote` 的完整字段表以容器文档与 `.skill/minitool-zip-builder/references/jsbridge-api.md` 为准，
> 未声明的字段一律不传。

## 兼容性（Chrome 61 回退层）

最低基线是 **Android 8.1 出场 Chrome / WebView 61**。做法是「基线层 + 能力检测后的增强层」，
不为旧内核另起一套页面：

| 能力 | 基线（Chrome 61 可用） | 增强（检测后启用） |
|------|----------------------|------------------|
| Flex `gap` | 子项 `margin-left` | `.supports-flex-gap` 下换 `gap` 并清 margin |
| `clamp()` | `--hero-h` 固定值 + 按视口高的媒体查询分档 | 不引入 |
| `env(safe-area-inset-*)` | `--sat / --sattop / --sab` 在 **`body`** 上算（容器把 `--safe-area-inset-*` 注入在 `html` 还是 `body` 都认 —— 只写在 `:root` 上算一次的话，注入在 `body` 时会取不到而静默退成 0）。无注入则 `0 / 8px / 0` | `@supports` 块里退成 `var(--safe-area-inset-*, env(safe-area-inset-*, 0px))` —— 认注入变量、真机认 `env()` |
| `:focus` | `:focus` 描边基线 | 不用 `:focus-visible` |
| WebGL 3D | 地球槽内挂 `.globe-down`，组建舰队/出港/航海/日志照常 | 完整地球 |
| `localStorage` | `try/catch` 包住，读写失败则自选舰队只活在本次会话 | 自选舰队跨会话保留 |
| 出港切换 | 两张图 `opacity` + `transform:scale` 交叉淡化，Chrome 61 原生可用 | 不引入 |
| 多行截断 | 介绍文字用 `-webkit-line-clamp`（Chrome 61 支持）限行 | 不引入 |
| 背景音乐 | `AudioContext` + `decodeAudioData` + `GainNode` 包络（Chrome 61 原生）；手势后才起播 | 没有 `AudioContext` / 解码失败则开关隐藏，不引入第三方音频库 |
| 笔记分享 | 能力检测 `window.xhs.miniTool.postNote`，没有就隐藏按钮；`writeTempFile` 缺失时直接传 `data:uri` | 不引入任何第三方 SDK |
| 船图转 base64 | `XMLHttpRequest`（`responseType:'blob'`）+ `FileReader.readAsDataURL`，拿到逐字节原图 | 不走 `canvas.drawImage` + `toDataURL` —— 既避免 `file://` 下画布被污染，也避免重编码 |

**3D 不可用不再是全屏报错**：地球只是标建造地的组件，它挂了就只在槽内降级，
底下的组建舰队、自选舰队、出港动画、航海检阅、航海日志一条不少。

## 打包

```bash
node tools/analyze-bgm.mjs assets/audio/bgm.mp3 --data-end 101.15  # 换曲目：先找循环乐句
node tools/make-bgm.mjs            # 生成 assets/audio/bgm.js（裁帧 + base64 + 门禁核对）
node pack.mjs                      # 产出 age-of-sail-3d.zip（zip 根即 index.html）
```

`--data-end 101.15` 是本项目特有的一步：音频只打前 101.15s 进包，
不告诉工具就会推荐一段**根本播不到**的乐句。工具会给出可直接粘贴的 `BGM_A / BGM_B / BGM_X`。

## 演示模式（录屏用）

- `index.html?demo` —— 自动播一遍「商船舰队」全流程
- `index.html?demo=warship` —— 指定舰队（`merchant` / `warship` / `explorer` / `lineage` / `east`）
- `index.html?demo&loop` —— 播完回到组建舰队页循环重播
- `index.html?demo&warm=3` —— 演示前静置 3 秒（软件渲染下给地球组件预热）

演示模式纯播放、不弹提示、不接受键盘。

## 与 jurassic-park-3d 的关系

复用其：五页结构、地球定位组件（`ll2v` 经纬→球面、相机手势、标记点显隐与脉动）、
Chrome 61 兼容层、零依赖离线单文件形态、缺图回退与演示模式。

改造点：

| jurassic-park-3d | age-of-sail-3d |
|------------------|----------------|
| 地质年代 `era`（古生代…新生代） | 海域家族 `family`（北海 / 地中海 / 大西洋 / 印度洋 / 东亚） |
| 化石发现地（恐龙） | 建造地「船坞 / 港口城市」（帆船） |
| 六维 [体型,威胁,速度,智力,防御,稀有] | 六维 [载重,火力,航速,耐久,机动,稀有] |
| `length` 体长（米） | `tons` 满载排水量（吨） |
| 园区监控画面（绿灰调 + REC + 时间码） | 海图图鉴画面（羊皮纸暖调 + 编号/年代/排水量） |
| 经典大门两帧（关闭 → 敞开） | 港口两帧（帆收起泊港 → 帆张满离港） |
| PADDOCK 围栏编号徽章 | 船级徽章（小型船 / 中型船 / 大型船） |
| 巡逻路线 ×4 + 自选 | 舰队 ×5（商船 / 战舰 / 探险 / 巡礼 / 东方）+ 自选舰队 |

## 分类判定

没有任务、没有输赢，用户点开是为了"组建一支舰队，跟着它把一整个时代的帆船看一遍，
知道每种船造在哪儿、强在哪"，看完脑子里多一份对船舶史与地理的认知 → `#vibeknow`。
地球是标注建造地的组件，3D 是手段而非目的，故不归 `#vibeart`。
