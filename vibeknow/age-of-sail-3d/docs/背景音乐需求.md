# 背景音乐需求 · `assets/audio/`

> **重要前提**：容器**上传白名单不含任何音频扩展名**（只有 `jpg / css / gif / svg / png / js /
> jpeg / json / html / woff2 / webp / woff`），`mp3` 会被上传页直接打回；而容器 CSP 又明确
> 「音视频 `<video>` / `<audio>` 只允许包内媒体文件，禁外部域名与 `data:` / `blob:` 媒体源」。
> 两条叠加＝**「包内音频文件」在容器里没有立足之地**。文档中「音视频播放 支持内联播放」那句，
> 实际只对用户自己选中的媒体 / 内存对象有意义。
>
> 因此本项目改用：**音频以 base64 藏在 `.js` 里 → 运行时用 Web Audio 解码播放**
> （全程不产生 URL，不触碰 CSP 的资源加载规则）。落地步骤见 §5，产物由
> [`tools/make-bgm.mjs`](../tools/make-bgm.mjs) 生成。

## 1. 它是干什么用的

全程铺底的循环 BGM，从「组建舰队页」用户第一次点按起播，一直循环到「航海日志页」，
中间穿过出港的 7.1s 起锚动画。它是**背景**，不是演出：图鉴要读文字、要转地球，
音乐只负责把「16 世纪港口」的气口撑住，不能抢注意力。

| 裁剪点 | 101.15s —— 由解码后的 RMS 包络挑出「窗口内能量最低且左右半窗最平」的一点（落差 0.2）。**这只是包体门禁的代价，不是循环点** |
| 循环乐句 | **19.54s → 97.56s（78.02s，60 小节）**：184.6 BPM / 4/4（小节 1.300s，置信度 3.0），两端都落在小节线上、相差整 60 小节；织体相似度 **0.991**，**波形互相关 0.554 且最佳时移仅 −1ms** —— 这两处本来就是同一段音乐的重复，交叠时两遍同相，接缝几乎听不出来。由 `tools/analyze-bgm.mjs` 选出（对照：把整段首尾相接只有 0.730 / 波形 0.069，那正是"接缝上撞出强拍"的来源） |
| 循环 | 每遍播 `[BGM_A, BGM_B]` 这一段乐句，与下一遍**交叠 1.300s（＝整 1 小节）**线性交叉淡化，增益和恒为 1 |
| 实测 | 无头 Chromium：`decodeAudioData` 成功（48kHz / 158.12s 源→裁后 101.15s）、手势起播、
静音/恢复、交叠排程 `set 0@0.08 / ramp 1@2.68 / set 1@98.63 / ramp 0@101.23`（L=D−X ✅） |

## 3. 硬约束（技术）

| 项 | 要求 | 原因 |
|------|------|------|
| 源文件 | `assets/audio/bgm.mp3`（替换曲目就换它，**保持文件名**） | `tools/make-bgm.mjs` 的输入路径写死了 |
| 源格式 | **mp3**（MPEG-1/2 Layer III，44.1kHz 或 22.05kHz） | 解码走 `decodeAudioData`，mp3 兼容面最广 |
| 产物 | `assets/audio/bgm.js`，**必须由 `tools/make-bgm.mjs` 生成**，不要手改 | 里面是 base64 大字符串 |
| 单条 Base64 解码后 | **≤ 1 MiB**（硬红线，见 `performance-budget.md` §1） | 超过即"大 Base64"，常规补救"改成独立包内文件"在容器里不存在 |
| 单个 `.js` | ≤ 2 MiB（超了会触发风险提示） | 大源码增加解析与峰值内存 |
| 时长 | 60–120 秒为宜；受上一条约束，**码率越低能留的时间越长** | 80kbps × 101s ≈ 988KB 就是当前这档 |
| 采样率 | 44.1kHz 优先；22.05kHz 能播但带宽仅约 11kHz，音色偏闷 | 越低越省体积，代价是高频发闷 |
| 循环 | 先按小节线切出一段**完整乐句**，再在乐句首尾做交叠淡化 | 直接 `loop` 整段会在接缝处跳变 |
| 音源 | 只能是包内文件（经 base64 内嵌） | 容器不联网 |

**体积换算**：`80kbps × 101s ≈ 988KB`（当前档）；`128kbps × 90s ≈ 1.4MB`（超红线，不可用）；
`64kbps × 120s ≈ 960KB`（可行，音质略逊）。一句话：**这个容器里"能听多久"由码率说了算**。

## 4. 音乐性要求（听感）

- **情绪**：航海 / 古乐 / 凯尔特 / 文艺复兴管弦 / 环境铺底。要「海图与罗盘」的时间感，
  不要电子鼓点、不要现代流行编曲、不要紧张追逐感（要的是检阅与远航，不是海战突袭）。
- **配器参考**：维奥尔琴、鲁特琴、竖笛、风笛、手鼓、中提琴低音持续音、弦乐弱奏、
  远处的人声哼鸣（**只作音色，不成词**）。
- **动态要平**：整曲响度起伏要小（当前这条曲子中位数约 -15dB、四分位区间只差 3 步，
  属于典型的"平"）。动态太大的曲子，每循环一圈就会"喘"一下，交叠淡化也救不回来。
- **不要人声唱词**：有歌词会和中文阅读抢注意力；占位感的无词哼鸣可以。
- **不要明显的主旋律钩子**：图鉴页停留时间长，洗脑循环容易烦。
- **首尾不要淡入淡出**：交叠淡化要求两端都是"满电平的连续音乐"，端点有长淡出会叠出一段空档。

## 5. 版权（上线前的硬门槛）

- ✅ 免版税 / CC0 / 已购买商用授权的音乐库曲目（Artlist、Epidemic Sound、Pixabay、
  Freesound 的 CC0 素材、Musopen 的公版古典乐录音等）
- ✅ 自己用 AI 音乐工具生成并确认**持有商用权**的曲目（Suno / Udio / Stable Audio 等，
  注意各平台免费档常不含商用授权）
- ❌ 流行歌曲、影视配乐、游戏原声 —— 哪怕是片段或变速处理
- ❌ 来源不明、只写「网络收集」的音频

⚠️ 公版**作曲**（如 16 世纪古乐谱）不等于公版**录音**：现代演奏版本仍有录音版权，
必须用明确标注可商用 / 公版的录音。

## 6. 落地步骤

```bash
# 1. 把源曲目放到 assets/audio/bgm.mp3（替换曲目就换它）
# 2. 生成运行时产物（脚本会打印门禁核对表）
node tools/make-bgm.mjs
# 3. 双击 index.html 打开，点一下任意位置（autoplay 策略要求用户手势）听效果
#    地球槽右上角出现一枚圆形音乐按钮（斜杠音符）即为识别成功；
#    起播后它会变成亮起的铜色圆（音符），点一下能停声、再点能恢复
# 4. 打包，确认 zip 不含 bgm.mp3、含 bgm.js 且总包 ≤ 10 MiB
node pack.mjs
```

裁剪点想换：先看 RMS 包络再定 —— 用 headless Chromium 解码后按 ~10ms 一窗算 dB 包络，
在「目标时长附近」挑**窗口内平均能量最低且左右半窗落差最小**的一点，把它换算成
MPEG 帧序号（帧长 576/22050 ≈ 26.1ms），再 `node tools/make-bgm.mjs --frames <帧号>`。

**循环乐句想换**（`BGM_A` / `BGM_B`）：直接用 `tools/analyze-bgm.mjs`（上面那些判据就是它实现的）：

```bash
npm --prefix tools i mpg123-decoder          # 只需一次
node tools/analyze-bgm.mjs assets/audio/bgm.mp3 --data-end 101.15 --top 10
```

`--data-end 101.15` 是本项目特有的一步：音频只打前 101.15s 进包，
不告诉工具就会推荐一段**根本播不到**的乐句。工具会打印候选表 + 可直接粘贴的
`BGM_A / BGM_B / BGM_X`（末尾还会提示码率上限与 1 MiB 门禁余量）。

- ✅ `bgm.js` 生成合规：base64 解码后 0.96 MiB ≤ 1 MiB、`.js` 1.29 MB ≤ 2 MiB
- ✅ `atob → ArrayBuffer → decodeAudioData` 成功，`html.has-bgm` 挂上、开关显形
- ✅ 手势之前**不出声**（`sources=0`）；`pointerdown` 之后起播（`sources=1 starts=1`）

## 8. 常见坑

| 现象 | 原因 | 处理 |
|------|------|------|
| 上传页报「包含不支持的文件类型：xxx.mp3」 | 白名单不收音频扩展名 | 把音频源排除出 zip、改用 `bgm.js`（见 §1 / §6） |
| 打开页面没有声音 | autoplay 策略：还没发生用户手势 | 点一下屏幕即可，属预期行为 |
| 开关不出现 | `bgm.js` 没加载 / `window.AOS3D_BGM` 为空 / `decodeAudioData` 失败 | 核对 `bgm.js` 在 `app.js` 之前引入；看控制台报错 |
| 开关挤在顶栏里、把标题拱偏 | 开关与顶栏同一行，顶栏就只能为它留右侧空白，居中的标题被推歪 | 开关已移到**地球槽右上角那一带**，顶栏不留白、标题始终居中；要微调高度改 `index.html` 里的 `--bgmgap`（默认 `16px`） |
| 顶栏被状态栏压住 / 安全区算成 0 | 容器把 `--safe-area-inset-*` 注入在 `body`，而安全区只在 `:root` 上算过一次（自定义属性只向下继承，取不到） | `--sat / --sattop / --sab` 已在 `body` 上再声明一次，两种注入层级都认 |
| 开关明明没在响却显示成"已开启" | 显示口径写成了"用户偏好"而不是"实际播放状态" | 显示只认 `bgmPlaying`（见 `app.js` 的 `bgmPaint`），偏好只存在 `localStorage` 里 |
| 循环处「咔」一下 / 冒出个强拍 | 循环体取成了整段音频 —— 曲头接曲尾＝两段不相干的音乐叠在一起，重拍互相撞 | 改成曲子内部的**整小节乐句**：调 `app.js` 的 `BGM_A` / `BGM_B`，交叠长度取整小节（`BGM_X`） |
| 上传报包体超限 | 音频裁得太少 / 码率太高 | 降到 64kbps，或改小 `--frames` |
| 播放时有明显卡顿 | base64 解码 + 首次解码占了主线程 | 解码已安排在首屏之后（`app.js` 里 `setTimeout(bgmDecode,900)`）；更长的曲子要相应放低码率 |
| 部署后仍播旧曲子 | 浏览器缓存 | 强刷（本项目不做版本号） |
