# 拼豆城市 · perler-city

把**拼豆**的「一颗一颗填满钉板」和**模拟城市**的「RCI 供需、水电垃圾、人口涨跌」缝在一起：
每栋楼都是一张拼豆图纸，**第一次盖必须亲手拼出来**，拼满自动熨烫成片、落进城里；
之后这栋楼就算「已掌握」，花金币可以直接盖。

盖完之后才是真正的游戏：**住宅 / 商业 / 工业**三条需求互相拉扯，
**电力 / 供水 / 环卫**三条管网随时可能爆掉——停水停电人会搬走，垃圾积压会拖垮整座城的幸福。

- 参赛：小红书 vibecoding 大赛 · **#vibegame** 互动游戏赛道
- 形态：纯前端、零依赖、零构建，浏览器直接打开即玩，移动端优先
- 产物：`index.html` + `main.js`（可压缩成小红书小工具 zip，约 20 KB）

## 玩法速览

| 系统 | 一句话 |
|------|--------|
| HUD | 顶栏三段统计铭牌（金币 / 人口 / 幸福），金色强一致 |
| 建造 | 6×6 网格，首栋必须拼豆（蓝图页 → 拼豆台 → 落城），之后可花金币直接盖 |
| 操作 | 底部 dock 4 个：蓝图 / 市政 / 数据 / 玩法；建造 / 拼豆 / 解锁都收口在蓝图底部 CTA |
| 人口 | 向 `min(住房容量, 岗位+6)` 收敛；停水停电会流失 |
| 电力 / 供水 | 满足率 < 1 → 收益打折 + 幸福扣减 + 人口停止迁入 |
| 环卫 | 运力不足 → 垃圾积压，持续扣幸福，需补建回收中心 |
| RCI | 顶栏三色需求条，告诉你下一栋该盖什么 |
| 幸福 | 总闸门，通过 `0.6 + 幸福/100×0.8` 系数乘在总收益上 |
| 浮层 | 蓝图（草图纸主卡 + 缩略图条 + 底部 dock CTA）/ 市政（4 类市政余量）/ 数据（幸福环 + 收入堆叠 + 构成条）/ 玩法（6 节图鉴） |
| 重置 | 数据页底栏「重置城市」，二次确认后清档重开（金币 / 建筑 / 人口 / 已掌握图纸全部归零） |
| 音效 | Web Audio 实时合成，零音频文件；HUD 最右一枚喇叭开关，偏好独立存档（重置城市不会连它一起清） |

完整数值见 [`设定文档.md`](设定文档.md)。

## 图纸设计原则

15 张图纸由 `_dev/redraw.py` 校验生成（不是手敲），每张都遵守四条硬约束：
1. **剪影优先**：顶部留白形成天际线，不塞满棋盘
2. **一物一符号**：每张有独一无二的视觉锤（人字坡 / Y 形叶片 / 收腰冷却塔 / 红白灯塔 / 回收三角 / 钟楼 …）
3. **底部地面线**：末行必须非空，保证放进 6×6 网格时所有建筑底部对齐
4. **左右对称**（`workshop` 是有意不对称的唯一例外）

新增图纸时改 `_dev/data/buildings.json`（直接编辑 rows），然后跑 `python _dev/redraw.py` 自动校验（方阵 / 对称 / 色号 / 末行地面线 / 填充量 45–125）。

## 蓝图页（第七轮）

- 顶栏「推荐 / 全部 / 住宅 / 商业 / 工业 / 电力 / 水利 / 环卫 / 民生」9 个标签
- **默认选中「推荐」**——根据当前供需缺口与 RCI 需求，自动挑出最该盖的类别
- 主卡：草图纸底纹（CSS 渐变网格）+ 图章号 `BLUEPRINT · NO.X` + 类别色点 + 描述 + 关键属性两列（最多 6 行：造价 / 住房 / 岗位 / 收益 / 幸福 / 耗电 / 耗水 / 垃圾 / 发电 / 供水 / 清运）
- 缩略图条：横向 `flex-wrap` 排布，每张带「已掌握 ✓ / 拼豆数 / 缺 N 人口」角标；点击切换主卡
- **底部 dock** 才是主操作：CTA 随状态变——「尚未解锁」(灰) / 「去拼豆台」(蓝) / 「金币不足」(灰) / 「直接建造」(金)。所有建造动作都收口在底部一行，不再每张卡都塞按钮
- 未解锁建筑主卡降到 0.5 透明度，已掌握卡描金色边框

> ⚠️ **筛选条用 `flex-wrap: wrap` 换行，不要改成 `overflow-x: auto` 横向滚动。**
> 小红书宿主的 WebView 会吞掉横向滑动手势（或与浮层纵向滚动冲突），超出屏宽的类别会**物理上点不到**。
> 在小程序/宿主 WebView 里，横向滚动条一律不可信——能用换行、折叠或分页就别用横滑。

## 数据页（第七轮）

全屏浮层，五段信息自上而下：

1. **城市概况**：当前称号（金色渐变大字）· 人口/容量/建筑 · 收入/分（带符号）
2. **幸福环**：120×120 SVG 双层环——背景灰圈 + 前景彩弧（≥60 绿、≥40 琥珀、<40 红），中心大数字 · 100
3. **收入构成**：堆叠条 + 类别色小方块图例（市政保底 / 人口税 / 产业收益）
4. **市政负荷**：电 / 水 / 环卫 / 积压 四行，每行 `N/M · 余 X 度/吨/车`，进度条用各自类目色（黄/蓝/紫/红）
5. **下一张图纸**：当前推荐类目下第一张可建造的卡（缩略图 + 名称 + 「还差 N 人口」进度）
6. **建筑构成**：堆叠条 + 7 类色点图例

底栏左侧是动态诊断 note，右侧依次是**重置城市**（幽灵样式）与**关闭**。

> ⚠️ **重置必须二次确认，且不要做删档入口的快捷键。**
> 存档是强制单槽的（`pcity_v2`），没有多存档位，误触一次就是不可逆的清档。
> `resetGame()` 里必须先 `clearTimeout(saveTimer)` 再 `removeItem`——
> 上一次操作排的 `save()` 还压在 400ms 防抖队列里，不清掉的话旧存档会在清档后原样写回来。

## 音效与 BGM（第十一轮）

**全部用 Web Audio 实时合成，项目里没有、也不会有音频文件。** 这不是洁癖，是被硬约束逼出来的：
本工具要求零外部资源、零 CDN，zip 要压在 2MB 内，而一段够听的 base64 循环就得上百 KB。
合成还白拿一个好处 —— 音高能跟着游戏状态走。

### BGM：D 大调 I–vi–IV–V，四小节一循环（约 13 秒）

| 层 | 内容 |
|---|---|
| 低音 | 每小节一个长音，正弦，慢起慢落 |
| 铺底 | 三音和弦，三角波，attack 0.7s —— 做成「垫子」而不是「音符」 |
| 琶音 | 只落在四分音符上，正弦短衰减，八音盒质感 |
| 点缀 | 第 2、4 小节弱拍一颗高音，避免四小节听起来一模一样 |

走「稀疏」路线是刻意的：注意力应该在拼豆上，音乐只负责填满留白，不负责抓耳朵。

### 音效

| 触发 | 音色 |
|---|---|
| 放豆 | 三角波短促下滑 + 一点噪声击打，**音高随完成度升**（0%→520Hz，100%→980Hz） |
| 橡皮 / 清空 | 更低更闷的下行 + 噪声 |
| 拼满 100% | D 大三和弦上行琶音 |
| 熨烫 | 由低到高的嘶声（带通噪声扫频）+ 下方暖和弦 |
| 落成 | 比「拼满」更宽更低的和弦 |
| 拆除 | 碎裂噪声 + 0.3 秒后一记金币声 |
| 告警（缺电/缺水/垃圾） | 两声下行，中低音区，能打断手上动作但不刺耳 |
| 浮层开 / 关 | 一上行、一下行，音量压得很低 |

音色分工：三角波偏木/塑料，正弦偏铃/水，方波只在金币这类需要一点金属摩擦的地方用，且音量最低。

### 三条不能破的约束

1. **AudioContext 只能在用户手势内创建。** 挂在 `document` 捕获阶段的 `pointerdown` 上解锁，
   之前所有 `sfx()` 静默返回 —— 不排队、不报错、不建节点。
2. **包络端点一律 0.0001，不能是 0。** `exponentialRampToValueAtTime(0, t)` 在真机上直接抛异常，
   而且只在特定分支上抛，很容易漏。
3. **切后台回来必须重新对齐时间线。** 不重新对齐的话，积压的几百个音符会被一次性排进去 ——
   实测拆掉对齐后 5 分钟后台会补播 **765 个音符**，听起来是一声巨响。

另外：`pcity_snd` 是独立存档键，**重置城市不会连音量偏好一起清掉**。

> ⚠️ 想改默认行为（比如进场默认静音）：改 `game.js` 里的 `DEFAULT_SOUND` 一行即可。
> 当前默认开启，但 BGM 有 2.5 秒淡入 —— 玩家可能是从信息流里点进来的，音乐不该「砸」出来。

### 验证

音效是唯一既看不着、又没法靠单测覆盖真机约束的部分，所以有两层：

- `node _dev/smoke_test.js` 的 **G 局（23 项）**：用会对非法参数抛错的假 AudioContext，
  钉死包络端点、调度不失控、静音后不再建节点、偏好不被重置连带清掉。
- `python _dev/audio_check.py`：开真 Edge 走一遍完整交互，验 AudioContext 只在手势后创建、
  噪声分支走到 `createBufferSource`、静音后零新增节点、整轮无 JS 报错。

## UI 质感约定

- **玻璃分层**：面板统一「渐变底 + `inset` 顶部内高光 + 外投影」三层，不用纯色块
- **毛玻璃**：顶栏 / 浮层 / 弹窗用 `backdrop-filter: blur()`，仅作增强，去掉也不影响可读性
- **金色强调**：主按钮与选中态走 `var(--gold)` 三段渐变；标题字用 `background-clip: text` 做金渐变
- **动效克制**：只保留三类——数值变化脉冲（`setChip` 加 `.bump`，430ms）、浮层入场位移、提示呼吸。不用弹跳、不用连续循环动画
- **数值写入**：一律走 `setChip(id, txt)`，只在文本真变时写 DOM（避免每帧无脑写），并顺带触发脉冲反馈

## 窄屏适配

- `@media (max-width:360px)`：标签收到 26px 高并隐藏数量角标，9 个类别两行内放完，不吃掉列表高度
- `@media (max-height:620px)`：压缩顶栏与需求条，给城市舞台留空间
- 布局上 `.ov-bar` 是 `flex:0 0 auto`、`.ov-scroll` 是 `flex:1 1 auto`，筛选条换行后列表自动收缩，不会互相挤压

## 市政面板（第五轮）

四组信息，自上而下：

1. **城市概况**：当前称号（金色渐变大字）· 人口/容量/建筑 · 收益/分 · 一句话诊断（diagnose() 优先级：缺电→缺水→积压→满员→缺岗→RCI 旺盛→空城）
2. **关键指标 2×2**：人口 / 就业 / 幸福 / 收益，每格带 CSS 几何图标 + 主数值 + 副信息
3. **市政供需 4 张**：电 / 水 / 环卫 / 积压，**用类别色**做左边条 + 图标 + 进度条；右侧「缺 N」/「余 N」徽章
4. **发展需求 3 条**：住 / 商 / 工 带色块标签 + 强度描述（强烈需求 / 需求旺盛 / 略有需求 / 供需平衡 / 过剩等 6 档）

**架构**：`refreshUtil` → `buildUtil()`（一次）+ `updateUtil(st)`（每帧）。节点引用存 `UT` 全局。`put/putW/putCls` 只在文本/宽度/class 真变时写 DOM。任何 `innerHTML = '...'` 整段重建的做法都会让 CSS 过渡失效、烧 CPU、阻断后续交互。

**图标零依赖**：clip-path 几何形（闪电/水滴/三角/五角星/菱形/螺母/人形等），禁止 emoji，禁止图标字体。

## 平衡推演

`_dev/simulate.js` 用零依赖 DOM stub 真实执行 `main.js`，让自动玩家跑满 60 分钟游戏时间，回答几个产品问题：

- 36 格多久填满？中途会不会卡死？
- 开局前 5 分钟节奏如何？
- 终局收入/人口/幸福停在什么水平？

两组玩家画像对照：
- **A 拼豆大师**：所有图纸瞬间掌握，纯经营决策
- **B 首次拼豆**：每张新图纸要先拼 90 秒才解锁

**反死锁不变量**（在 `_dev/smoke_test.js` E 局固化成断言，每次回归都会校验）：

1. 空城也有保底进账；住宅带来人口税，第一栋就能自我造血
2. 解锁看历史峰值人口，人口回落后已解锁的图纸不会重新上锁
3. 缺电时人口仍能增长（不被冻结）
4. 首个供水/清运设施在人口曲线可达的早期解锁
5. `recommendCat` 在缺水/缺电/积压时优先返回管网类别，**压过 RCI 需求**

**当前数值**（`_dev/data/buildings.json` + `game.js`）：开局 240 金币；市政保底 3 + 人口税 1.5/人 + 产业收益；`BASE_SUPPLY = {power:6, water:6, trash:14}`；缺电只扣收益、缺水冻结人口、垃圾积压扣幸福 + 4 以上时同时赶人。`recommendCat` 缺口优先于 RCI。

推演实测（60 分钟游戏时间）：

| 指标 | A 拼豆大师 | B 首次拼豆 |
|------|-----------|-----------|
| 填满 36 格 | 33:31 | 37:10 |
| 填满瞬间结余 | 1 金币 | 4 金币 |
| 终局结余（60 分钟） | 13267 | 11798 |
| 终局进账 / 幸福 | 486 /分 · 54 | 505 /分 · 51 |
| 最长干等 | 194 秒 | 194 秒 |

全程最低进账 486/分，无任何阶段归零。

**读这份推演要看两个数字**：

- **填满瞬间的结余（1–4 金币）**：前半段经济是紧的，玩家一直在花钱做取舍，没有「钱多到没意义」的阶段。
- **填满后白攒的金币（1.2 万 ≈ 20 栋云端大厦，最贵图纸才 600）**：终局金币完全无出口，游戏实际在第 33 分钟就结束了。
  → 这是下一个功能该解决的真问题，详见 `设定文档.md` 第十一节。

## 开发约定

1. **`_dev/` 是唯一真源**。根目录 `index.html` / `main.js` 是产物，直接改会被下次构建覆盖。
2. 新建筑只改 `_dev/data/buildings.json`：`rows` 必须是 N 行 × N 字符的方阵，色号必须在色卡里声明。`use` / `gen` 的 key 只能是 `power` / `water` / `trash`。构建时会自动校验，不合规直接报错退出。
3. 产物必须满足小红书小工具约束（构建脚本已内置校验，不通过会拒绝打包）：
   - 脚本外置，无内联 `<script>`；`index.html` 用 `<script src="./main.js">` 引入
   - 经典脚本，禁止 `import` / `export`
   - 零外部资源（无 CDN、无外链字体、无网络请求）
   - 安全区用 `var(--safe-area-inset-*, env(...))` 组合
   - 禁止用 UA 判定宿主 App 内缩
4. **元素 id 校验是自动的**：`build.py` 会扫描 JS 里所有函数定义，凡「函数体含 `getElementById(`」或「把自己首参传给已知取元素函数」的，都算取元素函数（当前识别出 `$` 与 `setChip`），再把这些函数的字符串首参当作 id 去 HTML 里比对。**新增同类 helper 无需改构建脚本**，但仍建议跑构建时看一眼识别出的函数名列表是否符合预期。
5. 改完数值/经济后跑一次 `node _dev/simulate.js`，把"建第 N 栋"时间和"全程最低进账"摆出来，能看出早期死锁或后期金币溢出。
6. 每次改动后至少跑一次 `node _dev/smoke_test.js`，确保核心循环没断。
   - 注意：**游戏内时间只在 rAF 回调里推进**，测试里要「边 sleep 边推帧」（`advance()`），光 sleep 不会让时间流逝。
   - 不要用 `b.size` / `b.total` 这类运行时属性（JSON 里没有），测试脚本应从 `rows` 自己推导。

## 发布流程（小红书小工具）

1. `python _dev/build.py` → `node _dev/smoke_test.js` → `python _dev/build_zip.py`
2. 上传 `perler-city.zip` 为小红书小工具（zip 根目录必须是 `index.html`）
3. 发布笔记挂载小工具，带 **#小红书vibecoding大赛** + **#vibegame**
