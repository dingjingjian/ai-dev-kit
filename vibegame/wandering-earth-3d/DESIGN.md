## 1. 定位

`#vibegame`。一句话：**太阳氦闪膨胀壳从第 0 秒就追上来，你以第三人称实时驾驶地球往外飞——管住发动机温度、躲耀斑脉冲、躲八颗行星、借行星弹弓加速，飞出 42 AU 逃出太阳系。**

平台：**专注移动端**，触屏单手操作，竖屏布局。双击 `index.html` 即开（`file://` 零 CORS，贴图全部 base64 内联）。

## 2. 核心玩法

- **开场即操作**：无序章、无剧情幕。2.8 秒过场把镜头从太阳系俯视推到地球后方，随后弹出任务简报，点「出发」即开始计时。
- **实时推力**：触屏按下并拖动 = 点火方向 + 强度（拖得越远推力越大），松手停机。**按住即烧**。
- **发动机过热（本作的核心节奏）**：推力每秒升温 30，松手每秒降温 12。**未烧满时可以随意断续使用且推力不打折**；一旦烧到满值触发**过热锁定**——推力归零，且**必须松手**才能降温，要一直冷却到 **0** 才解锁。
- **脉冲乘波**：5 次耀斑脉冲的 1 秒窗口内推力效率 ×1.8。把温度额度留给脉冲窗口是高分解。
- **不设时限**：`st.t` 只作正计时显示。唯一的死线是身后持续膨胀的氦闪壳。
- **第三人称跟拍相机**：相机锚在地球**运动方向的正后方**偏上，地球位于画面**中心偏下**，正对地球背面的 48 台行星发动机。
- **后视镜**：顶部常驻一路回望视角，从地球前上方看地球背面与身后追来的壳，是判断「还剩多少余量」的主要依据。
- **弹弓引导**：屏幕投影出「下一颗要穿越轨道的行星」，并直读当前相对速度能否安全掠射加速。
- **氦闪膨胀追击**：太阳壳从第 0 秒持续外胀，20 秒后进入二次加速的终局大爆发。
- **躲行星 + 借弹弓**：八颗行星沿圆轨道公转，各有引力与影响球。撞上 = 失败；低速进入影响球 = 被捕获失败；高速掠过 = 引力弹弓借力。
- **胜利条件**：**逃逸比 ≥ 1**（速度达到该处的逃逸速度）**且距日 > 42 AU**（越过冥王星轨道）。

## 4. 操控（移动端触屏）

| 操作 | 行为 |
|---|---|
| 单指按下并拖动 | 点火：方向 = 拖动方向 1:1 映射到世界 XZ 平面（向上 = 沿当前运动方向加速），强度 = 拖动距离（死区 12px，拖过屏幕短边 25% 达满推） |
| 单指松开 | 停机（也是过热锁定的唯一降温方式） |
| 双指捏合 | 相机距离微调（0.5–2.2×） |
| 点任务简报「出发」 | 开始计时 |
| 双击 / 点结算页 | 重开（结算页出现 1 秒后生效，防误触） |

- 开场过场期间与简报未关闭时，**输入被忽略**（`introT < INTRO_TIME` / `briefClosed === false`）。
- 无 WASD / 方向键 / Shift / 滚轮等桌面键鼠操作。
- **拖动 → 世界方向的映射必须各向同性**：由纯函数 `screenDragToWorld(dx, dy, fwdX, fwdZ)` 给出——把屏幕的「上下左右」映射到世界 XZ 平面的**一组正交基**（上方 = 相机前向的水平投影，右方 = 前向绕 Y 轴转 90°）。这样拖动方向与推力方向 1:1，斜拖 45° 就是世界 45°。
  反例（历史 bug：拖动不跟手）：先按相机 forward/right/**up** 基算方向再把 y 归零——相机有俯角，`up` 的 XZ 投影只剩 `sinθ`(≈0.45) 而 `right` 仍是 1，垂直轴灵敏度被压掉一半以上，实测斜拖 30° 会偏到 51.8°、45° 偏到 65.6°；壳逼近拉远（俯角变小）后偏差进一步恶化到 32°。
- `screenDragToWorld` 同样是**无 THREE 依赖的纯函数**，自检有 **8 条**断言锁死（含斜拖 30°/45° 的角度保真与退化输入）。

## 5. 相机（第三人称跟拍 + 后视镜）

- **朝向 = 地球运动方向**：`dir = followDir(vel, pos)`，取速度在 XZ 平面的单位向量；**不是**「相机停在太阳侧」。速度退化（近零）时回退到径向，避免方向抖动。
- **机位**：地球位置 − `dir` × `camBack`，再抬升 `camUp`。相机始终在地球**正后方**看它向前冲；地球模型朝向也已对齐运动方向，所以镜头正对背面，**能看到 48 道发动机光柱与尾焰**。太阳与氦闪壳在镜头背后膨胀追来。
- **构图：地球不居中，落在画面中心偏下**。注视点沿运动方向**前移** `camBack × CAM_LOOK_AHEAD`（不是 `lookAt(地球)`），把前方视野让出来。实测地球纵向位置 = 基础距离下 **−19.6% 半高**、氦闪拉远时 −12.9% 半高（负 = 偏下）。若改回 `lookAt(地球)`，地球会回到正中，自检会报红。
  偏下量随 `CAM_LOOK_AHEAD` 增大而增大但**有上限**（约 0.21 半高，约在 1.12 处取到），超过后注视点离地球过远、地球反而不降反升。
- **跟拍距离必须恒定、有界**：`camBack = followDist(rSun, shellR) × userZoom`，由纯函数给出，**只随「地球到壳的间隙」变化，绝不允许随壳半径增长**。壳半径终局无界膨胀到 1500+，历史 bug 就是直接线性驱动它，导致终局 `camBack` 逼近 500、地球只剩 1.3% 屏高（越飞越小）。修复后全程占屏高恒为 10.5%。
- **氦闪逼近拉远**：间隙 < `CAM_GAP_EASE`(60) 时开始拉远，间隙 0 时到上限 `CAM_PANIC_MAX`(1.6×)，让相机先于地球被壳吞没，强化压迫感。
- **不越过太阳**：跟拍距离再大也 ≤ `max(14, rSun − SUN_R)`。
- **平滑插值**：位置与视点均按 `k = 1 − e^(−4·dt)` 逼近目标；速度方向改变时画面平滑跟随，不甩。
- **捏合缩放**：用户手动微调 `userZoom`（0.5–2.2×），作为**独立相对倍率**叠加在自动距离之上。
- **开场过场**：相机从 `(0, 380, 0.01)` 俯视原点，smoothstep 平滑到**与游戏内跟拍位姿严格一致**的终点（机位 `(AU, CAM_UP, −CAM_BACK)`、注视点 `(AU, 0, CAM_BACK·CAM_LOOK_AHEAD)`），避免过场结束时镜头甩一下。

**后视镜**：单 renderer + `setScissor/setViewport` 画在同一块 canvas 顶部矩形里（不额外开 WebGL context，不重复上传 GPU 资源）。矩形位置**直接读 DOM**（`getBoundingClientRect`），安全区由 CSS 负责，JS 不重复实现一套。相机 = 地球前方 `MIRROR_BACK` 上方 `MIRROR_UP`，注视地球后方 `MIRROR_LOOK`。

| 常量 | 值 | 说明 |
|---|---|---|
| `CAM_BACK` | 55 | 基础跟拍距离（开局 1 AU 处） |
| `CAM_UP` | 28 | 相机相对地球的抬升 |
| `CAM_GAP_EASE` | 60 | 距壳该范围内开始拉远 |
| `CAM_PANIC_MAX` | 1.6 | 拉远上限倍率 |
| `CAM_FOV` | 60° | 垂直视场角（与 `PerspectiveCamera` 共用同一常量） |
| `CAM_LOOK_AHEAD` | 0.7 | 注视点前移比例（占 `camBack`），决定地球在画面中的偏下量（上限约 0.21 半高） |
| `MIRROR_BACK / UP / LOOK` | 26 / 6 / 200 | 后视镜机位与注视点 |
| `MIRROR_FOV` | 68° | 后视镜视场角（比主视角略广） |

`followDist` 与 `followDir` 都是**无 THREE 依赖的纯函数**，渲染层与无头自检共用，自检有 **15 条**断言锁死上面这组性质。

## 6. 物理模型

| 项 | 做法 |
|---|---|
| 运动平面 | 共面（XZ 平面），太阳静止于原点 |
| 太阳 | 引力 `a = −G_SUN · p / |p|³`，唯一引力主源 |
| 行星 | 圆轨道匀速公转，位置与速度解析给出；**各有引力 gm + 影响球 capR**；不受地球影响（单向引力，保证可预测） |
| 地球 | 受太阳 + 八颗行星引力 + 玩家实时推力 |
| 推力 | 实时持续推力：按住即烧，方向 = 拖动方向，强度 = 拖动距离 × 温度效率；松手停机 |
| 过热 | 推力升温 30/s，松手降温 12/s；烧满 → 过热锁定（推力 0，且按着不降温），冷却归零才解锁 |
| 积分 | 半隐式欧拉 + 固定子步（`SUBSTEP = 0.0045` 游戏秒），单帧子步上限 900 |
| 开局保护 | **`t > SAFE_TIME`(0.5 秒) 后才启用行星碰撞判定**。必须按时间而非帧数——按帧数会让 10fps 保护 6 秒、60fps 只保护 1 秒，同一路线在两种帧率下一个撞行星一个不撞 |

## 7. 氦闪膨胀模型

- 壳半径 `shellR(t) = SUN_R + ∫ growRate(t) dt`，**从第 0 秒开始胀**。
- 生长率 `growRate(t) = 4.0`（常态）；脉冲窗口内该基础项 ×4（即 16.0）；`t > 20` 后追加 `(t−20)²·0.01`（终局大爆发）。
- **脉冲窗口是唯一判据**：`pulseActive(t) = 存在 pt ∈ PULSE_TIMES 使 pt ≤ t < pt + PULSE_DUR`。生长率加成与推力加成**共用这一个函数**，不允许各自另写判据（历史 bug：曾用 `growRate(t) > BASE_GROW` 当判据，导致 `t > 20` 后推力加成永久生效）。
- 脉冲前 0.3 秒全屏红边预警。

### 8.3 玩家推力与过热

| 常量 | 值 | 说明 |
|---|---|---|
| `THRUST_ACC` | 7.0 | 满推力加速度（1 秒推力 = 20 km/s） |
| `HEAT_MAX` | 100 | 过热条满值 |
| `HEAT_RATE` | 30 /秒 | 满推升温（~3.3 秒烧满） |
| `COOL_RATE` | 12 /秒 | 松手降温（满值归零需 ~8.3 秒） |
| `PULSE_THRUST_BOOST` | 1.8× | 脉冲窗口内推力效率加成 |
| `AIM_DEAD` | 12 px | 拖动死区 |
| `AIM_FULL` | 0.25 | 达满推所需拖动距离（屏幕短边比例） |

|---|---|---|

### 8.5 真实单位换算（HUD 用）

| 常量 | 值 |
|---|---|
| `REAL_SEC_PER_GAME_SEC` | 5.26×10⁵（游戏 1 秒 ≈ 真实 6.09 天） |
| `KM_PER_UNIT` | ≈ 1.496×10⁶ |
| `KMS_PER_UNIT` | ≈ 2.844 |
| `YEARS_PER_GAME_SEC` | 1/60 |

互锁校验（自检断言）：1 AU 圆轨道速度 × KMS_PER_UNIT = 29.83 km/s，1 AU 转一圈 = 60 游戏秒 = 1 年。

## 9. 胜负判定与弹弓

| 条件 | 结果 |
|---|---|
| 距日 < `SUN_R + EARTH_R`（13.4） | 撞太阳失败 `crashed` |
| 距(行星) < 行星半径 + `EARTH_R` | 撞行星失败 `crashed` |
| 距(行星) < `capR` 且相对速度 < `√(2·gm/dist)` | 被引力捕获失败 `caught` |
| 距日 < `shellR`（当前壳半径） | **被氦闪壳吞没失败** `burned` |
| 逃逸比 ≥ 1 **且** 距日 > `ESCAPE_R` | **逃逸成功** `escaped` |

判定顺序：先太阳/壳，再行星（`t > SAFE_TIME` 后才启用），最后算逃逸比与胜利。`escapeRatio = |v| / √(2·G_SUN/r)`。

**弹弓引导**：取「轨道半径升序里第一个 > 距日的行星」作为目标，投影到屏幕并显示名称、距离，以及当前相对速度能否安全掠射——判据是 `vrel > 1.15 × √(2·gm/capR)`（掠射影响球而不被捕获所需的最低相对速度）。

**关于弹弓的现状（重要，如实说明）**：当前数值下**引力弹弓对结果几乎无影响**，实测把八颗行星全挪到对侧（基本吃不到弹弓）后逃逸用时只从 55.2s 变到 55.4s，**收益 0.3%**。原因是推力与行星引力的量级悬殊：1 秒推力 = 20 km/s，而整个木星飞掠在影响球边缘的逃逸速只有 13.4 km/s（≈0.7 秒推力）。离线的相位求解器（逐颗在 ±180° 内扫描、以逃逸用时为目标）也只把用时从 55.4s 优化到 55.2s，且求解出的火星相位会让参考路线在 t≈3.8s 擦过火星、对帧率极敏感，**收益不值风险，故保留原相位**。
若要让「用满弹弓」成为最优解，需要改动力度：把外行星 `gm` 放大 1–2 个数量级，或把 `THRUST_ACC` 降到 1–2。二者都会显著改变难度与手感，属待定的设计决策，尚未实施。

## 10. 场景与渲染

| 项 | 做法 |
|---|---|
| 引擎 | Three.js（内联 `three.min.js`，`sRGBEncoding` + `ACESFilmicToneMapping`） |

**星空的三个反例（都踩过，别再犯）**

统一根因：相机在半径 4000 的天球内部，屏幕只截取约 60° 视场，**贴图纹素在屏幕上被放大到数像素**。

1. 把星点画进 2048 宽的天球贴图 → 放大 2.3 倍，1px 星点变成 ~2.3px 模糊光斑，观感是「星星很大」。
2. 改用点精灵后把 `STAR_SIZE` 设成 3.5、贴图中心 50% 半径画成**纯不透明白** → 点太小（点精灵把整张贴图铺到 N 个像素上，像素中心只能落在贴图中心 ±(0.5/N) 的 UV 范围内），双线性采样永远只落在纹理正中心，每个点被画成实心白方块，满屏**「白色方格子」**。
3. 星点改对之后，底色渐变与银河雾仍留在天球贴图上 → 底色渐变的 8bit 色阶被拉成等距横条，银河雾（半透明圆斑依次 source-over 叠加）的合成量化台阶被放大成斜向网格 —— 又一片「白色方格子」。**提高分辨率只能把格子等比缩小，根除不了**（1024→2048 只是把网格间距翻倍）。

结论：

- **点精灵的 `size` 必须 ≥8px**（自检有断言）。视觉上的星点大小仍由贴图亮核决定（约 12% 半径，其余快速衰减到全透明），但只有当 `size` 够大时那条衰减曲线才会被采样到 —— `size` 是给渐变留的画布，画布太小就只剩中心那点纯白。
- **天球一律用顶点色，不用贴图**（自检有断言）。任何"画在贴图上"的天球内容都会被球内相机放大成方格，无论贴图多高分辨率。
- 颜色按**线性空间**给：材质输出要过 ACES tone mapping，暗部有死区（线性 <0.002 直接压成纯黑），底色取值要比直觉高一个量级。

## 14. 自检（81 项）

`node tests/headless_escape.js` —— 在 Node 沙箱里跑玩法内核；另含**静态契约**，因为沙箱里没有 `document`/`THREE`，渲染层整段被跳过，改名漏改不会被运行期发现。

| 组 | 断言 |
|---|---|
| 工程 | 脚本可求值；核心函数与常量导出齐全 |
| 工程（DOM/样式契约） | `app.js` 引用的每个 DOM id 都在 `index.html` 里；新 HUD 元素样式规则齐全；HUD 状态类在 CSS 中有定义；已删除的旧元素/变量无残留引用；**天球不用贴图**（用了就退回「白色方格子」） |
| 常量 | 换算互锁（2.844 km/s、1/60 年、29.8 km/s）；脉冲 5 次 @10/20/35/55/75；过热常量齐备；**已删除时限常量**；**星点尺寸 ≥8px**；行星 8 颗；门槛 42 AU |
| 物理 | 不操作时稳定绕日；不操作长时间被壳吞没；顺向推力外飞；引力坠日；**开局保护按时间计（10fps/60fps 保护窗口一致）** |
| 弹弓 | 低速进木星影响球被捕获；高速掠过不被捕获且速度不显著损失 |
| 氦闪 | 壳从第 0 秒持续膨胀；脉冲时生长率显著高于常态；壳内地球判吞没（落点在撞日半径之外） |
| 推力 | 同初态同满推，脉冲窗口内冲量显著高于窗口外（0.682 → 1.242） |
| 过热 | 开局 0 且未锁定；满推 ~3.3s 烧满；锁定期间效率 0；**锁定期间按着不降温、松手才降温**；必须归零才解锁；解锁后效率恢复 1；未过热时断续推效率恒为 1 |
| 相机 | 跟拍方向 = 运动方向；跟拍距离不随壳半径增长；间隙 >60 不拉远、间隙 30 拉远 1.3×、贴脸拉远到上限 1.6×；全程地球占屏高 ≥5%；不越过太阳；**地球不居中、明显偏下**（−19.6% / −12.9% 半高） |
| 地球模型 | 48 台发动机全在 −Z 半球；安装半径统一；**喷流一律平行朝后（48/48 与 −Z 夹角 0°）**；净推力合成 1.000（修复前 0.525） |
| 输入 | 向上拖 = 相机前向、向右拖 = 相机右向；斜拖 30°/45° 角度保真（各向同性）；前向有偏角时同样保真；垂直俯视/零位移返回 null |
| 胜负 | 逃逸比 ≥ 1 且飞出 42 AU 判胜；控温策略逃出（t≈55s）；60fps 同样逃出；**无脑满推逃不出**（永久锁定）；只乘波明显更慢（≥1.5×）；**不存在「时间耗尽」失败** |

## 15. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 真实尺度不可玩 | 放大天体半径与行星引力，只保证单位换算真实 |
| 单向引力不守恒 | 接受。玩法要的是可预测 |
| **推力远强于行星引力 → 弹弓形同装饰** | 如实记录在 §9（实测收益 0.3%）。要让它成为最优解需重调 `gm` 或 `THRUST_ACC`，属待定决策 |
| 无脑满推会被永久锁定 | 这是刻意的：锁定期按着不降温，逼玩家学会松手。HUD 标签直接写「松手冷却」 |
| 八行星全留包体大 | 接受。6 张 base64 + 3 张程序化，dist 原始体积 **2.71 MB**（限 10 MB） |
| `file://` CORS | 贴图全部 base64 内联，`three.min.js` 外置同目录，双击即开零 CORS |
