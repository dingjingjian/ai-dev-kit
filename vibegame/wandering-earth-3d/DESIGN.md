## 1. 定位

`#vibegame`。一句话：**地球沿固定航线自动飞向太阳系外缘，你唯一的操作是「什么时候点火」——在每颗行星的「最佳加速时机」区间按住点火借引力弹弓提速，太早吃不到放大、太晚被捕获或撞毁，还要比身后的氦闪膨胀壳快一步逃出去。**

平台：**专注移动端**，竖屏单手，按住屏幕任意位置点火。双击 `index.html` 即开（`file://` 零 CORS，贴图与 BGM 全部 base64 内联）。

**为什么放弃自由飞行**：自由飞行要求玩家同时管理「方向 + 强度 + 温度 + 行星引力」，触屏单手操作下认知负荷过高，且没有稳定的失败节拍。改成固定航线后，**唯一的自由度就是时机**——这是移动端节奏游戏最经得起反复玩的一种自由度，也让「谁更快」可以量化成一句话去分享。

## 2. 核心玩法

| 机制 | 规则 |
|---|---|
| **固定航线** | 地球沿一条**三维固定航线**（对数螺旋 + 垂直起伏）自动前进，玩家完全不能改变路线；航线终点 = 逃出太阳系 |
| **唯一操作** | 按住**屏幕任意位置**＝推力，松手＝停机。整块画布就是按钮：没有可点的落点、没有死角、不用瞄 |
| **加速窗口** | 距判定点 **2.5–2.8 秒**内显示「加速时机条」。**窗口时长与最佳区间宽度都逐行星不同**——由该行星的质量/引力强度（√(2GM/R)）派生：木星 2.80 s 里绿色占 44%，冥王星 2.50 s 里只占 28% |
| **引力弹弓** | **只在最佳区间**点火才触发：速度按 `a = slingK·(vSling − v)` **向该行星的弹弓速度逼近**。差距越大拉得越猛 → 前面慢了还能追回来，不会一次失误就崩盘。`slingK` 按区间宽度反向补偿 → 吃满的收益对五颗行星完全一致（87.3%） |
| **过早** | 推力照烧（效率仍 1×），但**吃不到弹弓放大**，白烧温度额度。温度总量只够连续点 1.43 s，而窗口有 2.6 s —— 「全程死按」会在最佳区间前就把温度烧穿。**更关键：本次掠过一旦在「过早」区间点过火，弹弓机会整次作废**（`lostSling`）——之后即便按住续进绿色区间，也只给普通推力、不再触发弹弓；评级最高封顶「差一口气」，绝无「完美弹弓」 |
| **过晚** | 残效 0.2×，等于没推。判定点速度不够 → **被引力捕获**（`caught`）；再低到门槛 ×0.72 以下 → **被拽入大气层撞毁**（`crashed`） |
| **温度** | 点火 +70/s，停机 −26/s。烧满即**过热锁定**：推力归零，且**按着不降温**，必须松手冷却到 0 才解锁 |
| **提示** | 只报**发动机与脉冲的紧急状态**：过热时的归零解锁倒计时（赶不上绿色区间就直说「这站来不及解锁」）、耀斑脉冲的预警与生效指令。**不报速度缺口**（过早区间速度必然低于门槛，那是正常状态），**也不报窗口开启倒计时**（把窗口提前送到嘴边会泄掉张力） |
| **氦闪膨胀壳** | 壳半径是**时间的解析函数**（不逐帧积分），从第 0 秒就在身后，全程加速外胀。`距日 < 壳半径` 即被吞没 |
| **脉冲乘波** | **2 次**耀斑脉冲（12 / 26 秒，各 1 秒）期间推力 ×1.6。它只作用于**普通推力项**：绿色区间被弹弓比例项接管，加成不生效（不叠加）。两次都落在行星之间的巡航段 —— 那里点火不作废弹弓，所以脉冲期是白拿 ×1.6 的正规窗口。**提前 2 s 预警**（提示条倒数），到时给动作指令：巡航段 `现在按住`、过早段 `别按（会作废弹弓）`。原来还有第 3 次 @40 s，实测不可达（单局最长 38.5 s）故删除 |
| **不设时限** | 正计时。唯一的死线是身后的壳 |
| **胜利** | 沿航线走完（`s ≥ route.len`）＝ 冲出太阳系 |
| **成绩** | **逃逸用时**。越短越强，本站最快记在 `localStorage`，结算页可直接分享战绩 |

## 3. 节奏与可达性

`node tests/headless_escape.js` 实测（60fps 固定子步）：

| 打法 | 结果 |
|---|---|
| **满弹弓**（最佳区间全程点火，5 次全满） | **escaped，t = 34.7 s**，5/5 完美弹弓，每次余量 20–30 |
| 弹弓 75%（区间内提前松手） | escaped，t = 38.3 s，冥王星处壳余量只剩 **1.0 s**（压线通关） |
| 弹弓 55% | 木星勉强过（余量 4），**土星被捕获** |
| 弹弓 35% / 从不点火 | **木星被捕获** |
| 一直按着 | 木星被捕获（烧满后按着不降温 → 永久锁定） |
| 窗口内全程死按 | 土星被捕获（过早白烧掉温度额度，最佳区间反而烧不满） |
| 10fps 步进 | escaped，与 60fps 结果一致（固定子步积分） |

单局 35–55 秒。**死亡梯度**：乱按 → 木星出局；会抓时机但不够满 → 越到外圈越紧，最终被捕获或被壳追上；抓满 → 34.7 s 逃出并留有余量。

## 4. 操作

| 操作 | 行为 |
|---|---|
| 按住**屏幕任意位置** | 推力开启。整块画布就是按钮：没有可点的落点、没有死角、不用瞄 |
| 松手 / `pointercancel` | 停机（也是过热锁定的唯一降温方式） |
| 双指捏合 | 相机距离微调（0.6–1.9×） |
| 点作业简报「出发」 | 开始计时 |
| 点结算页「再来一次」/ 点击结算页空白 | 重开（结算页出现 1 秒后生效，防误触） |
| 左上 ♪ | BGM 开关（状态持久化） |

- 过场期间与简报未关闭时输入被忽略（`introT < INTRO_TIME` / `briefClosed === false`）。
- 推力来源用 `refreshThrust()` 汇总两路（画布指针 + 按钮指针），**一处松手不会把另一处也熄火**。

## 5. 航线几何（本作最容易踩坑的地方）

### 5.1 参数化

```
r(u) = R0 · (R1/R0)^u                        对数螺旋，95 → 4300
φ(u) = TURNS · 2π · u^WIND                   方位角
y(u) = Y_AMP · sin(Y_FREQ·2π·u + PHASE)      垂直起伏
```

| 常量 | 值 | 说明 |
|---|---|---|
| `ROUTE_R0 / R1` | 95 / 4300 | 起止半径（0.95 → 43 AU） |
| `ROUTE_TURNS` | 0.25 | 全程绕日圈数 |
| `ROUTE_WIND` | 1.0 | 方位角幂次（1 = 匀速缠绕，起手不出现无限大转向率） |
| `ROUTE_Y_AMP / FREQ / PHASE` | 25 / 0.9 / −π/2 | 垂直起伏；相位取 −π/2 让起手是平的 |
| `ROUTE_SAMPLES` | 3600 | 采样段数（弧长表；内圈每段仅约 0.4 单位） |
| 航线总弧长 | **4551**（自检断言） | |

### 5.2 行星摆位：全部由航线反推

1. **二分反解** `u`，使「航线点沿局部正上方抬升 `(rad + clear)`」后的行星距日**恰好等于真实轨道半径**（仰角会拉长距离，所以不能直接按半径换算参数）；
2. `u` 吸附到航线采样点，行星锚在该点正上方 → **掠过的水平偏移严格为 0**（自检断言：偏移 ⊥ 切向、长度 = `rad + clear`）。

因此「掠过距离 = 半径 + 净空」是**构造出来的**，不依赖调参巧合；行星也总是从正前方/正上方进画面。

### 5.3 为什么环绕角必须小（关键教训）

**手机竖屏的水平视场只有约 ±16°**。航行方向每转 1°，就把「前方」甩 1°：

| 版本 | `TURNS` / `WIND` | 地球→火星的航向变化 | 观感 |
|---|---|---|---|
| 早期 | 0.92 / 0.42 | **137°** | 行星全从画面**侧后方**冒出来，竖屏完全框不住 |
| 现在 | 0.25 / 1.0 | 木星约 20° | 行星在正前方由小变大，掠过时位于画面上方 |

代价是「地球 → 第一颗行星」的弧长只能由真实轨道间距给出：**火星（1.52 AU，仅 52 单位）太近，窗口还没亮就到判定点**，只能从掠过名单里去掉（否则起手就是一个没法玩的窗口）。首颗行星改成 5.20 AU 的木星，起手有 461 单位（约 5 秒）的加速段。

**结论**：竖屏节奏游戏里，「航线绕日角」不是美术参数而是**可读性参数**，必须按水平视场倒推上限。

## 6. 相机

| 常量 | 值 | 说明 |
|---|---|---|
| `CAM_BACK` | 46 | 基础跟拍距离 |
| `CAM_UP` | 20 | 相机抬升（地球落画面偏下） |
| `CAM_AHEAD` | 0.62 | 注视点沿航线前移比例（占 `camBack`） |
| `CAM_FOV` | 60° | 垂直视场角（竖屏水平约 ±16°） |
| `CAM_GAP_EASE / PANIC_MAX` | 55 / 1.55 | 壳逼近时的拉远（只随**间隙**，绝不随壳半径无界增长） |
| `CAM_PAN_MAX` | 0.55 | 掠过行星时注视方向偏向行星的最大比例 |
| `CAM_PAN_LEAD` | 3.2 s | 接近段：距判定点该秒数内开始偏（行星提前进画面） |
| `CAM_PAN_HOLD` | 0.30 s | 掠过段：判定点之后仍保持偏移的秒数 |
| `CAM_PAN_TILT_MAX` | 9° | **注视方向被行星拉走的夹角上限**（半径等比放大后行星挂在航线几十单位之上，全额偏移会把地球顶出画面） |
| `MIRROR_BACK / UP / LOOK / FOV` | 26 / 6 / 200 / 68° | 后视镜 |
| `STAR_SIZE` | 9 px | 点精灵尺寸下限（见 §9） |

**三条必须守住的相机不变式**（都有自检断言）：

1. **注视角的偏移必须在「方向空间」做**：先把「沿航线的注视方向」与「指向行星的方向」按权重合成再归一化，最后按原注视距离投射。
   **历史 bug**：把注视**点**直接插值到行星位置——行星是**在航线上方**的，接近时相机被抬起来看它，掠过之后行星落到相机**后方**，注视点跟着跑到相机背后，`lookAt` 方向翻折，观感就是「刚穿过行星，镜头猛地一沉」。
   另一处同源错误是偏移窗口写成 `|s_i − s|` 的**对称**窗口：判定点之后好几秒视线还被拴在身后的行星上，然后才被拉回航线——把下坠拉长成了「镜头甩一下」。现在改成**单侧**窗口（lead 3.2 s / hold 0.3 s）。
   自检锁死：**偏不偏行星，注视距离必须一模一样（实测偏差 2.3e-13）**，且注视方向与航线前方的夹角全程 < 37°（实测最大 18°）。
2. **航线终点之外要把注视点沿末端切向外推**。否则 `routeSample` 会把注视点夹回终点，而终点就是地球本体 —— 最后一瞬镜头变成「盯着地球自己」，注视距离塌掉。
3. **注视方向被行星拉走的夹角必须有上限**（`CAM_PAN_TILT_MAX = 9°`）。半径等比放大后行星挂在航线几十单位之上（木星掠距 66.7），全额偏移会把视线抬高几十度 —— 实测地球离画面中心 42°，已经越过 30° 垂直半视场，**主角被顶出画面**。夹住夹角之后：地球最大离轴 17.8°、行星近缘最大离轴 27.6°，两者始终同框（掠过时行星压上半、地球带判定环留在下半，见 `.shots/y2-flyby.png`）。

**后视镜**：单 renderer + `setScissor/setViewport` 画在同一块 canvas 顶部矩形里（不额外开 WebGL context）。矩形位置直接读 DOM（`getBoundingClientRect`），安全区交给 CSS。

## 7. 数值真源

### 7.1 尺度与换算

| 常量 | 值 | 说明 |
|---|---|---|
| `AU` | 100 | 1 天文单位 |
| `AU_KM / KM_PER_UNIT` | 149597871 / 1495978.7 | 1 单位 = 1.496e6 km；半径从「真实 km」换算成游戏单位的桥 |

| 行星 | 真实半径 (km) | `rad` = ×800 | 真实半长轴 | 轨道 `orbitR` | 净空 | 掠距 = 半径+净空 | 判定门槛 `vNeed` | 弹弓速度 `vSling` | 贴图 |
|---|---|---|---|---|---|---|---|---|---|
| 木星 | 69911 | **37.39** | 5.203 AU | 5.20 AU | 29.3 | 66.7 | 98 | 156 | base64 |
| 土星 | 58232 | **31.14** | 9.537 AU | 9.54 AU | 26.7 | 57.8 | 130 | 168 | base64（含环） |
| 天王星 | 25362 | **13.56** | 19.19 AU | 19.20 AU | 24 | 37.6 | 138 | 172 | 程序化 |
| 海王星 | 24622 | **13.17** | 30.07 AU | 30.10 AU | 22.7 | 35.9 | 138 | 172 | 程序化 |
| 冥王星 | 1188 | **0.64** | 39.48 AU | 39.50 AU | 14.4※ | 15.0 | 132 | 164 | 程序化 |

- 半径的**唯一真源是 `rKm`（真实 km）**，`rad` 由 `bodyR()` 派生（`FLYBYS` 里只允许写 `rKm`）→ 行星之间的比例与真实严丝合缝：木:土 1.20、天:海 1.03、木:冥 58.9、木:地 10.97，全部有自检断言。**任何单颗行星的尺寸都不允许再手调**。
- 倍率为什么是 **800×**：真值下地球只有 0.0043 单位，必须放大才看得见。倍率是**以地球的观感为锚点**定的 —— 800× 让地球 = 3.41 单位，正好回到手调时代那版 3.4（占屏 13%），主角不再是一颗小球。代价是掠过行星同比放大 2.67×（木星 14.0 → 37.4）。
- **净空随半径等比放大（×2.667）**：`掠过距离 : 半径` 在放大前后完全一致（1.78 / 1.86 / 2.77 / 2.73，有断言）→ 「行星在正前方由小变大、贴着航线呼啸而过」的掠过分镜保持不变，只是整体变大。
- ※ **冥王星是唯一例外**：等比后掠距 19.3 几乎等于相机抬升 `CAM_UP = 20`，相机会从它中心擦过去；把净空单独压到 14.4（掠距 15.0），航线明显从它**下方**掠过（相机离它中心 5.0 单位 = 7.8 倍半径）。
- **土星光环的「穿环」是环面朝向问题，不是尺寸问题**（自检断言）。`RingGeometry` 默认躺在 XY 平面（法线 +Z），代码原先没给它旋转 → 环变成「竖着的圈」，航线恰好从环带内穿过环面：实测环带内最小垂距只有 **0.15 单位**（地球半径 3.41），确实是从环体里穿过去。
- 修法：**把环面摆到土星赤道面**（法线 +Y），并叠加真实**轴倾角 26.73°**（`ring.rotation.x = −π/2 + SAT_TILT`）。同一测法的最小垂距变成 **30.5 单位** → 永不穿环；环带也得以用**真实比例 1.11 ~ 2.27 R**（D 环内缘 → A 环外缘），不必再收窄。自检用与渲染层同一个法线 `RING_NORMAL` 验算这条几何约束。
- **太阳为什么是唯一例外**：同比它会是 0.4655 单位 × 800 = **372 单位**，而航线起点只有 95 单位、氦闪壳从 30 单位起 —— 地球会出生在太阳内部，壳也在太阳内部。故太阳单独取 10 单位（≈真值 21×），自检里有一条专门记录这个「同比会怎样」的断言。
- 门槛整体高于「巡航速度」，**只有吃到弹弓才过得去**（`vSling > vNeed` 有断言）；玩法只看「时间 + 速度」，与半径无关 → 改倍率后通关时间几乎不变（34.5 → 34.7 s）。
- 这五颗是**掠过目标**。太阳系里剩下的内行星（水星 / 金星 / 火星）也在场景里，只是不参与判定，见 §7.6。
- **每颗行星距日 = 真实轨道半径（偏差 < 0.05%）**，HUD 的 AU 读数因此不是摆设。
- 判定点占屏高（实测）：**地球 13.0%**（壳贴脸 8.8%）、木星 100%、土星 92%、天王星 51%、海王星 50%、冥王星 3%。
- 行星变得这么大之后，**注视偏移必须加上限**，否则掠过时视线被抬高几十度、把地球顶出画面（实测离轴 42° > 30° 半视场）→ 见 §6 的 `CAM_PAN_TILT_MAX`。

| 常量 | 值 | 说明 |

| `THRUST_ACC` | 9.0 | 常规推力加速度 |
| `DRAG_K` | 0.036 | 阻力 ∝ 速度（时间常数 ~28 s）——不点火会一路掉速 |

| `PULSE_THRUST_BOOST` | 1.6× | 脉冲期推力加成 |

**温度预算与窗口的互锁**（自检**逐行星**断言，因为窗口与区间都是逐行星的）：
- `满箱时间 < 该行星窗口时长` → 窗口中全程死按必然烧穿；
- `满箱时间 > 该行星最佳区间时长` → 规规矩矩只烧最佳区间不会过热。
这两条把「过早」变成一个真实的资源惩罚，而不是文案。

### 7.4 时机窗口与弹弓：**每颗行星不同，由质量派生**

窗口与最佳区间不是全局常量。引力强度取**真实质量 + 真实半径**推出的表面逃逸速度
`v_esc = √(2GM/R)`（弹弓能利用的增益上限就是它），再归一化成 `q ∈ [0,1]`：

| 行星 | 质量（地球=1） | `v_esc` | `q` | 窗口 `winTime` | 最佳区间 | 区间时长 | `slingK` | 完美阈值 `ratingSweet` |
|---|---|---|---|---|---|---|---|---|
| 木星 | 317.8 | 60.20 km/s | 1.000 | **2.80 s** | 46.0% → 90% | 1.23 s | 1.67 /s | 0.59 s |
| 土星 | 95.2 | 36.10 | 0.592 | 2.68 s | 52.5% → 90% | 1.00 s | 2.05 | 0.48 s |
| 海王星 | 17.15 | 23.56 | 0.378 | 2.61 s | 56.0% → 90% | 0.89 s | 2.31 | 0.43 s |
| 天王星 | 14.54 | 21.38 | 0.342 | 2.60 s | 56.5% → 90% | 0.87 s | 2.37 | 0.42 s |
| 冥王星 | 0.00218 | 1.21 | 0.000 | **2.50 s** | 62.0% → 90% | 0.70 s | 2.94 | 0.34 s |

| 派生式 | 值 | 说明 |
|---|---|---|
| `q` | (v_esc − min) / (max − min) | 引力强度归一化 |
| `winTime` | `2.5 + 0.3q` | 引力越强，窗口越早亮灯 |
| `sweet0 / sweet1` | `0.62 − 0.16q` / `0.90` | 引力越强，绿色区间越宽（起点更早） |
| `slingK` | `2.06 / 区间时长` | **反向补偿**：吃满的弹弓逼近量对五颗都是 **87.3%** |
| `ratingSweet` | `区间时长 × 0.48` | 「完美弹弓」= 把**该行星**的绿色区间吃满 |
| `LATE_EFF` | 0.2 | 过晚区间点火的残效 |
| `CRASH_RATIO` | 0.72 | `v < vNeed × 0.72` → 撞毁，否则被捕获 |

- `tToGo = (s_i − s)/v`，`phase = 1 − tToGo/winTime`，`phase < 0` 尚未进窗、`> 1` 已过判定点。
- **按质量，不按轨道顺序**：海王星（17.15）比天王星（14.54）重，所以它的窗口与区间都不小于天王星 —— 走在外圈的它反而比前一站好抓一点，这是数据而不是手感调参（有断言）。
- **窄区间只是「更难按准」，不是「吃满更亏」**：`slingK` 按区间宽度反向补偿后，吃满区间得到的速度增益逐行星完全一致 → 通关时间与氦闪壳曲线都不用重标（自检里有一条专门断言这个不变量）。
- **弹弓为什么用「比例项」而不是「固定 Δv」**：固定 Δv 会让速度形成正反馈（吃过弹弓 → 下一次弹弓更值钱 → 强者愈强），属「一次失误即宣判」。改成 `a = slingK·(vSling − v)` 后，逼近量随缺口自动放大，**落后可以追回**，斜率变平缓。实测梯度：吃满 **34.7 s** 逃出；吃到 75% → 38.3 s 逃出（末站只剩 1.0 s 壳余量）；吃到 50% → 土星处被捕获。

| 常量 | 值 |
|---|---|
| `SHELL_START` | 30 |
| `SHELL_A` | 48.22 |
| `SHELL_B` | 1.6282 |

按「满弹弓参考轨迹 + 逐年递减的余量」拟合：木星处余 2.9 s、天王星 9.6 s、终点 7.2 s；而弹弓 55% 的打法会在天王星附近**被壳吞掉**——壳因此是一条真实存在的第二死线，不是背景板。

### 7.6 场上的其他行星（不参与判定）

掠过名单只有五颗（火星距起点仅 52 单位、窗口来不及亮，见 §5.3），但**太阳系不能只剩五颗球**：
水星 / 金星 / 火星按真实半径（同一 `BODY_SCALE`）与真实轨道半径摆进场景，只是没有判定点、
没有加速窗口、不检测碰撞。

| 天体 | 真实半径 | `rad`（×800） | 真实轨道 | 摆位方式 |
|---|---|---|---|---|
| 水星 | 2440 km | 1.31 | 0.387 AU | `behind`：在航线起点内侧 → 摆在地球起点同一方位角的黄道面上 |
| 金星 | 6052 km | 3.23 | 0.723 AU | 同上 |
| 火星 | 3390 km | 1.81 | 1.524 AU | `route`：在航线外侧 → 与掠过行星同一套摆位（沿航线局部上抬 40 单位，距日仍反解到 1.524 AU） |

- **内侧行星在正前方本来就看不到**（它们在地球身后）：靠顶部**后视镜**与左上**小地图**读出来，小地图上永远有两个点在太阳旁边。

## 8. 判定与评级

| 条件 | 结果 |
|---|---|
| `s ≥ route.len` | **escaped** 冲出太阳系 |
| `距日 < shellR` | **burned** 氦闪吞没（速度欠账的最终收款人） |
| 判定点 `v < vNeed × 0.72` | **crashed** 被拽入行星大气层（低到连大气层都擦不过去） |
| 判定点 `v < vNeed` 且**这一关的窗口根本没碰**（`early ≈ 0` 且 `sweet ≈ 0`：只在过晚区间点、或完全没按） | **caught** 被行星引力捕获（即时失败） |
| 判定点 `v < vNeed` 但**推过了**（过早白烧 或 绿色区间吃到过一点） | **slow** 速度没拉起来 —— 地球照常掠过，**不在这里判死**，欠账交给氦闪壳在后面追讨（延迟失败） |
| 判定点 `v ≥ vNeed` | 通过；**未作废弹弓** 且 `最佳区间累计点火 ≥ 该行星 ratingSweet` → **perfect**，否则 **pass**（作废后最高 `差一口气`） |

**两种失败模式按原因分开**（这是设计意图，不是同一件事的两个名字）：

- **过晚 / 没按** → 这个窗口白白错过，速度根本没拉起来 → 这颗行星**当场抓住你**（`caught`；低到 `vNeed × 0.72` 以下则 `crashed`）。
- **过早过多** → 在「过早」区间（`zone === 'early'`）点过火——**哪怕只有一帧（1/120 s）**——就把该行星的 `lostSling` 置真，本掠过余下时间 `st.slinging` 恒为 false，续进绿色区间也只给普通推力（9 单位/s²，而温度总额只够连点 1.43 s）→ 判定点速度掉到门槛之下，但地球**照常掠过**（记为 `slow`），代价改由身后的氦闪壳结账。

**过早的代价是「被太阳追上」，不是当场终结**（逐颗实测，判定点速度 vs 门槛）：木星 82.0 / 98、土星 120.7 / 130、天王星 123.8 / 138、海王星 123.2 / 138、冥王星 127.3 / 132 —— 常规推力的天花板把速度卡在门槛之下、撞毁线之上，于是地球带着这份欠账继续跑：**前 3 颗行星上的过早点火，整局都会拖到 30 s 之后才被壳追平**（木星 34.1 s / 进度 82%、土星 38.1 s / 98%、天王星 38.2 s / 99%），而不是旧版 5.6 s 处当场被行星抓住；外圈（海王星 / 冥王星）若前面跑得够好，欠账还追得回来（37.5 s / 35.3 s 逃出）。同一颗行星上连续两次过早（比如木星 + 土星都烧废）才会掉到撞毁线以下，改为 `crashed`。

**掠过后即时评级**（`gradeFlyby` 纯函数，8 种情形有断言）：把「过早 / 绿色 / 过晚」三个区间的实际点火时长翻译成等级 + 一句可执行的提示；`lostSling` 为真时封顶「差一口气」并提示「弹弓已作废」。评级条固定两行：`绿色区间 X s / 完美线 Y s` + 下面那句提示（提示不再重复「绿色区间」，因为上一行已经报了）。

| 情形 | 等级 | 提示 |
|---|---|---|
| 绿色区间吃满 | 完美弹弓 | 吃满，弹弓把速度拉到了该行星的弹弓速度 |
| 吃到一半 | 差一口气 | 只吃到一半，弹弓没拉满 —— 下次让指针在绿色区间多停一会儿 |
| 有 sweet 但很少 | 按早了 | 过早区间只有普通推力，白烧了温度 —— 等指针进绿色区间再按 |
| 只有过晚 | 按晚了 | 过晚区间点火几乎不推进，判定点速度自然不够 |
| 只有过早 | 过早白烧 | 全程都在过早区间点火：那里吃不到弹弓，温度也烧光了 |
| 一次没按 | 没点火 | 一次都没按，速度被阻力一路吃掉 |
| 判定没过门槛但**推过**（`slow`） | 速度没拉起来 | 过早区间点过火，这颗的弹弓作废 / 前面欠的速度还没还上 —— 地球照常往前飞，氦闪壳正在追上来 |
| 判定没过门槛且**没碰窗口** | 被捕获 | 判定点速度不够：绿色区间必须吃满，弹弓才拉得起来 |

失败原因文案也随之分叉：吃过 `slow` 的局被壳追上时写「速度没拉起来，地球被氦闪壳追上」，否则写「地球被氦闪壳吞没」——玩家一眼能看出是被自己的过早烧没的。

| 情形 | 等级 | 提示 |
|---|---|---|
| 绿色区间吃满 | 完美弹弓 | 吃满，弹弓把速度拉到了该行星的弹弓速度 |
| 吃到一半 | 差一口气 | 只吃到一半，弹弓没拉满 —— 下次让指针在绿色区间多停一会儿 |
| 有 sweet 但很少 | 按早了 | 过早区间只有普通推力，白烧了温度 —— 等指针进绿色区间再按 |

### 9.2 星空（三个已踩过的反例）

统一根因：相机在半径 16000 的天球内部，屏幕只截取约 60° 视场，**贴图纹素会被放大到数像素**。

1. 星点画进天球贴图 → 放大 2.3 倍，1px 星点变模糊光斑；
2. 改用点精灵但 `STAR_SIZE = 3.5`、贴图中心画成纯不透明白 → 双线性采样永远只落在纹理正中心 → 满屏**「白色方格子」**；
3. 星点修好后，底色渐变与银河雾仍留在贴图上 → 8bit 色阶被拉成等距横条、雾的合成台阶被放大成斜向网格 —— 又一片方格。**提高分辨率只能把格子等比缩小，根除不了**。

结论（均有断言）：**天球一律用顶点色，不用贴图**；**点精灵 `size ≥ 8px`**（`size` 是给渐变留的画布，画布太小就只剩中心那点纯白）；颜色按线性空间给（要过 ACES，暗部 <0.002 直接压成纯黑）。

### 9.3 地球与发动机

- 地球 = base64 贴图 + 冷色 tint + 程序化冰封壳 + 稀薄云 + 大气壳。
- 48 台行星发动机按黄金角螺旋分布在**背面（−Z 半球）**，安装半径 `1.08 R`（> 大气 1.06 R 不穿模）；**喷流一律平行朝后**——历史 bug 是取球面法线朝外，赤道附近与 −Z 夹角达 87°，净推力只剩 0.53（现在是 1.000，有断言）。
- 地球朝向 = 航线切向（`slerp` 平滑），镜头正对背面，因此 48 道发动机光柱常驻画面。

### 9.4 BGM 与音效

- **BGM 为什么内联成 `.js`**：小工具容器上传白名单不收音频扩展名，且 `file://` 下 `<audio>` / `fetch` 会被跨域拦。做法同 `vibegame/perler-bead-game/bgm.js`：整曲 base64 藏进 `assets/bgm-data.js`，运行时 `atob → Uint8Array → AudioContext.decodeAudioData`，**全程不产生任何 URL**。源 `d8badba2214c66d62989f41c4000a402(1).mp3`（MPEG2 Layer III · 64 kbps · 24 kHz · 约 125 s · 974 KB → base64 1298 KB），由 `tools/make-bgm-data.mjs` 生成。
- **循环不用 `src.loop`**（接缝会「咔哒」），改为手动排期：每遍提前 3 s 起下一遍，交叠处一条淡出对一条淡入。
- 首次触摸解锁音频上下文；左上 ♪ 开关状态写入 `localStorage`；切后台 `suspend()`、回来 `resume()`。
- 音效仍是程序化 WebAudio：点火隆隆、脉冲爆音、过热告警、冷却归零、掠过评级音（按等级分双音/单音/失败音）、胜负音。

## 10. 分享战绩

按仓库既有做法（见 `vibeknow/china-rail-atlas/main.js`）走**容器 JSBridge**，不做 UA 判断：

```js
XHS = window.xhs && window.xhs.miniTool
CAN_SHARE = XHS && typeof XHS.postNote === 'function'
XHS.postNote({ title, content, pageType: 'photo_publish', mediaInfo: { image_resources: [{ url }] } })
```

- `mediaInfo` 必填，配图由 **Canvas 现画**的「战绩卡」（900×1200：用时巨字 + 评价 + 五颗行星评级色标 + 挑战文案 + 话题标签），**不引用任何外部图片**，也不碰被容器禁用的网络请求 API；写盘走 `XHS.writeTempFile({ data })`。
- 上限守卫：`title` ≤ 20 字、`content` ≤ 1000 字（主动裁剪）。
- **拿不到 bridge 就退化成「选中文案 + 引导长按复制」**（`createRange + getSelection`，同 `vibeknow/china-rail-atlas` 的 `copyPrompt`），按钮永不消失。
  注意**不能**用 `execCommand` / `clipboard.writeText` —— 它们在小工具容器的**禁用能力扫描清单**里，`verify-minitool.mjs` 会直接判不合规（自检也有断言禁止这两个标识符出现）。
- `postNote` 成功只代表**唤起发布页**，不代表过审——提示文案只写「已唤起发布页」。

| 耀斑脉冲 | 只两次且都落在单局时长内（被删的第 3 次 @40 s 走不到）；预警提前量 ≥1.5 s；`pulseIn` 倒数与 Infinity 收尾；**提示按区间分叉**（巡航段「现在按住」/ 过早段「别按（会作废弹弓）」/ 绿色与过晚不抢屏）；**预警期绝不说「按住」**（预警 2 s + 生效 1 s 连按会烧穿）；预警 2 s 与生效 1 s 逐帧成立；「现在按住」只在安全区出现 |
| 行星判定 | 高于门槛安全掠过；**没碰窗口**（不点火 / 只在过晚区间点）且在门槛与撞毁线之间被捕获、远低于被拽入大气层；**推过了但没过门槛**（过早白烧 / 绿色吃到过一点）记 `slow` 放行，欠账由壳追讨 |
| 氦闪壳 | 单调膨胀且加速；游戏内壳半径 = 解析式；进入壳内即判吞没 |
| 相机 | 跟拍距离有界、不越过太阳、不因壳半径增长；**地球占屏高 ≥5%（实测 13.0%、壳贴脸 8.8%）**；**偏移权重单侧（掠过 0.27 s 衰减过半、0.67 s 归零）**；**注视距离不因行星偏移而改变**；注视方向全程朝前（<37°）且无突变 |
| 构图不变式 | 掠过时地球离画面中心 < 26°（实测 17.8°）、行星近缘 < 30°（实测 27.6°，木星）→ **两者始终同框**；注视方向被行星拉走的夹角 ≤ `CAM_PAN_TILT_MAX`（实测 8.98° / 上限 9°） |
| 地球模型 | 48 台全在 −Z 半球；安装半径统一；喷流平行朝后；净推力合成 1.000 |
| 胜负 | 满弹弓逃出（34.7 s，5/5 完美）；75% 也能逃出但更慢（38.3 s）；35% / 不点火 / 一直按着 / 窗口死按均逃不出；**10fps 与 60fps 状态完全一致**；无「时间耗尽」失败 |

## 15. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 「固定航线」牺牲了自由飞行的空间感 | 换来的是可读的时机节奏与可量化的成绩（「谁更快」），移动端单手也更成立 |
| 火星 / 水星 / 金星不入航线 | 火星距起点仅 52 单位，窗口来不及亮；宁缺勿滥（贴图相应删除，包体 -310 KB） |
| 但水星 / 金星 / 火星仍摆进场景 | 只作背景（无判定点、无窗口、不检测碰撞）。太阳系因此是完整的，火星还顺便把「为什么不吃它」变成看得见的事实；代价是真实比例下它们只有几像素，识别靠柔光与小地图 |
| 窗口与最佳区间按质量/引力逐行星不同 | 大质量行星引力影响范围大 → 窗口更长、绿色区间更宽（木星 2.80 s/44%，冥王星 2.50 s/28%）。难度曲线因此自带「越靠近太阳系外缘越苛刻」，且是按真实数据而不是按手感拍；代价是评级阈值也得跟着逐行星折算 |
| 半径全部改成真实比例（统一 800×，以地球观感为锚点） | 行星之间的大小关系与真实一致（木 37.4 / 土 31.1 / 天 13.6 / 海 13.2 / 冥 0.64 / 地球 3.41）——地球回到手调时代的 13% 占屏，主角立住了。代价：掠过行星同比放大 2.67×（木星判定点压满整屏），净空必须同比放大才保住掠过分镜，注视偏移必须加上限才不把地球顶出画面；太阳仍是唯一例外（§7.2） |
| 航线近乎径向，观感不如盘旋 | 盘旋角大 → 行星从侧面出现、竖屏框不住。**可读性优先** |
| 门槛整体偏高、需要吃到弹弓 | 刻意如此：不吃弹弓就是过不去，机制才有存在感 |
| BGM 增加 1298 KB base64 | 容器不接受音频文件且 `file://` 跨域受限，只能内联；无 `WE_BGM_B64` 时静默降级，玩法不受影响 |
| 分享依赖容器 bridge | 能力检测而非 UA；拿不到就退化为复制文案，按钮不消失 |
| `postNote` 成功 ≠ 过审 | 提示只写「已唤起发布页」，不做任何强一致状态变更 |
| `file://` CORS | 贴图与 BGM 全部 base64 内联，`three.min.js` 外置同目录，双击即开零 CORS |
