> - 2026-09-26（**功率 → 温度**）：把两条互不相干的量串成一条因果链。旧版的**温度**是唯一资源（按住恒定 +70/s、满则锁死），而**功率**是从区间派生的瞬时读数（0/20/100/160%）—— 后果是「在过早区死按」与「在巡航段死按」烧穿温度的速度一模一样，功率表怎么动都不影响温度。现在旧「温度箱」变成**功率**（按住起转 0.5 s 到满额、松手 0.5 s 归零），另起一个新**温度**箱按**当前功率档位**涨（温度 = ∫ 功率：满功率恒温 1.33 s 烧穿、冷机起按住 1.58 s），满则进旧版那套过热锁定（推力归零、按着不降温、归零解锁 3.85 s —— 一条都没改）。三个副产物：① **过晚残效 20% 连温度都只涨 1/5**（旧版在过晚区照样满速烧温度，「白烧」不再等于「烧温度」，只等于「推力白给」）；② **脉冲乘波把功率推到 160% → 温升也 ×1.6**（满功率进脉冲 0.83 s 就烧穿，而老实等脉冲亮了再按满 1 秒只涨到 90）—— 脉冲从「白拿 ×1.6」变成「白拿，但烫」；③ **推力随功率一起起转**，所以普通推力项的起步略软（1 秒点火平均只有 75% 档位），但**绿色区间的增益由弹弓比例项接管、与功率无关**，因此满弹弓通关时间**仍是 34.7 s**、五颗行星吃满的收益仍是 87.3%。表盘布局一行未动（温度表与新温度箱、功率表与功率斜坡各自沿用原 DOM / 满量程），自检从 240 项增到 **259 项**。
> - 2026-09-26（**温度改柱状图 → 又回退**）：仪表行里温度先从**指针表盘**改成**柱状图**（`.tb / .tb-fill`，填充高度 = 温度百分比），理由是「温度是单调的余量，只关心离满箱多远，柱高直接就是答案」。**当天再回退成表盘** —— 三格统一成盘之后，柱与两张盘在同一行里的读法不一致（柱靠高度、盘靠角度，余光扫过要在两套语言间切换），而柱省下的那点认知远不如一致性值钱。**这一轮同时改了两件事**：① **顺序改为 `功率 → 温度 → 速度`**（见 §9.1.1 的顺序理由）；② 修掉两个实测抓到的历史 bug —— **功率指针刻度**（小数被当成百分数除满量程 → 指针全程只转 1°）与**值弧被 CSS 压掉**（`.dg-arc` 的 `stroke-dashoffset` 声明压过 SVG 表现属性 → 三条值弧永远是空的）。柱状图那套（`.tb-box / .tb-fill / elHeatBar`）已彻底移除、不留残留；自检 **262 → 264 项**（新增顺序契约 + 两个 bug 的回归契约）。
> - 2026-09-26（**强制降温**）：改动过热的收尾规则。旧规则是「按着不降温，必须松手冷到 0」——它把「没松手」本身当成惩罚，代价是逼玩家先抬指再按：手机上手指本来就在屏幕上，这条规则只教人做一次无意义的抬手动作，而**惩罚其实由「停机这一段」就说完了**。现在 **过热锁定 = 强制降温阶段**：温度无论按不按都按 `COOL_RATE` 降；按住既不会升温、也不会重新起转（功率与推力全程 0），**也不会打断降温进度**。两点连带效果：① 「一直按着」从「永久锁定」变成「停机 3.85 s」——木星窗口 2.5–2.8 s 整段都在冷却里，所以这一局照样出局（实测仍在 5.1 s 被捕获），但死因从「没抬手指」换成了「强制停机 3.85 s」；② **解锁那一刻手指还在屏幕上就立即复机**（不必松手再按），`sfxReady` 就是这一下的提示音。基准打法不碰过热，所以 34.7 s 的满弹弓时间与整条梯度不变。自检 264 → **265 项**。

## 1. 定位

`#vibegame`。一句话：**地球沿固定航线自动飞向太阳系外缘，你唯一的操作是「什么时候点火」——在每颗行星的绿色「引力窗口」区间按住点火借引力弹弓提速，太早吃不到放大、太晚被捕获或撞毁，还要比身后的氦闪膨胀壳快一步逃出去。**

平台：**专注移动端**，竖屏单手，按住屏幕任意位置点火。双击 `index.html` 即开（`file://` 零 CORS，贴图与 BGM 全部 base64 内联）。

**为什么放弃自由飞行**：自由飞行要求玩家同时管理「方向 + 强度 + 温度 + 行星引力」，触屏单手操作下认知负荷过高，且没有稳定的失败节拍。改成固定航线后，**唯一的自由度就是时机**——这是移动端节奏游戏最经得起反复玩的一种自由度，也让「谁更快」可以量化成一句话去分享。

## 2. 核心玩法

| 机制 | 规则 |
|---|---|
| **固定航线** | 地球沿一条**三维固定航线**（对数螺旋 + 垂直起伏）自动前进，玩家完全不能改变路线；航线终点 = 逃出太阳系 |
| **唯一操作** | 按住**屏幕任意位置**＝推力，松手＝停机。整块画布就是按钮：没有可点的落点、没有死角、不用瞄 |
| **加速窗口** | 距判定点 **2.5–2.8 秒**内显示「加速时机条」。**窗口时长与最佳区间宽度都逐行星不同**——由该行星的质量/引力强度（√(2GM/R)）派生：木星 2.80 s 里绿色占 44%，冥王星 2.50 s 里只占 28% |
| **引力弹弓** | **只在最佳区间**点火才触发：速度按 `a = slingK·(vSling − v)` **向该行星的弹弓速度逼近**。差距越大拉得越猛 → 前面慢了还能追回来，不会一次失误就崩盘。`slingK` 按区间宽度反向补偿 → 吃满的收益对五颗行星完全一致（87.3%） |
| **过早** | 推力照烧（效率仍 1×、温升也是满速），但**吃不到弹弓放大**，白烧温度额度。温度总量只够**满功率连点 1.33 s**（冷机起按住 1.58 s），而窗口有 2.5–2.8 s —— 「全程死按」会在绿色区间前就把温度烧穿。**更关键：本次掠过一旦在「过早」区间点过火，弹弓机会整次作废**（`lostSling`）——之后即便按住续进绿色区间，也只给普通推力、不再触发弹弓；评级最高封顶「弹弓增益损失」，绝无「完美弹弓」 |
| **过晚** | 残效 0.2×，等于没推（**温升也只有 20%** —— 它只白给推力，不白烧温度；ⓘ 功率表**读数不降级**，仍满表 100% + 红态，见 2026-09-27 演进记录）。判定点速度不够 → **被引力捕获**（`caught`）；再低到门槛 ×0.72 以下 → **被拽入大气层撞毁**（`crashed`） |
| **功率（发动机油门）** | 按住**起转**（`+PWR_UP` = 200/s → 0.5 s 到满额）、松手**熄火**（`−PWR_DOWN` = 200/s → 0.5 s 归零），过热锁定被强制归零。功率档位 = `功率 × 区间效率 × 脉冲乘波`，它同时是**推力系数**（普通推力项）与**温升系数** |
| **温度** | **按功率涨**：温升速率 = `TEMP_RATE × 功率档位`（= 75 × 功率 × 区间效率 × 乘波），停机 −26/s。烧满即进入**强制降温**（3.85 s）：推力归零、功率同时熄火，温度按 `COOL_RATE` 强制下降。**降温期间点也白点** —— 按着既不升温、也不重新起转、也不打断降温进度；降到 0 解锁，解锁时手指若还在屏幕上则立即复机 |
| **提示** | 只报三类**状态**（文案真源是核心的 `st.warn`）：① 过热 —— `发动机过热 · 强制冷却 X s`，冷却赶不上绿色区间时改说 `发动机过热锁定 · 本站窗口前无法解锁`（判据是**绿色区间开始**，不是窗口开启）；② 耀斑脉冲的预警与生效指令（见下一行）；③ **过晚** —— `窗口关闭 · 已错过`。**不报速度缺口**（过早区间速度必然低于门槛，那是正常状态），**也不报窗口开启倒计时**（把窗口提前送到嘴边会泄掉张力）。巡航段（`appr` / `done`）消息槽一律保持空 |
| **氦闪膨胀壳** | 壳半径是**时间的解析函数**（不逐帧积分），从第 0 秒就在身后，全程加速外胀。`距日 < 壳半径` 即被吞没 |
| **脉冲乘波** | **2 次**耀斑脉冲（12 / 26 秒，各 1 秒）期间推力 ×1.6。它只作用于**普通推力项**：绿色区间被弹弓比例项接管，加成不生效（不叠加）。两次都落在行星之间的巡航段 —— 那里点火不作废弹弓，所以脉冲期是白拿 ×1.6 的正规窗口。**提前 2 s 预警**（提示条倒数 `⚠ 太阳耀斑脉冲 2.0 s 后 · 推力 ×1.6`），到时给动作指令：巡航段 `⚠ 太阳耀斑脉冲 ×1.6 · 全功率推进`、过早段 `⚠ 太阳耀斑脉冲 ×1.6 · 窗口外禁止点火`（绿色 / 过晚不抢屏）。原来还有第 3 次 @40 s，实测不可达（单局最长 38.3 s）故删除。**乘波同时把功率推过额定线（160%）→ 温升也 ×1.6**：从冷机起按满整段 1 s 只涨到 90（提示里的「全功率推进」是安全的），但**已在满功率时进脉冲 0.83 s 就烧穿** —— 所以「别在预警期就按住」这条从「会烧穿」升级成「会先烧穿、再错过脉冲」 |
| **不设时限** | 正计时。唯一的死线是身后的壳 |
| **胜利** | 沿航线走完（`s ≥ route.len`）＝ 冲出太阳系 |
| **成绩** | **逃逸用时**（**两位小数**：局内计时器 / 结算页 / 分享卡 / 最快记录同一个数，由 `t2()` 统一取整）。越短越强，**最快记录**记在 `localStorage`，结算页可直接分享战绩 |

## 5. 航线几何（本作最容易踩坑的地方）

### 5.1 参数化

```
r(u) = R0 · (R1/R0)^u                        对数螺旋，95 → 4300
φ(u) = TURNS · 2π · u^WIND                   方位角
y(u) = Y_AMP · sin(Y_FREQ·2π·u + PHASE)      垂直起伏
```

| 常量 | 值 | 说明 |
|---|---|---|
| `ROUTE_R0 / R1` | 95 / 4300 | 起止半径（0.95 → 43 AU） |
| `ROUTE_TURNS` | 0.25 | 全程绕日圈数 |
| `ROUTE_WIND` | 1.0 | 方位角幂次（1 = 匀速缠绕，起手不出现无限大转向率） |
| `ROUTE_Y_AMP / FREQ / PHASE` | 25 / 0.9 / −π/2 | 垂直起伏；相位取 −π/2 让起手是平的 |
| `ROUTE_SAMPLES` | 3600 | 采样段数（弧长表；内圈每段仅约 0.4 单位） |
| 航线总弧长 | **4551**（自检断言） | |

### 5.2 行星摆位：全部由航线反推

1. **二分反解** `u`，使「航线点沿局部正上方抬升 `(rad + clear)`」后的行星距日**恰好等于真实轨道半径**（仰角会拉长距离，所以不能直接按半径换算参数）；
2. `u` 吸附到航线采样点，行星锚在该点正上方 → **掠过的水平偏移严格为 0**（自检断言：偏移 ⊥ 切向、长度 = `rad + clear`）。

因此「掠过距离 = 半径 + 净空」是**构造出来的**，不依赖调参巧合；行星也总是从正前方/正上方进画面。

### 5.3 为什么环绕角必须小（关键教训）

**手机竖屏的水平视场只有约 ±16°**。航行方向每转 1°，就把「前方」甩 1°：

| 版本 | `TURNS` / `WIND` | 地球→火星的航向变化 | 观感 |
|---|---|---|---|
| 早期 | 0.92 / 0.42 | **137°** | 行星全从画面**侧后方**冒出来，竖屏完全框不住 |
| 现在 | 0.25 / 1.0 | 木星约 20° | 行星在正前方由小变大，掠过时位于画面上方 |

代价是「地球 → 第一颗行星」的弧长只能由真实轨道间距给出：**火星（1.52 AU，站台在 s = 67）太近，窗口还没亮就到判定点**，只能从掠过名单里去掉（否则起手就是一个没法玩的窗口）。首颗行星改成 5.20 AU 的木星（判定点 s = 457），起手有 457 单位（约 5 秒）的加速段。

**结论**：竖屏节奏游戏里，「航线绕日角」不是美术参数而是**可读性参数**，必须按水平视场倒推上限。

**三条必须守住的相机不变式**（都有自检断言）：

1. **注视角的偏移必须在「方向空间」做**：先把「沿航线的注视方向」与「指向行星的方向」按权重合成再归一化，最后按原注视距离投射。
   **历史 bug**：把注视**点**直接插值到行星位置——行星是**在航线上方**的，接近时相机被抬起来看它，掠过之后行星落到相机**后方**，注视点跟着跑到相机背后，`lookAt` 方向翻折，观感就是「刚穿过行星，镜头猛地一沉」。
   另一处同源错误是偏移窗口写成 `|s_i − s|` 的**对称**窗口：判定点之后好几秒视线还被拴在身后的行星上，然后才被拉回航线——把下坠拉长成了「镜头甩一下」。现在改成**单侧**窗口（lead 3.2 s / hold 0.3 s）。
   自检锁死：**偏不偏行星，注视距离必须一模一样（实测偏差 2.3e-13）**，且注视方向与航线前方的夹角全程 < 37°（实测最大 18°）。
2. **航线终点之外要把注视点沿末端切向外推**。否则 `routeSample` 会把注视点夹回终点，而终点就是地球本体 —— 最后一瞬镜头变成「盯着地球自己」，注视距离塌掉。
3. **注视方向被行星拉走的夹角必须有上限**（`CAM_PAN_TILT_MAX = 9°`）。半径等比放大后行星挂在航线几十单位之上（木星掠距 66.7），全额偏移会把视线抬高几十度 —— 实测地球离画面中心 42°，已经越过 30° 垂直半视场，**主角被顶出画面**。夹住夹角之后：地球最大离轴 17.8°、行星近缘最大离轴 27.6°，两者始终同框（掠过时行星压上半、地球带判定环留在下半，见 `.shots/y2-flyby.png`）。

**尾向观测窗**（代码名仍是 mirror）：单 renderer + `setScissor/setViewport` 画在同一块 canvas 顶部矩形里（不额外开 WebGL context）。矩形位置直接读 DOM（`getBoundingClientRect`），安全区交给 CSS。

- 半径的**唯一真源是 `rKm`（真实 km）**，`rad` 由 `bodyR()` 派生（`FLYBYS` 里只允许写 `rKm`）→ 行星之间的比例与真实严丝合缝：木:土 1.20、天:海 1.03、木:冥 58.9、木:地 10.97，全部有自检断言。**任何单颗行星的尺寸都不允许再手调**。
- 倍率为什么是 **800×**：真值下地球只有 0.0043 单位，必须放大才看得见。倍率是**以地球的观感为锚点**定的 —— 800× 让地球 = 3.41 单位，正好回到手调时代那版 3.4（占屏 13%），主角不再是一颗小球。代价是掠过行星同比放大 2.67×（木星 14.0 → 37.4）。
- **净空随半径等比放大（×2.667）**：`掠过距离 : 半径` 在放大前后完全一致（1.78 / 1.86 / 2.77 / 2.73，有断言）→ 「行星在正前方由小变大、贴着航线呼啸而过」的掠过分镜保持不变，只是整体变大。
- ※ **冥王星是唯一例外**：等比后掠距 19.3 几乎等于相机抬升 `CAM_UP = 20`，相机会从它中心擦过去；把净空单独压到 14.4（掠距 15.0），航线明显从它**下方**掠过（相机离它中心 5.0 单位 = 7.8 倍半径）。
- **土星光环的「穿环」是环面朝向问题，不是尺寸问题**（自检断言）。`RingGeometry` 默认躺在 XY 平面（法线 +Z），代码原先没给它旋转 → 环变成「竖着的圈」，航线恰好从环带内穿过环面：实测环带内最小垂距只有 **0.15 单位**（地球半径 3.41），确实是从环体里穿过去。
- 修法：**把环面摆到土星赤道面**（法线 +Y），并叠加真实**轴倾角 26.73°**（`ring.rotation.x = −π/2 + SAT_TILT`）。同一测法的最小垂距变成 **30.5 单位** → 永不穿环；环带也得以用**真实比例 1.11 ~ 2.27 R**（D 环内缘 → A 环外缘），不必再收窄。ⓘ **2026-09-27 视觉优化**：环带从「一块纯色圆环」改成**按真实环结构画的径向色带纹理**（`satRingTex`）—— D / C / B 环 + 卡西尼缝 + A 环 + 恩克缝，UV 重映射成归一化半径，见最新一条演进记录。自检用与渲染层同一个法线 `RING_NORMAL` 验算这条几何约束。
- **太阳为什么是唯一例外**：同比它会是 0.4655 单位 × 800 = **372 单位**，而航线起点只有 95 单位、氦闪壳从 30 单位起 —— 地球会出生在太阳内部，壳也在太阳内部。故太阳单独取 10 单位（≈真值 21×），自检里有一条专门记录这个「同比会怎样」的断言。
- 门槛整体高于「巡航速度」，**只有吃到弹弓才过得去**（`vSling > vNeed` 有断言）；玩法只看「时间 + 速度」，与半径无关 → 改倍率后通关时间几乎不变（34.5 → 34.7 s）。
- 这五颗是**掠过目标**。太阳系里剩下的内行星（水星 / 金星 / 火星）也在场景里，只是不参与判定，见 §7.6。
- **每颗行星距日 = 真实轨道半径（偏差 < 0.05%）**，HUD 的 AU 读数因此不是摆设。
- 判定点占屏高（实测）：**地球 13.0%**（壳贴脸 8.8%）、木星 100%、土星 92%、天王星 51%、海王星 50%、冥王星 3%。
- 行星变得这么大之后，**注视偏移必须加上限**，否则掠过时视线被抬高几十度、把地球顶出画面（实测离轴 42° > 30° 半视场）→ 见 §6 的 `CAM_PAN_TILT_MAX`。

### 7.3 推力 / 阻力 / 功率 / 温度

| 常量 | 值 | 说明 |

| `DRAG_K` | 0.036 | 阻力 ∝ 速度（时间常数 ~28 s）——不点火会一路掉速 |
| `PWR_MAX / PWR_UP / PWR_DOWN` | 100 / 200 / 200 | 功率（油门）：按住 0.5 s 起转到满额、松手 0.5 s 熄火归零；过热锁定被强制归零 |
| `TEMP_MAX / TEMP_RATE / COOL_RATE` | 100 / 75 / 26 | 温度 = ∫ 有效推力档位（= 输出功率 × 区间效率）：满功率恒温 **1.33 s** 烧穿、冷机起按住 **1.58 s** 烧穿；降温 3.85 s 归零（停机时降温，**过热锁定后强制降温**） |
| `PULSE_TIMES / DUR / WARN` | [12, 26] / 1.0 s / **2.0 s** | 耀斑脉冲：两次，均落在巡航段（点火不作废弹弓）；预警从 0.5 s 提到 **2.0 s** 才够看到并决定按不按 |
| `PULSE_THRUST_BOOST` | 1.6× | 脉冲期推力加成（**同时计入功率档位 → 温升也 ×1.6**） |

**一条链，不是两条线**（2026-09-26 重构）：

```
按住 ──▶ 功率（0.5 s 起转到 100%）──▶ 功率档位 = 功率 × 区间效率 × 乘波
                                   ├──▶ 推力 = THRUST_ACC × 功率档位（绿色区间改由弹弓比例项接管）
                                   └──▶ 温升速率 = TEMP_RATE × 功率档位 ──▶ 温度满 = 过热锁定
```

- **温度 = ∫ 有效推力档位**（`st.thrustEff` = 输出功率 × 区间效率）：把「发热」挂在「出力」上 —— 过晚残效 20% 只涨 15/s（几乎不烫）、额定 75/s、乘波 120/s。旧版这条链是断的：温度恒定 70/s，跟功率表读什么毫无关系。
  ⓘ 2026-09-27：表盘与火焰改读 **`st.pwrOut`（输出功率，与区间无关）**，温升仍按 `thrustEff` —— 两者只在**过晚区间**分叉（表盘满 100%、温升 1/5），这是刻意的：过晚白烧的是**推力**，不是温度（见上一条演进记录）。
- **起转 0.5 s 是刻意的**：功率表因此是一条斜坡而不是开关（按住的每一帧指针都在爬），也让「过早区点一下就跑」变成「点了也还没出力」；同时它把冷机烧穿时间从 1.43 s 推到 **1.58 s**（起转三角只贡献 0.25 s 的等效满功率时间）。
- **乘波要付热度**：脉冲把功率推到 160%，温升随之 ×1.6 —— 冷机按满脉冲 1 s 只到 90（安全），但满功率进脉冲 **0.83 s** 就烧穿。这条把「别在预警期就按住」从口头警告变成了算术。
- **过热 = 强制停机一段**：烧满不是「你松手就没事」，而是**发动机停机 `TEMP_MAX / COOL_RATE` = 3.85 s** —— 这段时间里功率与推力恒为 0，按不按都一样（点了也不会升温、不会重新起转、更不打断降温），降到 0 才解锁。旧规则「按着不降温、必须松手」只是把抬手动作本身当成惩罚，现在惩罚落在**时间**上：3.85 s ≫ 任何一颗行星的窗口（2.5–2.8 s），所以窗口里烧穿 = 这一站报废，与手指怎么放无关。

**温度预算与窗口的互锁**（自检**逐行星**断言，因为窗口与区间都是逐行星的）：
- 冷机在窗口起点一路按住（`起转三角 + 满功率段` = 1.58 s）< 该行星窗口时长 → 窗口中全程死按必然烧穿；
- 冷机只按住该行星**整段绿色区间**（最长 1.23 s）→ 温度只到 **73.7 / 100** → 规规矩矩按绿色区间不会过热。
这两条把「过早」变成一个真实的资源惩罚，而不是文案。另外两条守脉冲：冷机按满 1 s 脉冲 **90 < 100**（按提示操作是安全的）、满功率进脉冲 **0.83 s < 1 s**（提前按住必烧穿）。

### 7.4 时机窗口与弹弓：**每颗行星不同，由质量派生**

窗口与最佳区间不是全局常量。引力强度取**真实质量 + 真实半径**推出的表面逃逸速度

|---|---|---|---|---|---|---|---|---|
| 木星 | 317.8 | 60.20 km/s | 1.000 | **2.80 s** | 46.0% → 90% | 1.232 s | 1.67 /s | 0.59 s |
| 土星 | 95.2 | 36.10 | 0.591 | 2.68 s | 52.5% → 90% | 1.003 s | 2.05 | 0.48 s |
| 海王星 | 17.15 | 23.56 | 0.379 | 2.61 s | 55.9% → 90% | 0.890 s | 2.31 | 0.43 s |

| 冥王星 | 0.00218 | 1.21 | 0.000 | **2.50 s** | 62.0% → 90% | 0.700 s | 2.94 | 0.34 s |

> 表内数值按两位小数四舍五入；全精度：海王星 `gravQ = 0.3789`、`sweet0 = 0.5594`、`slingK = 2.3138`；天王星 `slingK = 2.3648`（≈2.36）；木星 `ratingSweet = 0.5914`、冥王星 `0.336`。

| 派生式 | 值 | 说明 |
|---|---|---|
| `gravQ` | (v_esc − min) / (max − min) | 引力强度归一化（min / max 由五颗实测 v_esc 扫出） |
| `winTime` | `2.5 + 0.3·gravQ` | 引力越强，窗口越早亮灯 |
| `sweet0 / sweet1` | `0.62 − 0.16·gravQ` / `0.90` | 引力越强，绿色区间越宽（起点更早） |
| `slingK` | `2.06 / 区间时长` | **反向补偿**：吃满的弹弓逼近量对五颗都是 **87.3%** |
| `ratingSweet` | `区间时长 × 0.48` | 「完美弹弓」= 把**该行星**的绿色区间吃满 |
| `LATE_EFF` | 0.2 | 过晚区间点火的残效 |
| `CRASH_RATIO` | 0.72 | `v < vNeed × 0.72` → 撞毁，否则被捕获 |

- `tToGo = (s_i − s)/v`，`phase = 1 − tToGo/winTime`，`phase < 0` 尚未进窗、`> 1` 已过判定点。
- **按质量，不按轨道顺序**：海王星（17.15）比天王星（14.54）重，所以它的窗口与区间都不小于天王星 —— 走在外圈的它反而比前一站好抓一点，这是数据而不是手感调参（有断言）。
- **窄区间只是「更难按准」，不是「吃满更亏」**：`slingK` 按区间宽度反向补偿后，吃满区间得到的速度增益逐行星完全一致 → 通关时间与氦闪壳曲线都不用重标（自检里有一条专门断言这个不变量）。
- **弹弓为什么用「比例项」而不是「固定 Δv」**：固定 Δv 会让速度形成正反馈（吃过弹弓 → 下一次弹弓更值钱 → 强者愈强），属「一次失误即宣判」。改成 `a = slingK·(vSling − v)` 后，逼近量随缺口自动放大，**落后可以追回**，斜率变平缓。实测梯度（口径 = 绿色区间只按前 X% 就松手、之后不再按；见 §3 表）：吃满 **34.7 s** 逃出；75% → 38.3 s 逃出（末站余量只剩 2.8 s）；55% → 进度 58.7% 被壳追上（27.3 s）；35% → 进度 35.8% 被壳追上（19.6 s）。

### 7.5 氦闪壳

`shellR(t) = SHELL_START + A·t + B·t²`（**解析式**，不逐帧积分 → 标定容易、断言容易、天然帧率无关）

| 常量 | 值 |
|---|---|
| `SHELL_START` | 30 |
| `SHELL_A` | 48.22 |
| `SHELL_B` | 1.6282 |

按「满弹弓参考轨迹 + 逐站留余量」拟合。**余量的口径**（可复算）：在该次掠过的那一刻起**彻底熄火**，壳还需多少秒追上 —— 满弹弓逐站 = 木星 3.9 / 土星 7.8 / 天王星 8.7 / 海王星 7.3 / **冥王星 2.6 s**（最紧的是末站：前面吃得再满，最后一段也只剩不到 3 秒缓冲）。对照：绿色区间只按前 75% 的打法仍是 38.3 s 逃出，但末站余量缩到 2.8 s；只按前 55% 在**天王星与海王星之间**被吞（27.3 s、进度 58.7%），只按前 35% 更早 —— 在**土星与天王星之间**就被吞（19.6 s、进度 35.8%）。壳因此是一条真实存在的第二死线，不是背景板。

### 7.6 场上的其他行星（不参与判定）

掠过名单只有五颗（火星的站台只在航线 `s = 67` 处、窗口来不及亮，见 §5.3），但**太阳系不能只剩五颗球**：
水星 / 金星 / 火星按真实半径（同一 `BODY_SCALE`）与真实轨道半径摆进场景，只是没有判定点、
没有加速窗口、不检测碰撞。

| 天体 | 真实半径 | `rad`（×800） | 真实轨道 | 摆位方式 |
|---|---|---|---|---|
| 水星 | 2440 km | 1.30 | 0.387 AU | `behind`：在航线起点内侧 → 摆在地球起点同一方位角的黄道面上 |
| 金星 | 6052 km | 3.24 | 0.723 AU | 同上 |

- **内侧行星在正前方本来就看不到**（它们在地球身后）：靠顶栏左侧的**尾向观测窗**与右端的**导航图**读出来，导航图上永远有两个点在太阳旁边。

## 8. 判定与评级

| 条件 | 结果 |
|---|---|
| `s ≥ route.len` | **escaped** 冲出太阳系 |
| `距日 < shellR` | **burned** 氦闪吞没（速度欠账的最终收款人） |
| 判定点 `v < vNeed × 0.72` | **crashed** 被拽入行星大气层（低到连大气层都擦不过去） |
| 判定点 `v < vNeed` 且**这一关的窗口根本没碰**（`early ≈ 0` 且 `sweet ≈ 0`：只在过晚区间点、或完全没按） | **caught** 被行星引力捕获（即时失败） |
| 判定点 `v < vNeed` 但**推过了**（过早白烧 或 绿色区间吃到过一点） | **slow**（评级卡写「轨道速度不足」）—— 地球照常掠过，**不在这里判死**，欠账交给氦闪壳在后面追讨（延迟失败） |
| 判定点 `v ≥ vNeed` | 通过；**未作废弹弓** 且 `最佳区间累计点火 ≥ 该行星 ratingSweet` → **perfect**，否则 **pass**（作废后最高 `弹弓增益损失`） |

**两种失败模式按原因分开**（这是设计意图，不是同一件事的两个名字）：

- **过晚 / 没按** → 这个窗口白白错过，速度根本没拉起来 → 这颗行星**当场抓住你**（`caught`；低到 `vNeed × 0.72` 以下则 `crashed`）。
- **过早过多** → 在「过早」区间（`zone === 'early'`）点过火——**哪怕只有一帧（1/120 s）**——就把该行星的 `lostSling` 置真，本掠过余下时间 `st.slinging` 恒为 false，续进绿色区间也只给普通推力（9 单位/s² × 功率档位，而温度总额只够满功率连点 1.33 s、冷机起 1.58 s）→ 判定点速度掉到门槛之下，但地球**照常掠过**（记为 `slow`），代价改由身后的氦闪壳结账。

**过早的代价是「被太阳追上」，不是当场终结**（逐颗实测：该颗窗口内全程死按、其余按理想打法，记判定点速度 vs 门槛）：木星 **83.5 / 98**、土星 123.9 / 130、天王星 128.1 / 138、海王星 127.4 / 138、冥王星 **133.1 / 132**（外圈窗口又短又靠后，前面吃满的话这里反而压线掠过）—— 常规推力的天花板把前四颗卡在门槛之下、撞毁线之上，于是地球带着这份欠账继续跑：**「过早 1 帧」发生在前 3 颗行星上，整局都会拖到 30 s 之后才被壳追平**（木星 32.3 s / 进度 76%、土星 36.7 s / 93%、天王星 36.9 s / 94%），而不是旧版 5.6 s 处当场被行星抓住；外圈（海王星 / 冥王星）若前面跑得够好，欠账还追得回来（37.7 s / 35.4 s 逃出）。同一颗行星上连续两次过早（比如木星 + 土星都烧废）才会掉到撞毁线以下 —— **全程只在过早区点火**实测在 **土星处撞毁**（11.9 s、进度 20%）。

**掠过后即时评级**（`gradeFlyby(r, ok, ratingSweet)` 纯函数）：把「过早 / 绿色 / 过晚」三个区间的实际点火时长翻译成**等级 + 一句可执行的提示**，渲染层再补上 `绿色区间 X s / 完美线 Y s` 那一行（提示里因此不再重复「绿色区间」四个字）。等级文案与 `key`（决定配色）**全部以代码为准**：

| 判定顺序 | 情形 | 等级（`label`） | `key` / 颜色 | 提示（`tip`） |
|---|---|---|---|---|
| 1 | `r.result === 'slow'`（推过了但没过门槛） | **轨道速度不足** | `early` / 琥珀 | 弹弓增益已作废。轨道速度欠账，氦闪前壳正在逼近。（未作废时说「轨道速度欠账未弥补」） |
| 2 | `!ok`（判定点没过门槛、且窗口根本没碰） | **引力捕获** | `fail` / 红 | 通过判定点速度低于逃逸门槛。引力窗口内必须吃满推力。 |
| 3 | `lostSling` + 只在过晚区点 | **点火延迟** | `late` / 红 | 窗口已关闭，残余推力不产生轨道增量。 |
| 4 | `lostSling` + 一次没按 | **发动机未点火** | `none` / 红 | 全程未点火。轨道速度被星际阻力耗散。 |
| 5 | `lostSling` + 只有过早区 | **无效点火** | `early` / 琥珀 | 全程窗口外点火。弹弓增益作废，发动机温升超限。 |
| 6 | `lostSling` + 绿色也吃到一些 | **弹弓增益损失**（封顶） | `good` / 命中绿 | 过早点火，本次弹弓增益作废。绿色窗口开启前禁止点火。 |
| 7 | `sweet ≥ ratingSweet` | **完美弹弓** | `perfect` / 金 | 引力弹弓增益已拉满，轨道速度达标。 |
| 8 | `sweet ≥ ratingSweet × 0.45` | **弹弓增益未满** | `good` / 命中绿 | 弹弓增益未满。绿色窗口内保持推力更久。 |
| 9 | `sweet > 0` | **提前点火** | `early` / 琥珀 | 窗口外点火不增益，发动机温升无效。 |
| 10 | `late > 0` | **点火延迟** | `late` / 红 | 窗口已关闭，残余推力不产生轨道增量。 |
| 11 | `early > 0` | **无效点火** | `early` / 琥珀 | 全程窗口外点火。弹弓增益作废，发动机温升超限。 |
| 12 | 都不满足 | **发动机未点火** | `none` / 红 | 全程未点火。轨道速度被星际阻力耗散。 |

- 共同规律：**只要 `lostSling` 为真，最高只能到「弹弓增益损失」（`good`）** —— 绿色区间吃满了也给不了「完美弹弓」；`ratingSweet` 逐行星不同，所以同样 0.45 s 的绿色区间点火，在冥王星算吃满、在木星只算「弹弓增益未满」（自检有一条专门断言）。
- 失败原因文案（`st.reason`）也按因果分叉：吃过 `slow` 的局被壳追上时写「**轨道速度不足，地球被氦闪前壳追上**」，否则写「地球被氦闪前壳吞没」；被行星抓住写「轨道速度不足，被<行星>引力捕获」，再低一档写「轨道速度不足，坠入<行星>大气层」——玩家一眼能看出是被自己的过早烧没的。
- 评级由渲染层**轮询「已出结果的数量」**触发（不是比对 `st.target`）——因为失败那次 `target` 不再前进，只有按结果计数才捕捉得到，玩家才不会「死得不明不白」；评级卡 3.2 s 后淡出，被捕获 / 撞毁那次不弹（由结算页解释）。

| 结算 | 全屏 | 终端任务报告：标题栏 `MOSS · 航迹记录` + **大号用时**（成功 = `逃逸用时`／失败 = `航至`，**两位小数**）+ **最快记录**（同样两位小数，比较与落盘也按这两位） + **四行注脚清单**（名目 …… 数值，点线引导）+ 分享 / 再来一次 |

**布局分区：顶部只放「非驾驶」信息，底部整条带是信息栏 + 时机条 + 消息提示。**

- **顶部** = **一条顶栏 `#topbar`**（`left/right:12px`，`top: --top-gap + 14px + --sat`，flex 两端对齐）：左「**尾向观测窗**」方形 ┊ 中「计时」┊ 右「**导航图 + 声音键**」竖列。三块原本各自 `position:fixed`（三处 top/left 各写一遍），2026-09-26 收成一条 —— 左右两块共用 `--top-sq`（80×80）自然对称，中间的计时 `flex:1` 吃满余下宽度 = 天然居中，整条只叠一次 `--top-gap` 与安全区。320px 上中间那格只有 `320 − 24 − 80 − 80 = 136px`，**这就是「方形窗只能 80px、计时只能 36px」这道题的题面**：想再大就得先动 `--top-sq`，而它同时决定中间那格的宽度。ⓘ 2026-09-27 定稿实测（390×844）：观测窗 `12–92`、计时文本 `157–233`（= 屏幕正中 195）、导航图与声音条 `298–378`，两块标识同在 `y=66`（各自离组件左缘 2px）；320×568：观测窗 `12–92`、导航图 `228–308`、计时文本 `101–219`（36 / 18px 时文本 118px < 中间格 136px；同日把三位小数收成两位，文本更短）—— 两档都左右严格对称、互不重叠。ⓘ 同日还做了两件事：两块显示窗**去卡片化**（撤描边 / 投影 / 窗下那条 80×26 标签条），标识**嵌进画面顶部左上角**（尾向观测从两行收成单行 `▍尾向观测`）；退场类 `.hide` 从 canvas 挪到整块 `#radar-wrap` —— 两块显示窗的显示 / 隐藏从此完全一致（旧版简报、结算盖上来时「导航图」三个字会留在屏幕上）。ⓘ 更早的 2026-09-26 数值（计时 23/12px、观测窗 120×62 横窗、标签在窗下）已作废，见本文末尾演进日志。
- **底部 `#cockpit`**（`left/right:14px; bottom:14px + var(--sab)`，flex 纵排）：`#cockpit-stage`（**时机条 + 与它同带的零高度消息槽**）→ `#dash`（**两排的信息栏**：上排 = **控制台两列**【表盘 │ 参数】，下排 = 逃逸进度独占一行）。窗口开合与提示出现都**不改动下方几何**（时机条与信息栏是常驻盒子，`.hide` 只改透明度；消息槽高度为 0），所以没有任何跳动。ⓘ 2026-09-26 实测：320×568 的 `#dash` = **112px**（上排高度由参数列 75px 决定）、390×844 = **119px**，地球与掠过行星整颗露在两条之上（那一版的表盘 59 / 64px，见下一条的 2026-09-27 调整）。
- **信息栏为什么从三列退回两列**：三列那版（表盘 │ 参数 │ 雷达）里雷达只有 42px，点与线小到读不出位置，于是**导航图搬到顶栏右列（80px 方窗）**，信息栏只剩两列 —— 高度一点没变（仍由参数列 75px 决定），空出来的宽度全归表盘。**参数列的宽度是反推的**：`距日` + `4.19 AU` 实测要 67px，所以列宽 `min-width:76px`（窄于 76px 时实测 `scrollWidth-clientWidth > 0`，数字会压出面板右缘）；ⓘ 2026-09-27：上限收到 **96px**、表盘上限 64 → **70px**，并把三张盘在列内**居中**（`justify-content:center`）—— 旧版吃满上限后余量全堆在右侧，三张盘看着是「贴左的一坨」。实测 390：表盘 70px 一格、列内两侧各余 7px；320：表盘铺满列宽。

**为什么必须这样**：点火窗口只有 2.5–2.8 秒，玩家要在同一个瞬间比对「判定针在哪一段」「温度还剩多少」「速度够不够门槛」「发动机这一刻出了多大力」。旧版把仪表盘放在右上角、时机条放在屏幕中下，等于逼玩家在 0.2 秒里做完一次上下半屏的眼动 —— 这不是难度，是设计缺陷。现在这四件事落在同一条水平带上，一眼扫完。

### 9.1.1 仪表盘：为什么从「文字遥测」改成「盘型指针」

旧版右上是一块四行文字（速度 / 距日 / 距壳 + 一条温度条）。玩家在点火瞬间只会**余光**扫一眼仪表 —— 而「现在多快 / 多烫 / 发动机多大力」用数字表达，余光读不出来。改成汽车驾驶舱的读法（**并且放在时机条正下方**，见 §9.1 的布局理由）：

- **功率 / 温度 / 速度 = 三个 270° 表盘**（弧长 `2π×38×¾ = 179.1`），指针角度与值弧长度同时表达同一个量；值弧走 `stroke-dasharray / dashoffset`，指针走 **SVG `rotate(a,50,50)` 属性**（不是 CSS `transform`：Chrome 61 的 SVG 要用 CSS transform 还得有 `transform-box` / `transform-origin`，属性变换是 SVG 1.1 就有的）。三张盘满量程各不同：**功率 160%**、温度 100%、速度 80 km/s。
- **顺序 = 驾驶时的手上顺序**：`功率 → 温度 → 速度`。按下去那一瞬玩家问的第一个问题是「这一下出了多大力」（功率表同时是「按住多久」的反馈），第二个是「烧到哪了」（温度 = ∫ 功率，是功率的账），最后才是「够不够门槛」（速度与门槛刻度）。改顺序只动 DOM，JS 全按 id 取，自检里有一条锁 DOM 次序。
- **值弧必须写 inline style，不能写表现属性**（2026-09-26 实测踩到的历史 bug）：`.dg-arc{stroke-dashoffset:179.1}` 是 CSS 声明，而 **CSS 声明永远压过同名的 SVG 表现属性** —— 旧写法 `arcEl.setAttribute('stroke-dashoffset', …)` 属性确实在变，但 computed 恒为 179.1px，**三条值弧一辈子是空的**，表盘上只剩指针在动。现在 `gaugeSet` 写 `arcEl.style.strokeDashoffset`（CSS 里那条 179.1 退化成首帧基线），自检同时锁两头。
- **速度满量程 80 km/s**：实测满弹弓全程峰值 67.1 km/s、开局 37.0 → 指针常驻表盘 46%–84%，顶部留得住余量（真被顶满也只是指针贴死上限，数字读数仍是真的）。
- **门槛刻度**（`#dg-tick`）：当前行星的判定速度在表盘上的位置，速度够了转绿、不够转红 —— 汽车仪表盘上那道「红区」的等价物，取代了旧面板里「速度 X / 门槛 Y」的对照关系。没有目标行星时整根刻度淡出。
- **功率表（`#dg-pw`，发动机输出功率）**：读数取自物理核心的 **`st.pwrOut`**（= 油门 × 脉冲乘波，**与区间、与弹弓都无关**；没按住 / 过热锁定由核心直接归零）。ⓘ 2026-09-27 之前读的是 `st.thrustEff`（= 输出功率 × 区间效率），过晚区间因此被画成 20% —— 那是**推力残效**，不是发动机出了多少力，玩家反馈后拆成两个量：

  | 状态 | 读数 | 颜色 |
  |---|---|---|
  | 停机 / 过热锁定（`idle`） | 0% | 灰（指针与值弧一起转灰） |
  | 过晚区间（`weak`） | **100%（读数不降级）** | 红 —— 「这一份功率兑不出推力」在表上看得见（2026-09-27 前这里是 20%，那是推力残效，不是发动机出了多少力） |
  | 巡航 / 过早 / 引力窗口（默认） | 0 → 100%（按住 0.5 s 起转到额定线） | 主绿（= 额定推力） |
  | 耀斑脉冲乘波（`boost`） | 最多 160% | 琥珀（与 `耀斑` 灯同色，指针推过额定线） |

   **刻度换算**：`st.pwrOut` 是**小数**（1.0 = 额定），指针位置 = `pwrOut × 100 / PWR_VMAX` → 100% 落在额定线（弧长 62.5% 处）、160% 顶满到 +135°、0% 回到 -135°。**历史 bug**（2026-09-26 实测抓到）：旧写法直接 `power / PWR_VMAX` = 1/160 = 0.006 → **指针全程只转 1°**，看着像「指针不会动」（采样：读数 29 → 66 → 96 → 100，指针 -134.5° → -133.3°）。数字读数一直是对的（`Math.round(power * 100)`），只有指针被这层换算漏掉了。
  满量程取 **160%** 而不是 100%，就是为了让「乘波」成为一个**指针动作**（推过额定线）而不是一次数字跳变；额定 100% 处放一道细刻度（`.dg-ref`，中性灰，不参与红绿语义）。另外它天然是**「按住多久」的反馈**：按住指针 0.5 s 爬到额定线、松手 0.5 s 落回 0 —— 而**温升就是按有效推力档位（`st.thrustEff` = 输出功率 × 区间效率）积出来的**，两者只在过晚区间分叉（表盘满、温升 1/5），所以「指针越高越烫」在正常区间仍是玩家能直接读到的因果，不必背文案。`.weak`（红）只按**区间**判（`zone === 'late'`），不按读数大小判 —— 否则每次按住的起转前 0.25 s 都会闪一次红，那是正常起转、不是白烧。
- **四盏警报灯**（2×2，都在参数列）：`过热`（温度 >85% 或过热锁定转红、>70% 转琥珀）/ `弹弓`（绿＝弹弓正在生效、红＝本次掠过已作废）/ `耀斑`（琥珀，脉冲预警与生效期）/ `氦闪`（距壳 <28 AU 琥珀、<12 AU 红闪）。**灯只回答「有没有事」，「该怎么做」仍然归底部消息槽** —— 两者分工，不叠字。
- 指针踩进最佳区间时，速度表整表转绿（与 3D 判定环、时机条、全屏呼吸光同一套时机轴颜色）。

### 9.1.2 开场简报 / 结算：**整屏终端骨架**（`.scr`）

2026-09-26 改版：这两页不再是「居中一张卡片」（旧版是 352px 圆角卡片 + 1px 边框 + 四角折角 + 三颗窗口圆点 + 投影 —— 那是宿主里一个对话框的样子），而是**整屏终端本体**。共用一套骨架，只有正文不同：

| 层 | 元素 | 职责 |
|---|---|---|
| 屏顶 | `.scr-top` | 方形指示灯 + 标题（简报 = `流浪地球 · 引力弹弓`，结算 = `MOSS · 航迹记录`）+ 右端三根递增高的小竖条（一台在线终端的读数）。下面是**一条通宽细线** |
| 正文 | `.scr-body` > `.scr-wrap` | 简报 = 标题 → 扁版航线示意（`viewBox 210×86`）→ **三条 MOSS 输出 + 一条「你」**（`$ 你：选定点火时刻`）→ 三步操作卡；结算 = 状态行（`冲出太阳系` / `逃逸失败`）→ 用时读数 → 收尾句 / 失败原因 → 四行清单 → 分享提示。`overflow-y:auto` **自己滚动**；`.scr-wrap{margin:auto 0}` 让内容少时垂直居中、内容多时从顶部开始并可滚动 |
| 屏底 | `.scr-foot` | 上面**一条通宽细线**，主按钮钉在这里（简报 1 个 = `点火启航`、结算 2 个 = `分享战绩` + `再来一次`） |

**结构上不可能再「按不到按钮」**：正文溢出只滚正文，按钮是 `flex:0 0 auto` 的独立一层（旧卡片版靠把整块压进 498px 预算来保证，那一版实测 320×568 面板 478px）。（三层外面原还有一层 `#brief::before` / `#result::before` 的整屏扫描线，**2026-09-27 已删** —— 全站不再有模拟扫描横条。）

实测（Chromium）：
- 320×568：简报正文几乎占满，按钮 505–550；结算正文到 y≈380，按钮 505–550。
- 390×844：正文块在状态行与动作区之间**垂直居中**，不再在底部空一大片。

排版细节（都是这一版新增的「终端」理由）：

- **一律左对齐**：标题、MOSS / 你 两行、三步卡、结算状态行与清单全部左起。终端输出不居中，居中读起来像卡片。
- **块内不再套盒子**：`.bf-term` 只留左缘一条竖条（原来还有一圈边框 + 圆角），整页只有「屏顶线 / 屏底线」两条通宽细线。
- **右端是信号条不是窗口圆点**：三根递增高的小竖条（4 / 7 / 11px），是「终端在线」的读数；三颗等大圆点是「对话框」的语言，已删。

篇幅契约仍然保留（自检逐条锁死）：`.bf-step` 内不得出现 `<i>`（三条指令各占一行）、示意图 `viewBox` 高 ≤ 90、简报可见正文 ≤ 125 字（现 **119**）。骨架虽然不再逼着省高度，这些约束仍防止「又变回一张卡片」——`@media (max-height:520px)` 下依旧撤掉示意图。

**配色语义（两条互不争用的轴）**：

- **时机轴 = 绿 / 红**：绿色 = 命中区 —— 时机条的绿色区间（`引力窗口`）、判定针、命中态 tag、全屏呼吸光、3D 判定环（`0x7fd0a8`）、速度表踩进区间时的整表转绿，全部同色；红色 = 危险（过晚、速度不足、氦闪逼近）。绿／红构成红绿灯对照，余光扫到即可判读。
- **评价轴 = 金**：金色只出现在**掠过之后与结算页**（完美弹弓、逃逸用时、新纪录），表达「最高评价 / 荣誉」。旧版金色同时承担「该按了」与「最高评价」两件事，掠过后与局内的金色无法区分；拆开后两个轴不再共用颜色（自检逐条列出 `var(--gold)` 的选择器并断言全部落在评级／结算）。

顶部安全区三重叠加，缺一层就会出问题：`--top-gap:50px`（无条件常量，避让宿主顶部按钮）＋ `--sat/--sab = var(--safe-area-inset-*, env(..., 0px))`（刘海 / 手势条）＋ 每个元素**先给一条纯像素基线、再给一条 `calc(var(--top-gap) + Npx + var(--sat))`**；Chrome 61 丢弃 `calc` 行后自动回落基线，无需兼容分支。**`--top-gap` 全文只由 `#topbar` 一条承载**（简报 / 结算的 `.scr` 骨架另用它做 `padding-top`）：2026-09-26 把顶部三块收进同一条 flex 之前是 `#clock / #mute / #mirror-frame` 三处各写一遍，漏一处就等于把那个元素送进宿主顶栏。自检同时锁两条反向契约 —— 进度与导航图**不得**再出现 `var(--top-gap)` 或 `position:fixed`（导航图的 `--top-gap` 由 `#topbar` 统一叠）。

### 9.1.3 视觉语言：MOSS 舰载终端

整屏按「MOSS 电脑终端」统一，**纯 CSS，不引入任何新 Web API、不改任何分区**：

| 件 | 做法 | 理由 |
|---|---|---|
| 字体 | 全站等宽：`ui-monospace → SFMono-Regular / Menlo / Consolas / Liberation Mono / DejaVu Sans Mono → PingFang SC / Microsoft YaHei → monospace` | 等宽是「终端」最直接的一眼信号；中文没有等宽字形，靠系统黑体兜底，西文（数字 / 单位 / 版本号）才是真正等宽的那部分 |
| 屏质感 | **只有暗角**：`body::after`（`radial-gradient` 暗角，`z-index:6`，压在 3D 之上、HUD 之下）。**全站扫描横条一律没有** | ⚠ 2026-09-26：原先还有一层 `body::before` 全屏扫描线，但 3D 画面会透过半透明仪表盘（`--panel` alpha .80）显出来 → **操作界面看起来自带一层横条纹**（反馈原话「操作界面不要加横线滤镜」），故整层撤掉。⚠ **2026-09-27**：简报 / 结算 / 加载三块整屏自带的那层 1px 扫描线也按反馈一并删了（「所有界面的模拟扫描横条」）—— 终端质感现在完全由等宽字、字距、提示符与细边承担 |
| 面板 | `--panel` 半透明底 + 1px `--line` 细边（**方形折角已删**，2026-09-27） | 时机条与消息卡走的是**无框暗玻璃板**（圆角 8px、一条装饰线都不留，见 §9.1）；`#radar` 是 `<canvas>`，原先那圈 `box-shadow` 描边 2026-09-27 也撤了 |
| 标签 | 一律宽字距；表盘格写 `[功率] / [温度] / [速度]`、评级写 `[完美弹弓]`（方括号由 CSS 加，DOM 里是干净的两字标签） | 括号是终端里最常见的信息包裹方式，且**不占用 DOM 文本**（`.bf-step` 内不得出现 `<i>` 那条契约因此不受影响） |

### 9.2 星空（三个已踩过的反例）

统一根因：相机在半径 16000 的天球内部，屏幕只截取约 60° 视场，**贴图纹素会被放大到数像素**。

1. 星点画进天球贴图 → 放大 2.3 倍，1px 星点变模糊光斑；
2. 改用点精灵但 `STAR_SIZE = 3.5`、贴图中心画成纯不透明白 → 双线性采样永远只落在纹理正中心 → 满屏**「白色方格子」**；
3. 星点修好后，底色渐变与银河雾仍留在贴图上 → 8bit 色阶被拉成等距横条、雾的合成台阶被放大成斜向网格 —— 又一片方格。**提高分辨率只能把格子等比缩小，根除不了**。

结论（均有断言）：**天球一律用顶点色，不用贴图**；**点精灵 `size ≥ 8px`**（`size` 是给渐变留的画布，画布太小就只剩中心那点纯白）；颜色按线性空间给（要过 ACES，暗部 <0.002 直接压成纯黑）。

### 9.3 地球与发动机

- 地球 = base64 贴图 + 冷色 tint + 程序化冰封壳 + 稀薄云 + 大气壳。
- 48 台行星发动机按**环式阵列**（中心 1 台 + 4 圈同心环 1 / 5 / 11 / 16 / 15，极角 0° / 40° / 60° / 74° / 83°）分布在**背面（−Z 半球）**，安装半径 `1.08 R`（> 大气 1.06 R 不穿模）；**喷流一律平行朝后**——历史 bug 是取球面法线朝外，赤道附近与 −Z 夹角达 87°，净推力只剩 0.53（现在是 1.000，有断言）。2026-09-27 之前是黄金角螺旋均匀撒点，读不出「阵列」；改环之后最外圈 `sin83° = 0.993` 正好压在地平边缘，就是参考图里那圈亮环。
- 地球朝向 = 航线切向（`slerp` 平滑），镜头正对背面，因此 48 台发动机（深色喷口 + 蓝白等离子柱 + 口面光点）常驻画面。

### 9.4 BGM 与音效

- **BGM 为什么内联成 `.js`**：小工具容器上传白名单不收音频扩展名，且 `file://` 下 `<audio>` / `fetch` 会被跨域拦。做法同 `vibegame/perler-bead-game/bgm.js`：整曲 base64 藏进 `assets/bgm-data.js`，运行时 `atob → Uint8Array → AudioContext.decodeAudioData`，**全程不产生任何 URL**。源 `d8badba2214c66d62989f41c4000a402(1).mp3`（MPEG2 Layer III · 64 kbps · 24 kHz · 约 125 s · 974 KB → base64 1298 KB），由 `tools/make-bgm-data.mjs` 生成。
- **循环不用 `src.loop`**（接缝会「咔哒」），改为手动排期：每遍提前 3 s 起下一遍，交叠处一条淡出对一条淡入。
- 首次触摸解锁音频上下文；顶栏右列那枚 ♪（导航图下方）的开关状态写入 `localStorage`；切后台 `suspend()`、回来 `resume()`。
- 音效仍是程序化 WebAudio：点火隆隆、脉冲爆音、过热告警、冷却归零、掠过评级音（按等级分双音/单音/失败音）、胜负音。

## 10. 分享战绩

按官方文档（[小工具容器能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)）走**容器注入的 JS API**，不做 UA 判断。文档里**没有**独立的 share API；§3.2 一览中唯一标注「分享」的能力是 **§3.9 `interactionOpenApi`**（携带评论草稿唤起评论区，客户端 9.49+），因此以它为首选，§3.3 `postNote`（唤起笔记发布页）作为低版本回退：

```js
// 首选 §3.9：图文评论草稿 + 同步存相册
await window.xhs.miniTool.interactionOpenApi({
  payload: {
    action: 'post_comment',
    content: 战绩短文案,
    media_bean: [{ media_type: 'image', cover_image_url: filePath }],   // 只收本地文件句柄
    miniToolSnapshotInfo: JSON.stringify({ page: 'result', t, perfect, ... }),
  },
  saveToAlbum: true,
});
// 回退 §3.3：拿不到 interactionOpenApi（客户端 < 9.49）时发笔记
await window.xhs.miniTool.postNote({
  title, content, pageType: 'photo_publish',
  mediaInfo: { image_resources: [{ url: filePath || dataURI }] },
});
```

- **图片先换成本地句柄**：`writeTempFile({ data })` → `filePath`。§3.9 的 `media_bean` 只接受容器可访问的本地文件句柄（`data:` URI / 网络地址 / 绝对路径都不可用）；§3.3 的 `image_resources.url` 两种都收，所以只有发笔记这条退路才会把 data URI 直接交出去。
- **手势要求 ⇒ 提前备图**：§3.9 要求「用户点击等主动操作触发」，且容器会**先关闭小工具再拉起评论区**，所以配图由 **Canvas 现画**的「战绩卡」（900×1200，**不引用任何外部图片**）在**结算页亮出来时**就画好、落好盘；点击时直接带着现成句柄发起，不把异步步骤夹进手势栈里。点得太快没备好时才补一次 `writeTempFile`，补不上就回退发笔记。
- **战绩卡的版面**（自上而下）：`流浪地球 · 引力弹弓` → 状态标签（赢 = `逃逸用时`、输 = `航至`）→ **用时巨字（数字 + `秒` 按 `measureText` 实测宽度整体居中，2026-09-27 修）** → 状态句（赢 = `逃逸成功`、输 = **核心给出的真实死因 `st.reason`**：被某颗行星捕获 / 坠入大气层 / 被壳追上 / 被壳吞没）→ 最快记录与完美弹弓计数 → **五颗行星的评级色标**（点 = 评级色，标签写**全名** `木星 / 土星 / 天王星 / 海王星 / 冥王星`，2026-09-27 修 —— 旧版取行星名末字，五颗全印成同一个「星」；全名实测最长 66px < 点间距 132px，留 66px 间隙）→ 挑战文案 → 一句「去哪儿找这个工具」。**卡上不带任何 `#` 话题标签，分享文案同样不带**（2026-09-27 按反馈删掉）。
- **版本判断照 §3.6**：`buildVersion` 末三位是编译序号，先 `/1000` 取整再比；同步读 `window.xhs.launchOptions.miniToolEnv.buildVersion`，缺失才异步 `getLaunchOptions()`。门槛 `9490` = 客户端 9.49。取不到版本时以「方法是否存在」为准 —— 低版本客户端本就不会注入该方法。
- **分享文案只讲成绩**（2026-09-27 两轮改写的结论：**不写玩法介绍、不写教程、不写「去哪找」** —— 那些与「分享成绩」无关；三处都不带 `#` 话题标签）：
  - **标题**（`postNote` 上限 20 字）= 一行成绩卡：赢 `逃出太阳系 · 34.66 秒`；输 `止步木星 · 5.75 秒`，被壳追上的那档写 `被氦闪追上 · 27.30 秒`（死因取 `st.culprit`，`太阳` 不写成「止步太阳」）。最长 15 字，留得住余量。
  - **正文** = 三行封顶：成绩（赢 = `把地球开出太阳系：X 秒 · 完美弹弓 k / 5`；输 = `第 X 秒，被<行星>引力捕获`）→ 纪录行（只有「赢了且这一局就是纪录」才写 `★ 新纪录 X 秒`，否则写 `我的最快记录 X 秒`；**输的时候报的是自己的 PB，不是本局**）→ 一句挑战 `看谁更快。`
  - **评论草稿**（§3.9 评论区收短文本）= 一句话成绩（`我把地球开出太阳系用了 X 秒（完美弹弓 k / 5）` / `第 X 秒，被<行星>引力捕获`）+ `看谁更快。`
  - **死因说人话**：`被<行星>引力捕获` / `坠入<行星>大气层` / `被氦闪前壳追上`；`st.reason` 那句完整死因（`轨道速度不足，……`）只留给结算页。战绩卡上那句「小红书小工具 · 搜…」属于**图片**、不在这份文案里（要一并删也可以，说一声）。
- **能力检测在调用时做**：§3.1 要求「调用前用 `window.xhs && window.xhs.miniTool` 判空」，所以不缓存脚本加载那一刻的 `window` 状态；每次点击重算分享模式，按钮文案在 `分享到评论区 / 分享到小红书 / 分享战绩` 之间切换。
- 上限守卫：`title` ≤ 20 字、`content` ≤ 1000 字（主动裁剪）；`miniToolSnapshotInfo` 只有几十字节（§3.9 上限 2KB，文档未给读回入口，这里只负责写入）。
- 结果语义（文档明说）：`postNote` 成功只代表**发布页被唤起**、不代表过审；§3.9 的 `routed` 只代表评论侧路由成功 —— 提示文案只写「已打开评论区 / 已唤起发布页」，不据此做任何状态变更。
- **端能力会同步抛异常**：§3.1 说「参数不合法时在本地直接失败，不上行」，所以两条路径都包在一层 `callBridge` 里（同步异常 / 非 Promise 返回一律转成「这次没发出去」+ 提示），不让它冒进渲染循环或手势回调。
- **未实测**：`interactionOpenApi` 需要客户端 9.49+ 的真机容器，本机与无头自检只能验静态契约与「无端能力 → 选中文案」这条退化路径。
- **拿不到端能力就退化成「选中文案 + 引导长按复制」**（`createRange + getSelection`，同 `vibeknow/china-rail-atlas` 的 `copyPrompt`），按钮永不消失；桌面直接开 `index.html` 走的就是这条。
  注意**不能**用 `execCommand` / `clipboard.writeText` —— 它们在小工具容器的**禁用能力扫描清单**里，`verify-minitool.mjs` 会直接判不合规（自检也有断言禁止这两个标识符出现）。

| 氦闪壳 | 单调膨胀且加速；游戏内壳半径 = 解析式；进入壳内即判吞没 |
| 相机 | 跟拍距离有界、不越过太阳、不因壳半径增长；**地球占屏高 ≥5%（实测 13.0%、壳贴脸 8.8%）**；**偏移权重单侧（掠过 0.27 s 衰减过半、0.67 s 归零）**；**注视距离不因行星偏移而改变**；注视方向全程朝前（<37°）且无突变 |
| 构图不变式 | 掠过时地球离画面中心 < 26°（实测 17.8°）、行星近缘 < 30°（实测 27.6°，木星）→ **两者始终同框**；注视方向被行星拉走的夹角 ≤ `CAM_PAN_TILT_MAX`（实测 8.98° / 上限 9°） |
| 地球模型 | 48 台全在 −Z 半球；**环式阵列**（1 / 5 / 11 / 16 / 15，外两圈占 ≥60%、最外圈 `sin 极角 > 0.95`）；同圈相邻间距 > 焰柱最粗处 ×4；安装半径统一；喷流平行朝后；净推力合成 1.000；每台自带等离子柱（长度随推力伸缩 + 双频抖动 + 径向呼吸、底座锚在喷口）、焰柱是**「锥底接喷口、细尖朝后」的锥线**（与喷口共用 `engineQuat`，长 0.95 R / 最粗 0.06 R）且吃一张**喷口白热 → 尾端散尽**的渐变纹理（`makePlumeTex`，亮端在 uv.y=0，主焰 / 内芯 / 焰柱三处共用）、口面光点两档亮度（怠速 0.28 / 点火 0.55）且**按离轴距离分档尺寸**、球后两枚**总尾焰光晕**（+Z，亮度随输出功率）、主焰收小到 0.22R/1.1R、**外观一律与弹弓无关**（只读 `st.pwrOut` = 输出功率） |
| 胜负 | 满弹弓逃出（34.7 s，5/5 完美，掠过即熄火的逐站余量 = 3.9 / 7.8 / 8.7 / 7.3 / 2.6 s）；绿色只按前 75% 也能逃出但更慢（38.3 s，冥王星处余量 2.8 s）；前 55% / 35% / 不点火 / 一直按着 / 窗口内死按均逃不出；**10fps 与 60fps 状态完全一致**；无「时间耗尽」失败 |

## 15. 风险与取舍

| 风险 | 取舍 |
|---|---|
| 「固定航线」牺牲了自由飞行的空间感 | 换来的是可读的时机节奏与可量化的成绩（「谁更快」），移动端单手也更成立 |
| 火星 / 水星 / 金星不入航线 | 火星站台只在航线 `s = 67`（木星是 457），窗口来不及亮；宁缺勿滥。ⓘ 2026-09-27：它们**改回真实影像贴图**（+约 1 MB 包体，换来「那是水星 / 金星 / 火星」一眼可辨），但仍不参与判定 |
| 但水星 / 金星 / 火星仍摆进场景 | 只作背景（无判定点、无窗口、不检测碰撞）。太阳系因此是完整的，火星还顺便把「为什么不吃它」变成看得见的事实；代价是真实比例下它们只有几像素，识别靠柔光与导航图 |
| 窗口与最佳区间按质量/引力逐行星不同 | 大质量行星引力影响范围大 → 窗口更长、绿色区间更宽（木星 2.80 s/44%，冥王星 2.50 s/28%）。难度曲线因此自带「越靠近太阳系外缘越苛刻」，且是按真实数据而不是按手感拍；代价是评级阈值也得跟着逐行星折算 |
| 半径全部改成真实比例（统一 800×，以地球观感为锚点） | 行星之间的大小关系与真实一致（木 37.4 / 土 31.1 / 天 13.6 / 海 13.2 / 冥 0.64 / 地球 3.41）——地球回到手调时代的 13% 占屏，主角立住了。代价：掠过行星同比放大 2.67×（木星判定点压满整屏），净空必须同比放大才保住掠过分镜，注视偏移必须加上限才不把地球顶出画面；太阳仍是唯一例外（§7.2） |
| 航线近乎径向，观感不如盘旋 | 盘旋角大 → 行星从侧面出现、竖屏框不住。**可读性优先** |
| 门槛整体偏高、需要吃到弹弓 | 刻意如此：不吃弹弓就是过不去，机制才有存在感 |
| BGM 增加 1298 KB base64 | 容器不接受音频文件且 `file://` 跨域受限，只能内联；无 `WE_BGM_B64` 时静默降级，玩法不受影响 |
| 分享依赖容器 bridge | 能力检测而非 UA；拿不到就退化为复制文案，按钮不消失 |
| `postNote` 成功 ≠ 过审 | 提示只写「已唤起发布页」，不做任何强一致状态变更 |
| `file://` CORS | 贴图与 BGM 全部 base64 内联，`three.min.js` 外置同目录，双击即开零 CORS |
