# 拼豆城市 · 设定文档

> 状态：**核心循环 + RCI 三需求 + 市政三系统已跑通，平衡推演已完成**（2026-09-01，66 项断言全绿）。数值经 `_dev/simulate.js` 长时间推演校准，并已修复 5 处正反馈死锁。

## 一、项目定位

- **一句话**：每一栋楼，都是你亲手拼出来的一块拼豆。
- **品类缝合**：拼豆填色（手工/解压）× 模拟城市（RCI 供需 / 市政管网 / 成长）。
- **赛道**：#vibegame 互动游戏赛道。核心卖点是「拼豆 → 落成」的因果感，叠加「水电够不够、人往哪搬」的经营判断。
- **形态**：纯前端单文件、零依赖，移动端优先，可直接上传小红书小工具。

## 二、核心循环

```
点空地 → 图纸册挑一栋 → 钉板上照淡底稿点豆 → 拼满 100%
      → 自动熨烫（豆子融成一片） → 建筑落进城（升起 + 光环）
      → 人口迁入 / 岗位增加 / 水电垃圾负荷变化
      → 看需求条决定下一栋盖什么 → 解锁更大的图纸 → 花金币直接盖第二栋
```

**关键设计：首次必须拼，之后可以买。**
这是拼豆玩法与经营玩法的接缝——拼豆负责「获得感与门槛」，金币负责「规模扩张」。
如果每次建造都要拼，会很快变成劳动；如果完全不用拼，就退化成普通放置游戏。

## 三、城市机制

| 机制 | 规则 |
|------|------|
| 地图 | 6×6 = 36 格固定网格，全部初始可用 |
| 人口 | 动态浮点值，向 `min(住房容量, 岗位 + 8)` 平滑收敛；**缺水或幸福 < 30 时反向流失**（地板 = 历史峰值的 40%） |
| 收益 | `(市政保底 + 人口税 + 产业收益) × 供需满足率 × 幸福系数`，单位「金币/分」 |
| 幸福 | `50 + 建筑修正 − (1−供电率)×30 − (1−供水率)×25 − min(25, 垃圾积压×0.5)`，钳制 0–100 |
| 幸福系数 | `0.6 + 幸福/100 × 0.8`，即 0.6×～1.4× |
| 金币 | 实时累积；离线按时间补算，**最多结算 4 小时** |
| 拆除 | 返还 50% 造价 |
| 存档 | `localStorage` 键 `pcity_v2` |

**幸福是这台机器的总闸门**。
摩天楼收益最高但扣幸福，还要吃掉 6 度电 5 吨水；街心树不赚钱但 +5 幸福且零负荷。
只堆高收益建筑，幸福被拖垮 → 系数掉到 0.6×，实际进账反而更少。

### 收入三段式

| 段 | 常量 | 规则 |
|----|------|------|
| 市政保底 | `BASE_INCOME = 3` | 任何局面都有进账。**没有这一项，纯住宅/纯市政城的 `income` 恒为 0 → `rate` 恒为 0 → 金币永不增长，玩家被永久锁死** |
| 人口税基 | `TAX_PER_HEAD = 1.5` | `min(实际人口, 住房容量) × 1.5`。住宅本身不产金币，**住进来的人才交税**；空置的房子一分不收 |
| 产业收益 | 图纸 `income` | 工业/环卫直接计入；商业还要再乘人气系数 |

开局金币 240。三段加起来让「第一栋小屋住满」就能自我造血（4 人 × 1.5 = 6 金币/分），不必依赖商业建筑回本。

## 四、市政三系统

开局自带**基础管线**：电力 6、供水 6、环卫 14（够撑起前六栋楼，让新手先学会「盖房子」再学「铺管网」）。

| 系统 | 供给来源 | 消耗方 | 缺口后果 |
|------|----------|--------|----------|
| 电力 ⚡ | 风力豆机 +8、燃煤电厂 +26 | 几乎所有建筑 | 供电率 < 1 → 幸福最多 −30，**收益按供电率线性打折**（最差 ~0.6×）。**不冻结人口** —— 否则会形成「缺电 → 人口停滞 → 电厂永远解锁不了」的正反馈死循环 |
| 供水 💧 | 街角水塔 +7、自来水厂 +20（后者自身耗 2 度电） | 住宅与工商 | 供水率 < 1 → 幸福最多 −25，人口停止迁入并缓慢流失（地板 = 峰值的 40%） |
| 环卫 🗑 | 回收中心 +14（自身耗 1 度电，附 2 岗位） | 所有住人与营业的建筑 | 垃圾按 `(用量−运力)×0.15/秒` 积压，上限 200；每点积压扣 0.5 幸福，最多 −25；积压 30+ 也算环卫缺口，会顶到推荐位 |

**三者分工不同**：
- **电**卡的是「当下效率」（即时打折），不会赶人；早建电厂就能解决
- **水**卡的是「能不能住」（冻结人口）；水塔 pop 8 解锁，很早就该建
- **环卫**卡的是「历史欠账」（积压会持续累积，必须补建回收中心 pop 24 解锁才能消化）

**解锁看历史峰值人口**（`S.popPeak`），不回落。已经解锁的图纸不会因为城市萧条而重新上锁。人口流失有 40% 峰值的「地板」，税基不会归零。

**`recommendCat` 优先级**：缺水电垃圾 > RCI 需求。需求条权重（R×0.8 量级 0-80）比缺口权重（4×缺口的量级 0-40）更高，必须把缺口检查**前置**并直接短路返回，否则玩家会被「住宅需求旺盛」牵着一直盖房、直到水电爆掉。

**实际进账系数 = 供水中位 × (0.6 + 幸福/100 × 0.8)**。水电同时缺时只取最紧的那一项（min 而非 product），让「补一个就能涨」的设计直觉成立。

## 五、RCI 三需求

顶栏常驻三条需求条，从中间向左右生长：正值向右（绿色）= 缺、负值向左（红色）= 过剩。
这是玩家「下一栋该盖什么」的唯一信号灯。

```
住宅需求 R = 空城 30 ｜ 无空房 −60 ｜ (岗位 − 人口×0.8) × 8，钳制 ±100
商业需求 C = (人口/7 − 商业数) × 34，钳制 ±100
工业需求 I = (人口/11 − 工业数) × 34，钳制 ±100
```

**闭环逻辑**：工业商业提供岗位 → 岗位吸引人口 → 人口又要求更多商业与工业。
住宅过剩（没有岗位）R 会转负，逼你去盖工坊而不是继续盖楼。
商业还有一道**人气约束**：`人气 = 人口 / (商业数 × 8)`，钳制 0.4–1.3——
没居民光顾，铺子开再多也赚不到钱，防止无脑堆商业刷收益。
反过来人口足够多时上限 1.3 是奖励：先盖住宅养人口，再盖商业，收益比反着来更高。

### 五处正反馈死锁（推演暴露，已用断言固化）

这五个 bug 长得一模一样：**缺口 → 关键指标冻结 → 补救设施解锁不了 → 缺口永久化**。
`_dev/smoke_test.js` 的 E 局用 14 项断言把它们钉死，改数值时任一回归都会立刻报警。

| # | 死锁 | 后果 | 修法 |
|---|------|------|------|
| 1 | 收入只来自商业/工业/环卫 | 纯住宅或纯市政城 `income = 0` → `rate = 0` → 金币恒 90 永不增长 | 三段式收入 + `BASE_INCOME` 保底 |
| 2 | 解锁看**当前**人口 | 缺水 → 人口掉 → 水塔（pop 8）解锁不了 → 更缺水 → 人口归零 | `peakPop()` 历史峰值解锁 + 40% 峰值地板 |
| 3 | 缺电也冻结人口 | 缺电 → 人口停滞 → 电厂解锁不了 → 永远缺电 | `tickPop` 只看 `watRatio`；水电同时缺取 `min` 而非连乘 |
| 4 | 环卫解锁太晚（原 pop 40） | 7–8 栋就爆仓，而人口被岗位卡在 8，回收中心永远解锁不了 | 降到 pop 12，基础环卫 6 → 14 |
| 5 | `recommendCat` 让 RCI 压过缺口 | 住宅需求权重 56 > 缺口权重 8，玩家被牵着一直盖房直到水电爆掉 | 缺口检查前置并短路 `return` |

另外补了一条：**幸福 < 30 也赶人**。否则「全城工厂、幸福掉到个位数」这种功利玩法在经济上完全成立，公园学堂就成了摆设。

## 七、拼豆玩法细则

- **棋盘**：跟随图纸尺寸（11×11 / 13×13 / 15×15 三档）。
- **临摹**：非空格显示目标色的 22% 淡底，照着点即可，不考验记忆。
- **填豆**：点选色珠 → 点按或拖动连续填；橡皮可清除。
- **严格完成**：非空格全部填对 **且** 空格不能有多余豆，才触发熨烫。有多余豆会提示数量。
- **提示**：自动补上一处错误格。
- **色板**：只列出当前图纸用到的颜色，每颗右上角显示「已放/需放」，放满变绿。
- **熨烫**：孔洞收缩、边缘外扩、叠加柔光，约 1.5 秒；随后建筑落位。

## 八、图纸设计原则（核心要点）

第二轮重新设计后的硬约束——任何新增图纸都必须满足：

1. **剪影优先**：每张图顶部必须留白，不能塞满棋盘。这样放进 6×6 城市网格时，能形成起伏的天际线，而不是一片同高的方块。
2. **一物一符号**：每张图必须有一个独一无二的视觉锤，让人 0.5 秒内认出类别——
   - 住宅：人字坡屋顶 / 阳台外挑 / 收分塔身
   - 商业：红白斜条纹遮阳篷 / 多色大棚
   - 工业：单坡顶（不对称）/ 双烟囱锯齿厂房
   - 电力：Y 形三叶 / 双曲线收腰冷却塔
   - 水利：罐体 + 外撇支腿 / 圆形沉淀池
   - 环卫：空心三角回收标志
   - 民生：树冠 / 红白塔身 + 光束 / 钟楼
3. **底部地面线**：最后一行必须非空（且宽度 ≥60%），保证放进城市网格时所有建筑底部对齐，不会"浮高"。
4. **左右对称**（`workshop` 是有意不对称的唯一例外）。
5. **填充量区间 45–125**：拼豆时间与建筑重要程度正比。`house` 拼得快（63 颗），`tower` 拼得久（125 颗）。

## 九、美术规范

- **珠子**：哑光塑料短管，正视＝「圆环 + 中心孔」，孔径约占外径 30%，孔壁下侧受光；高光极小且只落在环面上，避免糖果感。
- **城市里的建筑＝已熨烫的成品**（`iron = 0.62`），拼豆台上＝生豆（`iron = 0`）。同一套 `drawBead()`，一处改动两边生效。
- **配色**：黄昏天空（深蓝紫 → 暖橙），地块深绿灰，建筑用拼豆原色，UI 描金。
- **类别角标**：每栋建筑右下角画一个类别色小圆点（住宅绿 / 商业蓝 / 工业橙 / 电力黄 / 水利青 / 环卫紫 / 民生粉）。
- **动效**：建筑落成＝上升 + 缩放 + 光环扩散 + 投影收拢；背景有缓慢下落的金色微尘。
- **UI 图标**：不用 emoji，纯文字按钮 + Canvas/SVG 绘制。

### UI 质感（第四轮补充）

- **玻璃分层**：面板统一「渐变底 + `inset` 顶部内高光 + 外投影」三层，不用纯色块。顶栏 / 浮层 / 弹窗再叠 `backdrop-filter: blur()`（仅增强，去掉也不影响可读性）。
- **金色强调**：主按钮与选中态走 `var(--gold)` 三段渐变；标题字用 `background-clip: text` 做金渐变；顶栏底缘一条金色余晖线。
- **动效克制**：只保留三类——数值变化脉冲（`setChip` 给卡片加 `.bump`，430ms）、浮层入场 `translateY(12px)`、提示呼吸。不用弹跳、不用连续循环动画。
- **数值写入一律走 `setChip(id, txt)`**：只在文本真变时写 DOM（避免每帧无脑写），并顺带触发脉冲反馈。
- **面板组件「结构只建一次、数值只更新」**：任何 `innerHTML = '...'` 整段重建的做法都会让 CSS 过渡失效、烧 CPU、阻断后续交互。约定用 `buildXxx()` 一次性建结构并缓存节点引用，后续 `updateXxx()` 只改文本/宽度/class。
- **图标一律零依赖**：禁 emoji、禁图标字体、禁外链 SVG。**但不要为了「有图标」而造装饰性图标**——
  市政面板曾用 clip-path 画了 8 个几何图标（小人/螺母/五角星/菱形/闪电/水滴/三角/横杠）配在每格卡片上，
  第七轮以「AI 味」为由全部删除。类别区分改用**类别色文字 / 色点**即可，不占版面也不产生装饰感。

### 市政面板信息架构（第七轮 · 去组件化）

四组信息，自上而下，全部走**行式排版**，组间只用 1px 细线分隔：

1. **城市概况**：当前称号（金色渐变大字）+ 右端收益 · 人口/容量/建筑副标 · 人口容量细条 · **一句话诊断**（`diagnose()` 优先级：缺电→缺水→积压→住房满→缺岗位→RCI 旺盛→空城引导）
2. **数据 4 行**：现有人口 / 就业岗位 / 幸福度 / 收益。每行 = 标签（左，暗色小字）+ 数值（右，金色大字 `min-width:62px` 右对齐）+ 状态（最右，固定 66px 右对齐）。三列各自成列
3. **市政 4 行**：电（#F0C24B）/ 水（#5BC8E8）/ 环卫（#B98FD0）/ 积压（#8E7FA8）。每行 = 名称 + `用量 / 供给　余|缺 N 单位` + 一条 4px 细线（类别色只染这一条线）
4. **发展需求 3 条**：住宅/商业/工业（类别色文字，非色块）+ 强度描述（7 档）+ 双向条（6px，比顶栏细但要保住方向感）

副标题口径：人口走 `Math.floor`，避免「现有人口 7 / 2.38 人待业」这种浮点漂移。

#### ⚠️ 反「AI 味」排版约定（第五轮踩过，第七轮推翻）

第五轮做的那一版被判定「AI 味太浓」，问题不在质感不够，而在**组件化堆砌**。
下列手法是「仪表盘生成器」的视觉指纹，本项目一律不用：

| 禁用 | 原因 | 替代 |
|------|------|------|
| 相同结构的卡片复制 ×N（2×2 / 网格） | 一眼看出是模板套出来的 | 行式列表，靠右端对齐成列 |
| 每格配一个装饰性几何图标 | 图标不承载信息，纯占位 | 不给图标，用文字标签 |
| 圆角胶囊徽章（「缺 3」「余 6」） | 徽章是组件库味最重的一环 | 余缺直接写进数值行，用颜色区分 |
| 类别色左边条 `border-left:3px` | callout 的指纹 | 类别色每处只出现一次（染细条或染文字），不铺面 |
| 彩色左边框的诊断块 | 同上 | 整行微染背景 + 一枚小圆点 |
| 小标题右侧的渐隐装饰线 | 无信息量的纯装饰 | 靠字重 / 字距 / 留白拉开层次 |
| 每项下面另起一行「贴心解释」 | 把面板撑成说明书 | 合并进同一行的右端状态列 |

**要保留的是质感，不是组件**：字号与字重的层次对比、`font-variant-numeric: tabular-nums` 的数字对齐、
1px 细线的分隔节奏、金色强调色。这些来自排版，不来自复制粘贴的方块。

**验证方式**：`python _dev/shot_util.py --dump` 会把面板结构 dump 成缩进文本 + 盒模型，
能直接看出层次顺序、每行宽高、数值列是否成列、有没有横向溢出。
截图只能人眼看，改排版时以这份清单为准。

## 十、宿主 App 适配

- 顶栏零返回按钮：避免与小红书自带关闭控件冲突误触。
- 安全区：`--safe-top/bottom` 用 `var(--safe-area-inset-*, env(...))` 组合，PC 模拟器与真机都兼容。
- 不用 UA 判定宿主，不做内缩。
- **⚠️ 横向滚动条一律不可信**：宿主 WebView 会吞掉横向滑动手势（或与浮层纵向滚动冲突），超出屏宽的类别会**物理上点不到**。图纸册筛选条已改为 `flex-wrap: wrap` 换行，后续任何横向列表（标签 / 图例 / 步骤条）都应优先用换行、折叠或分页，不要退回到 `overflow-x: auto`。
- **窄屏断点**：`@media (max-width:360px)` 收紧标签（26px 高、隐藏数量角标），9 个类别两行内放完；`@media (max-height:620px)` 压缩顶栏与需求条，给城市舞台留空间。

## 十一、平衡推演结论（2026-09-01）

用 `_dev/simulate.js` 跑两组玩家画像各 60 分钟游戏时间（每帧 100ms，共 36000 帧，拼豆耗时真实计入）：

| 指标 | A 拼豆大师（图纸全已掌握） | B 首次拼豆（每张图纸先拼一次） |
|------|--------------------------|------------------------------|
| 第 1 栋 | 0:00 | 1:30 |
| 第 12 栋 | 16:06 | 18:25 |
| **填满 36 格** | **33:31** | **37:10** |
| 填满瞬间结余 | **1 金币** | **4 金币** |
| 填满瞬间进账 | 516 /分 | 529 /分 |
| 60 分钟终局结余 | 13267 金币 | 11798 金币 |
| 终局人口 / 幸福 | 58/64 · 54 | 62/68 · 51 |
| 最长干等 | 194 秒 | 194 秒 |
| 新拼图纸 | — | 11 张 |

**两条结论：**

1. **前半段经济是健康的。** 填满那一刻结余只有 1–4 金币，说明玩家从头到尾都在花钱、一直在做取舍，没有「钱多到没意义」的阶段。最长干等 194 秒（约 3 分钟）也在可接受区间。

2. **终局是真空的。** 填满之后还剩 23–26 分钟，白攒 1.2 万金币 ≈ 20 栋云端大厦，而最贵的图纸只要 600。**金币在终局完全失去意义，游戏在第 33 分钟就结束了，剩下的只是看数字涨。**

### 对「道路系统 vs 建筑升级」的判断

推演给出的答案是**建筑升级优先，而且道路系统在 6×6 下大概率是负收益**：

- **建筑升级直接命中真问题**（金币无出口），并且复用已有的拼豆台——重拼同一张图纸升到 2 级，零新增 UI 学习成本，还强化了「拼豆 → 落成」这个核心卖点。
- **道路系统会加剧瓶颈。** 空间不是太多了而是太少了（33 分钟就填满）。36 格若拿出 1/3 铺路，可建面积直接砍到 24 栋，内容量不增反减，还要额外承担「连通判定 + 放置规则 + 路网视觉」一整套成本。
- 但道路想解决的那个问题是真的：**当前「放哪一格」这个决策是无效的**——推演里玩家基本按顺序填，位置对结果零影响（没有任何邻接规则）。
- **更划算的替代：邻接加成**。住宅挨着公园 +幸福、商业挨着住宅 +人气、工业挨着住宅 −幸福。不占格子、不增 UI，纯数值层就能让「放哪」变得重要，实现成本约为道路的 1/5。

## 十二、待确认 / 后续清单

按优先级排列，未定的先不动：

1. **建筑升级**：同一栋楼拼第二遍 → 升到 2 级（收益/容量提升）。**推演已证明这是当前最高优先级**——它同时解决终局金币溢出和拼豆玩法留存，且复用现有拼豆台。待定的是成长曲线：线性（2 级封顶）还是递增造价。
2. **邻接加成**：让「放哪一格」产生意义，替代道路系统。成本远低于道路，不占格子。
3. **道路系统**：暂缓。空间是瓶颈不是富余，铺路会减少可建面积。除非地图扩到 8×8 以上再考虑。
4. **地图视角**：当前是正交俯视网格。等距 2.5D 更「像城市」，但拼豆像素画与斜网格的对齐成本高，小屏下格子会很小。**倾向保持正交，靠建筑高度偏移 + 投影营造立体感。**
5. **图纸扩充**：当前 15 张已覆盖 7 类。可再加「节日限定」图纸；电力现在只有风力 14 / 燃煤 40 两档，跨度仍偏大，缺一张中型发电。
6. **成就与分享**：城市里程碑（人口破百、图纸全掌握）生成一张可保存的城市海报图，利于小红书传播。
7. **音效**：拼豆落格的清脆声、熨烫的滋滋声（需内联极短音频，注意体积）。
8. **图纸册 UI**：当前已上线「推荐 / 全部 / 7 类」筛选条 + 横向紧凑卡片。后续可加：按造价 / 解锁人口 / 拼豆数排序；锁定建筑可展开看完整数值。
