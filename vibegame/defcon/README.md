# 核战危机 DEFCON（defcon）

> **分类**：`#vibegame` 互动游戏　·　分类索引见根目录 [`TRACKS.md`](../../TRACKS.md)
> 小红书 VibeCoding 大赛参赛作品 · 完整设定见 [`DESIGN.md`](DESIGN.md)

一款 3D 球面核战策略游戏，**竖屏移动端单手游玩**。六个虚构阵营在一颗星球上互相威慑，你通过一次次危机抉择把世界推向——或拉离——核战争边缘。核弹有限、存续规模大的才算赢。

## 项目信息

- 中文名：核战危机 DEFCON
- 仓库名：`defcon`
- 主赛道：`#vibegame`（互动游戏）
- 灵感来源：Introversion《DEFCON》(2006)
- 复用来源：`vibeknow/earth-3d` 的 three.js 运行时与地球贴图

## 玩法

一局约 6–8 分钟。开局选一个阵营，随后进入两段循环：

**危机博弈** —— 每回合 20 秒弹出一张国际事件卡，六方同时选择。每个选项推高或压低全局危机值，危机值决定 DEFCON 等级，跌到 DEFCON 1 即解锁核弹。世界每回合自动滑向战争一点，你只能拖慢，不能阻止。不想等？事件卡底部有「直接拉满危机值」，一按就开战。

**热核战争** —— 单指拖动旋转地球、双指缩放，轻点敌方城市选中目标，再按「发 射」确认（核弹不可逆，不做一键发射；已选中再点一次同一目标也等于确认）。齐射可切 ×1 / ×3。导弹沿大圆弹道飞行 15–40 秒，途中可能被敌方防空拦截，命中即抹掉城市。敌方发射的导弹一旦进入你的雷达覆盖，你可以靠弹道反推找到它的发射井——但你自己开火时，也一样会暴露。

终局按「存续规模」排名。赢不是灭了对手，是谁的存续规模大。

顶栏「≡」打开抽屉：各方存续规模、单位图例（六边形 = 发射井，三角 = 防空，椭圆 = 雷达）与全部城市列表。敌方单位默认不可见，只有被雷达捕获并弹道溯源标记后才会显形。

## 三条设计主线

1. **DEFCON 等级由博弈驱动，不由倒计时驱动** —— 何时开战是六方共同选择的结果
2. **核弹有限且不可逆** —— 打一枚少一枚，先手倾泻会暴露发射井，第二轮就没得打了
3. **存续规模计分** —— 相互确保毁灭的数学化，逼出二次核反击的考量

## 技术路线

- `index.html` + `src/` 下 10 个外置经典脚本，**无构建步骤**，作为小红书「小工具」上传挂载
- 竖屏移动端布局（390×844 基准，桌面端居中成 480px 竖屏）
- 渲染：three.js r149（本地，无 CDN）+ 一张 2048×1024 等距圆柱地球贴图 + 手写 bloom 后处理（亮度提取 → 两趟高斯 → 叠加，含自动降级）
- 逻辑 10 Hz 固定步长 + 渲染 60 fps 插值，确定性便于无头测试
- 红线：离线运行不联网、无 `fetch` / `Worker` / `eval`、脚本全外置、无外部资源
- 音频：全部 WebAudio 现场合成，不引任何音频文件。10 个音效分三档——事件档（DEFCON 跃迁 / 发射 / 拦截 / 核爆 / 指令被拒 / 己方城市被毁 / 终局）、操作档（选中目标 = 雷达 ping）、界面档（tap 通用点击 / pick 决策确认）；总线挂压缩器，密集触发时叠加升调而非丢弃
- 界面音刻意做轻：`tap` 只有 35 ms、峰值 0.16，一局要按几十次，稍厚就会变成噪音；`pick` 略重用于不可逆决策。两档音高与事件音错开，闭眼也能分辨点的是什么
- **核爆是全场最响的音效**：核爆的「沉」来自极低频（它紧跟一次全屏白闪，听觉上不该抢过视觉），
  所以修的一直是**它周围太吵**、不是它自己太小 —— 把同期竞争的音压回它之下，
  并在它爆发的那一秒让 BGM 让路（`duck`，−7 dB 快下、约 1.5 s 归位）。
  九改重构后层级仍保持：核爆 0.30 > 发射 0.23 > 拦截 0.20（单音实测峰值）
- **九改（2026-09-11）三个音效完全重构**：用户反馈「SAM 拦截 / 核爆 / 导弹发射 现在的完全不行」。
  此前八次改动都在「调频段 / 换滤波器 / 抬压电平」这一个维度里打转，而问题在**声音的物理结构**——
  真实的爆炸与发射不是「一声」，而是「起爆瞬态 → 持续身体 → 长尾回响」的时间过程。
  三个音效按这个三段结构重搭（总长翻倍）：`launch` 0.9 → **1.6 s**（点火 / 推力 1.6 s / 低频重量 / 尾焰远去）；
  `intercept` 0.14 → 0.3 s（近炸爆响 / 炸开身体 / 金属碎片）；
  `nuke` 1.1 → **2.55 s**（起爆 / 主轰鸣 1.75 s / 撕裂层 / 长尾回响 2.4 s）。
  **核爆的关键是主轰鸣改用慢衰减（1.7 s）** —— 历次被判「像在打鼓」的根因是包络收得太快，
  而此前各版从未动过包络长度。实测核爆手机冲击 0.021 → **0.034**，齐射峰值 0.657、**0 削波**。
  八改给 siren 加的升八度层本次保留不动。详见 `DESIGN.md`「音频补记 · **九改**」
- **BGM**：三段配乐，同样现场合成；三个玩法阶段各有一段，**全程没有静默段**。
  **危机段**（简报 / 危机）D 小调 i–VI–iv–V 走 16 小节，和声真的在动、低音跟着和弦走；
  紧张度靠「加乐器 + 提速」而不是调音量：5 = 和弦 + 低音 + 八分音型 → 4 = 音型加强 →
  3 = 加底鼓 / 反拍军鼓 / hi-hat 与旋律动机 → 2 = 加悬置长音与十六分幽灵音（60→92 bpm 平滑提速）。
  **战争段**（热核战争）防空警报旋回 A4↔D5，每 16 拍拉响一次、鸣 12 拍留 4 拍，
  底下垫八分音型与行军式的低音脉冲；警报那两个音在战争段的和声（Dm / Gm / A7）上
  分别落在五度与根音，所以警报永远在调上。
  **八改**给警报叠了一层升八度 triangle（880↔1174 Hz）—— 原旋回压在手机低截止边缘，
  外放上被滚降吃掉；补层后手机(>500 Hz) RMS 0.0204 → **0.0241（+1.4 dB）**，500-2k 占比 16% → **23%**。
  **终局段**夺冠走 D 大调 I–IV–vi–V 皮卡迪三度收束（天亮），
  其余名次停在**去掉三度的空五度**上（余烬，不落地）；两版都不给落败方任何推进感。
  实测：危机段峰值 0.18~0.22 / 战争段 0.34 / 终局 0.10~0.19，叠加核爆 0.34 不削波；
  **>500 Hz（手机外放的有效段）占全频 RMS 的 40~59%，主导频点 234 Hz** ——
  外放听到的是配乐本身，不是噪声。
  声部越多总线反而压得越低（密度补偿，否则 DEFCON 2 会盖住界面音）；总线绕开压缩器，避免持续低音把核爆压下去；
  总线末端另有 `duck` 让路节点：核爆爆发时将背景压低 −7 dB 再放回，让那一秒的轰鸣不被警报糊掉
- 音频共经历过九次大改，最后一版推翻重做的原因写在 `DESIGN.md`「音频补记 · **三改**」：
  **二改的紧张感是靠非乐音素材（摩尔斯滴答、每拍 4.2 kHz 击打、小二度摩擦）硬凑的**，
  而手机外放会把 500 Hz 以下的音乐全部滤掉 ——
  玩家听到的不是「配乐跑调」，是「一台坏掉的设备在滴滴响」

## 目录约定

```
index.html          # 入口（内联样式 + HUD 骨架，脚本外置）
assets/
  three.min.js      # r149，608 KB
  earth.jpg         # 2048×1024，512 KB
src/
  compat.js         # 能力检测（Flex gap 等），给 <html> 挂 Chrome 61 降级 class（最先加载）
  data.js           # 阵营、城市、事件卡、配置（纯 JS，不 fetch）
  geo.js            # 经纬度数学、大圆航线、弹道、溯源
  landmask.js       # 海陆掩膜（自动生成，tools/gen-landmask.py 产出）
  sim.js            # 阶段机、实体状态、tick、伤害结算
  ai.js             # AI 决策
  render.js         # three.js 渲染（球体、单位、导弹、城市光点与定位环、特效）
  audio.js          # WebAudio 程序化音频（10 个音效 + 三段落 BGM，不引任何音频文件，默认开启）
  ui.js             # HUD、事件卡、城市列表、终局复盘
  game.js           # 主循环、事件绑定
tests/              # 无头校验脚本，不进提交包
tools/              # 构建与实测脚本（landmask 生成、dist 同步、音频探针），不进提交包
dist/               # 提交包的内容根（由 tools/build_dist.py 从源同步，勿手改）
defcon.zip          # 提交产物（打包 dist 的内容，根目录必须是 index.html）
docs/               # 素材与截图
DESIGN.md           # 设计文档
# 小工具打包规范见工作区根 .skill/minitool-zip-builder/（本目录不内嵌副本）
```

脚本加载顺序即依赖顺序：`compat → data → geo → sim → ai → render → audio → ui → game`，靠 `window.DC` 命名空间协作。

### Chrome 61 兼容基线

小红书容器的最低兼容基线是 **Android 8.1 出场 Chrome / WebView 61**（规范见工作区根 `.skill/minitool-zip-builder/references/`）。本作按「基线层 + 能力检测增强层」交付，最终包内不保留任何超出基线的要求：

| 项 | 处理 |
|---|---|
| JS 语法 | 直接用 ES5 / ES2017 写法（`var` + 函数），不引入构建链；ES2018+ 语法（可选链 `?.`、空值合并 `??`、对象展开、可选 catch 绑定、异步迭代等）一律不用 |
| Flex `gap` / `row-gap` / `column-gap`（Chrome 84） | `src/compat.js` 建 Flex 容器**实测布局行为**后给 `<html>` 加 `.supports-flex-gap`；现代内核走 `gap`，旧内核落到 `html:not(.supports-flex-gap)` 下的子项 `margin` 基线 |
| `inset`（Chrome 87） | 全部改写为 `top/right/bottom/left` 四个物理属性 |
| `min()` / `max()` / `clamp()`（Chrome 79） | 改固定值 + 百分比 + `max-width`（终局面板 `width:92%;max-width:400px`） |
| `env()` 安全区（Chrome 69） | 基线 `--safe-t`/`--safe-b` 只引用容器注入的 `--safe-area-inset-*`（`var` 带静态兜底）；`env()` 放进 `@supports` 增强块，避免旧内核里 `calc()` 整体失效导致顶栏掉位 |
| `backdrop-filter`（Chrome 76） | 仅作增强，包在 `@supports` 里；基线是 `--panel` 的半透明实底 |
| 两位置渐变停点（CSS Images 4） | 扫描线改用单色停点四段写法，兼容旧解析器 |
| 被禁能力 | 无 `fetch` / `XHR` / `Worker` / `eval` / `new Function` / 内联脚本 / 行内事件；脚本全外置、事件用 `addEventListener` |

> 标记：以上为静态核对与集中修复，**Chrome 61 / Android 8.1 真机兼容性未实测**。

各脚本尾部的 IIFE 收尾写作 `})(typeof window !== 'undefined' ? window : globalThis)`。
`globalThis`（ES2020）受 `typeof` 与三元短路双重保护：浏览器里 `window` 恒存在，永远取 `window` 分支、
不会求值，Chrome 61 解析这个标识符也不报错；它只是为 Node（`tests/` 无头脚本）保留的回落分支，
故不构成实际的兼容性风险，未做改动。

## 打包

```bash
python tools/build_dist.py          # 同步 dist/ 并重打 defcon.zip
python tools/build_dist.py --check  # 只校验 dist/ 是否与源一致
node ../../.skill/minitool-zip-builder/scripts/audit_artifact.mjs dist
```

`dist/index.html` 与源 `index.html` 的唯一差异是**去掉 `data-page-node-id`**（设计稿 D2C 工具留下的产物标记，
提交包不需要）。这一步固定在 `build_dist.py` 里做，不要再手改 `dist/`。

产物须符合工作区根 `.skill/minitool-zip-builder/` 的小工具打包规范。核心要求：

- `index.html` 在 zip 根目录 —— 压缩 `dist/` 的**内容**而非目录本身
- 脚本全外置、经典脚本、无 `import` / `export` / `type="module"`，ES5 语法（基线 WebView 61）
- 全部相对路径，无外部引用
- zip 不超过 10 MiB（建议 2 MiB 内）；当前 14 项约 934 KB

打包前按 `.skill/minitool-zip-builder/references/zip-artifact-spec.md` §6 与 `performance-budget.md` §6 逐项自检。
音频改动另需跑 `python tools/bgm-probe.py`（三段 BGM 的换段、电平、频段分布与削波实测；
战争段另有**警报升八度层（800~1400 Hz）占比** —— 这一项才代表手机上「听不听得见警报」，
原来的 400~600 Hz 占比量的是手机放不出的那一层）
与 `python tools/sfx-probe.py`（10 个音效的单音电平、手机外放保留、战争段警报在场时的信掩比、
以及核爆让路的实际深度与恢复时间 —— 改到 `duck` 或战争段音效电平时，**让路那一项必须看**：
信掩比这个指标量不出让路的收益，反而会变负，理由见 DESIGN.md 七改）。
改到某个音效的**触发密度**（`MIN_GAP` / `MAX_STACK`）时加跑 `node tools/impact-density.js`：
它统计真实对局里核爆音的间隔分布，用来判断「叠加升调」这类规则的实际触发比例 ——
实测 87% 的核爆是单发，故叠加不是「像在打鼓」的主因，响度才是（见 DESIGN.md 六改）。

## 分类判定

有分数、有输赢、有六方对抗与终局排名，用户点开是为了「赢一局」 → `#vibegame`。
冷战题材与核战反思是包装，主价值是策略对抗的爽感，故不归 `#vibeknow`；玩法驱动而非观看体验，故不归 `#vibeart`。
